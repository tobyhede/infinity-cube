# 02 — Build the Start window

**Status:** ready-for-human — built and seen in a live webview on Linux (WebKitGTK 2.52.6); macOS and Windows not run, and CI not yet run on a pull request.

**Blocked by:** 04 (the folder rules and Title), 05 (its page served from the app's build). 01 is done.

**What to build:** The Start window as ST-131 states it, to the design 01 accepts: a window the shell opens itself (`tauri.conf.json` still declares none), drawn by a React entry built from `@project/ui`, holding the only invoke commands it calls (create, open, browse, the recent list) in a capability naming its label alone. It shows at launch when nothing else opens and for File › New Space…, and closes when a Space window opens from it. New Space writes `<location>/<name>` through the host's `init_directory` with the Title, and refuses and defaults its name, by 04's functions. Its page is `packages/app/start.html` (entry `src/start-main.tsx`), built by `packages/app/desktop-shell-build.config.ts` into `packages/app/dist-desktop-shell`, which is the shell's `frontendDist` with the close question's files copied beside it, and the shell opens it as `WebviewUrl::App("start.html")` under the label `start`, whose capability (`capabilities/start.json`) names that label alone (ADR 0172; 05's spike, `src/start.rs`, replaces its throwaway page and its ping command and drops the `INFINITY_CUBE_START_WINDOW_SPIKE` gate). The launch decision in `launch.rs` moves from asking for a folder to showing the Start window, and the last-window rule (macOS runs on, Linux and Windows end) is decided there too.

## Components (from the design audit of the review stories)

The review stories are the layout reference, not the component reference. Build with:

- `StatusBusy` for "Opening…", not the stories' hand-made spinner and status (UI-92: one labelled status, announced once). If the folder line must be announced, give `StatusBusy` a slot for it.
- shadcn's `item` for Recent entries (`ItemGroup`, `Item` rendered as a button, `ItemContent`, `ItemTitle`, `ItemDescription`, `ItemActions`), added to `@project/ui` through `shadcn-first-ui` step 3, instead of the stories' ghost `Button` with layout overrides. A gone or failed entry's reason goes in `ItemDescription`, with no arbitrary icon selectors.
- A folder glyph (lucide `FolderOpen`) added to `icons.tsx` for Open Folder….
- Headings on the chrome type scale, or a recorded heading token, not `text-lg`.
- Retry's accessible name contains its visible text ("Try again", WCAG 2.5.3), and the list's hint is wired with `aria-describedby` or dropped.
- The project `Button` has no icon gap or `data-icon`; decide whether to add one before spacing icons by hand.

Decisions:

- **`item` written by hand.** `shadcn add item` could not reach `ui.shadcn.com` through this machine's proxy (403), so `packages/ui/src/components/item.tsx` was written from memory of base-nova's `item`. Compared afterwards with base-nova 4.18.0 as fetched from GitHub (`apps/v4/registry/bases/base/ui/item.tsx` and the `cn-item*` classes of `apps/v4/registry/styles/style-nova.css`, at tag `shadcn@4.18.0`; the CLI still could not reach the registry): the structure, slots, `useRender`/`mergeProps` and exports match, and the class lists differ. The registry's `Item` is `w-full rounded-lg border text-sm` with `[a]:hover:bg-muted`, its `default` variant `border-transparent`, its sizes `gap-2.5 px-3 py-2.5` (`default` and `sm`) and `gap-2 px-2.5 py-2` (`xs`); ours is `rounded-md border-transparent` with no `w-full`, `[a]:hover:bg-accent/50`, and sizes `gap-4 p-4`, `gap-2.5 px-4 py-3`, `gap-2 px-2 py-2`. The registry's `ItemGroup` has `w-full` and per-size gaps and ours neither; its `ItemSeparator` is `my-2`, ours `my-0`; its `ItemMedia` icon variant only sizes the SVG, where ours adds `size-8 rounded-sm border bg-muted`, and its image variant sizes per item size; its `ItemContent` drops its gap at `xs` and has no `min-w-0`; its `ItemTitle` has `line-clamp-1` and `underline-offset-4` and no `max-w-full`; its `ItemDescription` is `text-left text-sm`, `text-xs` at `xs`, with no `text-balance`. The recorded extensions are the chrome type scale and a button item's cursor, left alignment and `hover:bg-secondary`; `xs` is the registry's own size, not an extension, as first recorded here. **Reconciled:** `item.tsx` now carries base-nova 4.18.0's classes, keeping those extensions plus `min-w-0` on `ItemContent` and `max-w-full` on `ItemTitle`, so a long folder path truncates in the Recent pane. Its only consumer is the Start window's Recent list (`packages/app/src/components/StartWindow.tsx`); `EntityActionsMenu` draws menu items, not `Item`. Before and after screenshots of the Recent review story are in the project's `screenshots/start-window/item-reconcile/`.
- **Button icon gap.** No change to `Button`: New Space and Open Folder… space their icon with `gap-2` by hand. Adding `data-icon` would restyle every button in the application, which is a change for its own ticket.
- **Headings.** `text-chrome-sm` from the chrome type scale; no new heading token.
- **`StatusBusy`** is labelled "Opening <name>…" with the folder beside it, not inside the status, so the status is announced once. It shows for the moment between Create and the window opening, too short to observe live.
- **Recent.** The shell hands `recents: []` until 03, so the page shows its empty state. The entries, Try again (accessible name "Try again to open <Title>", WCAG 2.5.3) and the hint wired with `aria-describedby` are built and proven in `StartPage.test.tsx`, and drawn by the review story `review/start-window-recent.stories.tsx` (production cannot reach Recent until 03, so it holds no stable story or parity claim). Remove is drawn only when the page is given a handler, which 03 adds.
- **A refusal is a value.** `start_create_space` resolves with the refusal (`{of, …}`) or `null` rather than rejecting, so the page never parses a rejection's reason.
- **Each failure where it can be fixed** (2026-11-24, the approved redesign at `screenshots/start-window/error-rules/`). A failed Create Space used to show `StatusFailure` above the form, printing the system's error with the path twice and pushing Create Space out of the 720×520 window. Now `start.rs` classifies the first `io::Error` in the failure's chain (`cause_of`) into a code (`no-permission`, `read-only`, `location-gone`, `disk-full`, `failed`), `not-opened` carries the written folder, and `app/src/start-refusal.ts` words each one: on Name, on Location (Browse… the default button), or a notice above the buttons, the system's words behind a closed Details. Two findings decided the wording. A missing Location is made by Export's `create_dir_all`, so `location-gone` comes from a Location that is a file (`NotADirectory` on listing) or from any system error while the Location is missing (a removed disk's mount point, which the system will not let the write make); and Export leaves the folders it made before a failed file, which then take the name, so "Nothing was kept" is said only when the folder holds nothing afterwards (`kept`), and otherwise the sentence says part of the Space was left in that folder. Open Folder… on `not-opened` reuses `start_open_recent`, so no command was added. Proven by `start/tests.rs` (`given_a_write_that_fails`, `given_a_failure_s_cause`, `given_the_page`), `StartPage.test.tsx`, `start-refusal.test.ts` and eight `Components/Start Window` stories with a Ladle claim each; not seen in a live window.
- **Wording and focus after a refusal** (2026-11-24, from the copy review and design critique in the project's `reviews/start-window-ux-copy-2026-11-24.md` and `reviews/start-window-design-critique-2026-11-24.md`). A name that is not one folder name is worded by the case the typed name meets (empty, only dots, or the separator it holds, quoted) rather than one sentence listing every rule; names and characters typed are quoted; every notice ends in what to do; "location" is lowercase in sentences. When the form comes back refused, focus goes to Browse… for a cause on Location and to Name, selected, otherwise, so typing cannot replace a name the person meant to keep. Proven by `start-refusal.test.ts`, `StartPage.test.tsx` and the Ladle spec's Browse… focus check.
- **The native window** is titled "InfinityCube", 720×520 at a 560×420 minimum; UI-111's Open question keeps the title, minimum size and touch sizes.
- **`sideEffects: ["*.css"]`** is declared in `ui`, `plugins`, every `plugin-*`, `resource-api` and `core`. `dist-desktop-shell` fell from 4.7 MB (about 60 assets) to 348,763 bytes (one 270 KB script and one 75 KB stylesheet), held by `desktop-shell-build.test.ts`. `pnpm build` passes, and `packages/app/dist` fell from 5,432,126 to 5,348,177 bytes with the same 60 asset names; its fixture Space drew live from the new build. The release binary's size was not measured. 05 and 06 can treat it as done.
