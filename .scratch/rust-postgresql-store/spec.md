# The Rust PostgreSQL store, at test parity in one pass

**Status:** draft for the user's decisions (Open questions below). No ticket starts before 00, a cold audit of this plan, and the user's answers.

**Why:** rust-host 15 shipped the Rust SQLite store with far less coverage than the TypeScript side, and it took six review passes and PR #528's thirteen tickets to plan the way back. Rust-host 16 (`.scratch/rust-host/issues/16-rust-postgresql-store.md`) is next and has the same shape: its acceptance criteria name the HTTP wire and store-condition cases, `migrate` and the restart proof, and nothing about the repository contract, PostgreSQL's concurrency or failure classification. This plan front-loads what the SQLite effort learned, so the PostgreSQL store reaches at least test parity with the TypeScript PostgreSQL store as it lands, not after.

**Lessons it builds in (from #528 and its three reviews):**

- A parity claim written from memory was wrong. Every claim here carries a `file:line` or a command; 00 checks them.
- No Rust test reached the SQLite aggregate write path (replacing it with `abort()` stayed green; 26 of 51 hand mutants survived). Here every ticket names the mutants it must kill, and its PR records the test that kills each one (13).
- Comparing two Rust stores cannot catch a defect they share (the revision ceiling in `crates/host/src/repository.rs:41-42` saturates for both). Every port asserts the TypeScript contract's absolute answers, never only agreement with another Rust store.
- Every TypeScript case needs a Rust port carrying `// Case: <name>`, or a written exemption, and a unit test fails otherwise (03).
- Divergences are decided before tickets are written (Decisions, Open questions).

**Where things stand** (paths at `fdb63a1`, #521's head, unless they say `main`):

- There is no Rust PostgreSQL store. `crates/host/src/sql/` has `codec.rs`, `path.rs` and `sqlite.rs` only; `sqlx` with the `postgres` feature is a `host` dev-dependency used by `crates/host/tests/shared_migrations.rs` alone (`crates/host/Cargo.toml` on `main`).
- The one Rust SQL repository (`crates/host/src/sql.rs`) runs every operation behind a process mutex (`sql.rs:162`, taken at `sql.rs:204`), one transaction per operation, and decides a commit against rows read in that transaction (`sql.rs:405-441`). That is correct for SQLite, where a write opens with `BEGIN IMMEDIATE` (`sql/sqlite.rs:166`) on one connection (`sql/sqlite.rs:93`). It is not the TypeScript PostgreSQL protocol (next point), and it is not enough across processes.
- The TypeScript PostgreSQL store (`src/prisma/sql-store.ts`) runs no process serialisation (`serialise` is the identity, `:269`). It protects the aggregate with a transaction-scoped advisory lock on the key `(1213812818, 1)`, exclusive for aggregate commits, complete reads and the lifecycle doors (`:242`, used from `src/persistence/sql-space-repository.ts:764`), shared for the single-Space fast path (`:255`, used at `sql-space-repository.ts:623`); `loadSpace` and `listSpaces` take no lock (`sql-space-repository.ts:308-326`). It re-reads a Space's revision under its row lock (`writeDocumentUnderLock`, `src/persistence/sql-store.ts:487-494`, called at `sql-space-repository.ts:679`), relocks the Meta row once more if a replacement moved it and answers unavailable after a second move (`sql-space-repository.ts:763-772`), relocks every row on replacement (`:1012-1017`), and runs the fast path and the aggregate decision in separate transactions so a shared holder never asks for the exclusive lock (`:564-605`). It reads failures by SQLSTATE and socket errno allowlists (`src/prisma/sql-store.ts:76-112`) and a lost primary-key race by `23505` and `<table>_pkey` (`:43-54`). It takes `DATABASE_URL` from the environment or the nearest `.env` (`src/prisma/db.ts:43-47`).
- The TypeScript PostgreSQL tests, listed by the command in Source: 73 contract `it` cases (`test/support/repository-contract.ts`, 76 runs, every one of which runs on PostgreSQL because the harness at `test/integration/postgres-space-repository.test.ts:31-99` supplies every optional member), 13 more in that file, 5 in `postgres-aggregate-initialization.test.ts`, 3 in `postgres-misconfiguration.test.ts`, 2 in `prisma-postgres.test.ts`, 9 in `test/unit/postgres-unreachable.test.ts`, 1 in `postgres-aggregate-lock-key.test.ts`, 4 in `prisma-postgres-env-path.test.ts`, the 6 fast-path races run on PostgreSQL with `runsCommitsConcurrently: true` (`test/integration/fast-path-races.test.ts:12-19`), the PostgreSQL half of `test/unit/sql-connection-failure.test.ts` (12 cases, `:54-204`), the two PostgreSQL start-up cases of `test/unit/database-startup.test.ts` (`:442-497`), and the restart proof `test/e2e/postgres-persistence.spec.ts`.
- The schema (`migrations-sql/postgres/`) makes several SQLite broken states unrepresentable: ids and `meta_space_id` are `uuid`, `repository_state.meta_space_id` references `spaces(id) ON DELETE RESTRICT`, documents are `jsonb` (which refuses text that is not JSON and the escape `\u0000`, and reorders object keys), and `resources.updated_at` and `spaces.updated_at` are `NOT NULL` with no default.
- CI: the `rust` job already starts PostgreSQL through Compose for `shared_migrations` (`.github/workflows/ci.yml:711-732` on `main`); the `crap-rust` job starts none, so a PostgreSQL store tested only against a server would score as uncovered there.

**Goal:** the same as #528's, for PostgreSQL. TypeScript is the frozen reference; parity means Rust is at least as good as TypeScript wherever TypeScript is right. Every TypeScript PostgreSQL case has a Rust port on PostgreSQL or a written exemption, CI fails otherwise, and each ticket's named mutants are killed before it merges.

## Decisions carried over from #528

These were decided for SQLite (#528's `spec.md`, Decisions and Settled questions) and apply unchanged, because the repository code they govern is shared (`crates/host/src/sql.rs`, `repository.rs`, `commit.rs`, `startup.rs`):

- **TypeScript is frozen.** No ticket changes TypeScript's behaviour or its contract; its test and tooling files may change where a ticket needs them.
- **Rust-native ports**, one Rust test per TypeScript case, each carrying `// Case: <name>`, held by a ports unit test (03).
- **The shared-code defects #528's 01 fixes are fixed once**, on the shared repository, and the PostgreSQL ports re-hold them: the revision ceiling refused as an invariant failure (deleting a Space at the ceiling still commits), and `list_spaces` listing every Space when one fails intake, however it is broken.
- **Accepted differences:** a commit's answer does not depend on the order of its changes (the contract case "writes a moved Resource through the ownership check, which refuses it before its Space releases it" is exempt, as on SQLite: TypeScript's shared SQL writer refuses the receiving-first move on PostgreSQL too); `serve` answers requests before its first start-up attempt ends; `load_space` over a broken Space answers an invariant failure; `list_spaces` lists a broken Space; replacing an Aggregate deletes orphan Resource rows; invalid Default Content stops start-up at once.
- **The glossary terms** Invariant failure, Unavailable and Unclassified failure (#528's 02) name every classification here.
- **No coverage floor.** The ports test is the parity table; `crap-rust` measures coverage (but see Q9).

Settled by rust-host 16's Agent Brief (grilled 2026-11-24) and not reopened: `serve --store postgres` refuses an unset or blank `DATABASE_URL` before it serves (TypeScript falls back to the driver's defaults, `src/prisma/db.ts:68-74`); `serve` does not migrate; `sqlx` becomes the only migrator through `infinity-cube migrate` (ADR 0173 on `main`, renumbered 0174 by #533); a database Prisma Next migrated is refused, never adopted.

## Does not apply on PostgreSQL

Exempt from the PostgreSQL adapter as "does not apply", each with this reason in the ports test, because the schema or the driver makes the state impossible:

- A document stored as a BLOB, or as text that is not JSON, or holding a lone surrogate: `jsonb` refuses each on write (`postgres-space-repository.test.ts:287` holds the refusal; its port is in 07).
- A Space id or Meta identity that is not a UUID: the columns are `uuid`.
- A Meta identity naming no Space: the foreign key restricts it (`postgres-space-repository.test.ts:765` holds the restriction; its port is in 07).
- Every SQLite file rule: `SQLITE_PATH`, code 14, a file replaced under the host, journal mode and `synchronous`, the busy timeout, reserved locks.
- The four `prisma-postgres-env-path.test.ts` cases, if Q7 is answered "environment only".

## Open questions

Each has a recommendation; the plan's tickets are written to the recommendation and change if the answer differs.

- **Q1. One Rust repository contract for both stores?** The TypeScript contract is one function run per store. #528's 04, 05, 06 and 12 write SQLite-only ports, which PostgreSQL would then copy. **Recommend:** write the Rust ports once, as a table every store runs (`crates/host/tests/repository_contract/`, invoked as `repository_cases!(harness)` the way `http_conformance::cases!` is), asserting the contract's absolute values; each store adds only its own cases. This changes #528's 03–06 and 12 before they start (they are blocked on #520 and #521 merging, so nothing is lost) and is 02 here. The table holds the contract's answers, not one store against another, so it does not repeat the shared-bug trap.
- **Q2. Concurrency: mirror the TypeScript PostgreSQL protocol?** **Recommend yes**, exactly: no process serialisation on PostgreSQL; the advisory key `(1213812818, 1)`, shared for the fast path and exclusive for aggregate commits, complete reads and lifecycle doors; the fast path and the aggregate decision in separate transactions; the revision re-read under the row lock; the Meta relock retried once, then unavailable; every stored row relocked by revision on replacement. Same key, so a TypeScript and a Rust host on one database exclude each other during the move to Rust (19). The alternative, one exclusive advisory lock around every write, is simpler but breaks ST-5 (edits to different Spaces would queue) and the fast-path race "lets Map-internal Edits to different Spaces commit side by side where the store runs commits concurrently". This is 04: the SQL repository gains lock modes and a per-store choice of process serialisation, and SQLite keeps its mutex.
- **Q3. Isolation level.** TypeScript inherits the server's default (READ COMMITTED on a stock server; nothing in `src/prisma/` sets it). **Recommend:** Rust sets READ COMMITTED on every transaction, so a server whose `default_transaction_isolation` is stricter cannot turn conflicts into `40001` answers of 503. An accepted difference, recorded in the ADR (01).
- **Q4. Lock waits.** TypeScript sets no `lock_timeout` or `statement_timeout`, so an advisory or row lock is waited on indefinitely. **Recommend:** the same in Rust, recorded; a bounded wait would answer `55P03` as 503, a behaviour TypeScript does not have.
- **Q5. Failure classification.** **Recommend:** the TypeScript SQLSTATE allowlist exactly (`08000 08001 08003 08004 08006 40001 40P01 53300 55P03 57P01 57P02 57P03` unavailable; `28P01`, `28000`, `3D000` and every other SQLSTATE unclassified), socket failures by `std::io::ErrorKind` (`ConnectionRefused`, `ConnectionReset`, `TimedOut`, `HostUnreachable`, `NetworkUnreachable` unavailable; anything else unclassified), `PoolTimedOut` and `PoolClosed` unavailable, and `23505` on `resources_pkey` answered as the ownership refusal (`invalid-commit`), on `spaces_pkey` or `repository_state_pkey` inside initialization re-read and classified as TypeScript does (`sql-space-repository.ts:943-980`). One accepted difference: TypeScript tells a temporary resolver failure (`EAI_AGAIN`, unavailable) from a name that does not resolve (`ENOTFOUND`, unclassified); `sqlx` and Tokio do not expose that distinction reliably, so Rust answers every resolver failure unclassified. 00 confirms that claim against the pinned `sqlx`.
- **Q6. A missing table or an unmigrated database.** TypeScript answers `42P01` unclassified (it is not in the allowlist). The SQLite decision (#528's 01) is invariant failure. Both answer 500 and both stop start-up after the confirming retry, so only the name and the log differ. **Recommend:** invariant failure, one rule for both Rust stores, recorded as a difference from TypeScript in the ADR.
- **Q7. Where `DATABASE_URL` comes from.** TypeScript also reads the nearest `.env`. The SQLite decision for `SQLITE_PATH` is environment only. **Recommend:** environment only, with the refusal naming `DATABASE_URL`; the four `.env` cases are exempt as does not apply. `pnpm dev` users export it or use the TypeScript host until 19.
- **Q8. Connection pool.** TypeScript uses the driver's pool with its defaults (`src/prisma/db.ts:68-74` sets none). **Recommend:** 10 connections, a 5 s acquire timeout (answered unavailable), connections opened lazily and reopened after an outage (the port of `postgres-unreachable.test.ts:133`). An operation holds one connection at a time: the fast path's transaction ends before the aggregate transaction begins, so a full pool cannot deadlock a commit against itself; 05 tests that with a pool of one.
- **Q9. Where the PostgreSQL tests run, and how they cannot pass by skipping.** **Recommend:** marked `#[ignore]`, run by the `rust` job with `--run-ignored only` against Compose's server, each on a fresh database cloned from one migrated template (needs a role that may create databases, as `shared_migrations` already does). A guard test fails when `CI` is set and the server variable is not, and the job checks nextest's summary ran more than zero PostgreSQL tests. The `crap-rust` job starts PostgreSQL too and runs them, or the store scores as uncovered there (a function of cyclomatic complexity 6 at 0% coverage scores 42, over the gate's 30).
- **Q10. TLS.** **Recommend:** build `sqlx` with `tls-rustls` so a `DATABASE_URL` with `sslmode=require` works; test that `sslmode=disable` serves and that `sslmode=require` against Compose's server (no TLS) fails as unclassified. The alternative is no TLS and a refusal naming it.
- **Q11. A string holding `\u0000`.** Intake accepts the escape (`crates/intake/src/json.rs:412` refuses only a raw control character) and `jsonb` refuses it. By reading, TypeScript then answers the commit as an unclassified failure (500), which the browser retries; nothing tests it in either runtime. **Recommend:** Rust answers the same, a Rust test pins it, and a separate issue records it as a defect in both runtimes. 00 probes TypeScript's real answer before 05 starts.
- **Q12. The mutation gate.** `cargo-mutants` is not installed in the review sandboxes (#528's review, `evidence/mutation.md`), and CI gating on mutation scores is refused for StrykerJS (`AGENTS.md`, Mutation testing). **Recommend:** each ticket lists named hand mutants; its PR description records, for each, the test that kills it or why it is equivalent; a ticket does not merge with a survivor. 13 then runs `cargo-mutants` (pinned) once over `sql.rs`, `sql/postgres.rs` and `commit.rs` against the PostgreSQL oracle as an audit, not a CI gate, and every survivor gets a test or a written equivalence.
- **Q13. How rust-host 16 is split.** **Recommend:** 16 keeps `migrate`, the Prisma Next retirement, the CI `db verify` step and the docs, unchanged; this plan replaces its store half (the PostgreSQL store, `serve --store postgres`, the conformance route and the restart proof on Rust). Rust tests migrate each database with `sqlx`'s migrator as setup, as `crates/host/tests/sqlite_support` does, so neither half waits on the other.

## Not in scope

Any change to the HTTP contract, the browser application or the TypeScript repository's behaviour or contract. `migrate` and the Prisma Next retirement (rust-host 16, Q13). `import` and `export` against a store (rust-host 17, 26). Moving `pnpm dev` to Rust (rust-host 19). PgBouncer or any connection pooler. A coverage floor.
