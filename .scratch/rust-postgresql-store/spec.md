# The Rust PostgreSQL store, at test parity in one pass

**Status:** decided. 00, the cold audit, ran on 2026-11-25 and this version is corrected from it (Audit, below). The user settled every question on 2026-11-26 (Decisions for PostgreSQL, below); 01 records them in an ADR and Storage before any code.

**Why:** rust-host 15 (PRs #520 and #521, open) builds the Rust SQLite store with far less coverage than the TypeScript side, and three reviews and PR #528's thirteen tickets were needed to plan the way back. Rust-host 16 (`.scratch/rust-host/issues/16-rust-postgresql-store.md`) is next and has the same shape: its acceptance criteria name the HTTP wire and store-condition cases, `migrate` and the restart proof, and nothing about the repository contract, PostgreSQL's concurrency or failure classification. This plan front-loads what the SQLite effort learned, so the PostgreSQL store reaches at least test parity with the TypeScript PostgreSQL store as it lands, not after.

**Lessons it builds in (from #528 and its reviews, in the project's `reviews/rust-sqlite-*`):**

- A parity claim written from memory was wrong (#528's `spec.md`, Source: its third review corrected the first). Every claim here carries a `file:line` or a command; 00 checked them.
- No `host` test reached the SQLite aggregate write path: replacing it with `abort()` left every `host` test green, and only one CLI process test fails (`crates/cli/tests/serve.rs`, `keeps_an_edit_across_a_restart`, #528's `spec.md`); 26 of 51 hand mutants survived. Here every ticket names the mutants its own tests kill, and its PR records the test that kills each (Q12).
- Comparing two Rust stores cannot catch a defect they share (the revision ceiling saturates for both, `crates/host/src/repository.rs:41-42`). Every port asserts the TypeScript contract's absolute answers, never only agreement with another Rust store.
- Every TypeScript case needs a Rust port carrying `// Case: <name>`, or a written exemption, and a unit test fails otherwise (03).
- Divergences are decided before tickets are written (Decisions carried over, Decisions for PostgreSQL).

**Where things stand.** Paths and lines are at `fdb63a1`. #521 has since been rebased to `1a9aa5d`, where 00 found the cited Rust files and `ci.yml` byte-identical. Lines marked `main` are at `343a66c`.

- There is no Rust PostgreSQL store. `crates/host/src/sql/` has `codec.rs`, `path.rs` and `sqlite.rs` only; `sqlx` with the `postgres` feature is a `host` dev-dependency used by `crates/host/tests/shared_migrations.rs` alone (`crates/host/Cargo.toml` on `main`).
- The one Rust SQL repository (`crates/host/src/sql.rs`) runs every operation behind a process mutex (`sql.rs:162`, taken at `sql.rs:204`), one transaction per operation, and decides a commit against rows read in that transaction (`sql.rs:405-441`). That is correct for SQLite, where a write opens with `BEGIN IMMEDIATE` (`sql/sqlite.rs:166`) on one connection (`sql/sqlite.rs:93`). It is not the TypeScript PostgreSQL protocol (next point), and it is not enough across processes.
- The TypeScript PostgreSQL store (`src/prisma/sql-store.ts`) runs no process serialisation (`serialise` is the identity, `:269`). It protects the aggregate with a transaction-scoped advisory lock on the key `(1213812818, 1)`: exclusive for aggregate commits, `loadAggregate` and both lifecycle doors (`:242`, taken by `#lockMetaIdentity`, `src/persistence/sql-space-repository.ts:763-772`), shared for the single-Space fast path (`:255`, taken at `sql-space-repository.ts:623`). `listSpaces`, `loadSpace` (`:304-326`), `loadMetaSpaceId` (`:937-941`), `markExported` (`:491-499`) and the asset operations (`:412-444`) take no advisory lock. It re-reads a Space's revision under its row lock (`writeDocumentUnderLock`, `src/persistence/sql-store.ts:487-495`, called at `sql-space-repository.ts:679`) and, on a stale revision, answers a conflict carrying the Space read afresh after the rollback (`:537-550`); it refuses an update whose upsert finds the Resource owned by another Space (`:709-726`); it relocks the Meta row once more if a replacement moved it and answers unavailable after a second move (`:763-772`); it relocks every row on replacement (`:1012-1017`); and it runs the fast path and the aggregate decision in separate transactions so a shared holder never asks for the exclusive lock (`:555-596`). It creates rows by plain `INSERT` and checks a delete removed a row (`:578-592`). It reads failures by SQLSTATE and socket errno allowlists over the whole cause chain (`src/prisma/sql-store.ts:76-112`, `:148-164`) and a lost primary-key race by `23505` and `<table>_pkey` (`:43-54`), answered per operation (initialization re-reads, `:964-979`; replacement propagates, `:1020-1026`). It takes `DATABASE_URL` from the environment or the nearest `.env` (`src/prisma/db.ts:43-47`).
- The TypeScript PostgreSQL tests (inventory: `case-map.md`, regenerated and confirmed by 00): 73 contract `it` cases (`test/support/repository-contract.ts`, 76 runs, all of which run on PostgreSQL because the harness at `test/integration/postgres-space-repository.test.ts:31-103` supplies every optional member); 13 more in that file; 5 in `postgres-aggregate-initialization.test.ts`; 3 in `postgres-misconfiguration.test.ts` (under a `describe.each`); 2 in `prisma-postgres.test.ts`; 9 in `test/unit/postgres-unreachable.test.ts`; 1 in `postgres-aggregate-lock-key.test.ts`; 4 in `prisma-postgres-env-path.test.ts`; the 6 fast-path races, run on PostgreSQL with `runsCommitsConcurrently: true` (`test/integration/fast-path-races.test.ts:12-19`); the 12 cases of the `postgresSqlStore.isUnavailable` describe (`test/unit/sql-connection-failure.test.ts:54-204`); the 2 PostgreSQL start-up cases (`test/unit/database-startup.test.ts:442-497`); and, found by 00, the PostgreSQL arm of `aggregate-commit-differential.test.ts` (1), `database-http-runtime.test.ts` (3), `test/unit/vite-hono-host.test.ts:974` (1), `test/unit/prisma-foundation.test.ts` (4), `test/e2e/postgres-persistence.spec.ts` (1), and two CLI files outside scope, `infinity-cube-cli.test.ts` (7) and `database-cli-targets.test.ts` (1).
- The schema (`migrations-sql/postgres/`) makes several SQLite broken states unrepresentable: ids and `meta_space_id` are `uuid`; `repository_state.meta_space_id` references `spaces(id) ON DELETE RESTRICT`; `resources.space_id` references `spaces(id) ON DELETE CASCADE` (`202609200949_rename_thing_to_resource.sql:14-18`); documents are `jsonb`, which refuses text that is not JSON and the escape `\u0000` (`22P05`, probed), sorts object keys by length then bytes, keeps a duplicate key's last value and reads `-0` back as `0` (probed); `spaces.updated_at` and `resources.updated_at` are `NOT NULL` with no default.
- CI: the `rust` job already starts PostgreSQL through Compose for `shared_migrations` (`.github/workflows/ci.yml:677-698` on `main`); the `crap-rust` job starts none, so a PostgreSQL store tested only against a server would score as uncovered there. Rust-host 16 deletes `shared_migrations` and its variable, so this plan sets up its own (05).

**Goal:** TypeScript is the frozen reference; parity means Rust is at least as good as TypeScript wherever TypeScript is right. Every TypeScript PostgreSQL case has a Rust port on PostgreSQL or a written exemption, CI fails otherwise, and each ticket's named mutants are killed before it merges.

## Decisions carried over from #528

Decided for SQLite (#528's `spec.md`, Decisions and Settled questions); they apply unchanged because the code they govern is shared (`crates/host/src/sql.rs`, `repository.rs`, `commit.rs`, `startup.rs`):

- **TypeScript is frozen.** No ticket changes TypeScript's behaviour or its contract; its test and tooling files may change where a ticket needs them.
- **Rust-native ports**, one Rust test per TypeScript case, each carrying `// Case: <name>`, held by a ports unit test (03).
- **The shared-code defects #528's 01 fixes are fixed once**, and the PostgreSQL ports re-hold them: the revision ceiling refused as an invariant failure (deleting a Space at the ceiling still commits), and `list_spaces` listing every Space when one fails intake.
- **Accepted differences:** a commit's answer does not depend on the order of its changes (the contract case "writes a moved Resource through the ownership check, which refuses it before its Space releases it" is exempt; TypeScript's shared SQL writer refuses the receiving-first move on PostgreSQL too); `serve` answers requests before its first start-up attempt ends; `load_space` over a broken Space answers an invariant failure; `list_spaces` lists a broken Space; replacing an Aggregate deletes orphan Resource rows; invalid Default Content stops start-up at once.
- **The glossary terms** Invariant failure and Unclassified failure, now in `CONTEXT.md`, and **Unreachable** for what #528 calls Unavailable (Q17): `CONTEXT.md` already defines Unavailable as a command state, so #528's 02 uses Unreachable too.
- **No coverage floor.**

Settled by rust-host 16's Agent Brief (2026-11-24) and not reopened: `serve --store postgres` refuses an unset or blank `DATABASE_URL` before it serves (TypeScript falls back to the driver's defaults, `src/prisma/db.ts:68-74`); `serve` does not migrate; `sqlx` becomes the only migrator through `infinity-cube migrate` (ADR 0173 on `main`, renumbered 0174 by #533); a database Prisma Next migrated is refused, never adopted.

## Does not apply on PostgreSQL

Exempt from the PostgreSQL adapter as "does not apply", each with this reason in the ports test:

- A document stored as a BLOB, as text that is not JSON, or holding a lone surrogate: `jsonb` refuses each on write. `postgres-space-repository.test.ts:287` holds the not-JSON refusal (ported in 07); the others follow from the column type.
- A Space id or Meta identity that is not a UUID: the columns are `uuid`.
- A Meta identity naming no Space: the foreign key restricts it (`postgres-space-repository.test.ts:765`, ported in 07).
- Every SQLite file rule: `SQLITE_PATH`, code 14, a file replaced under the host, journal mode and `synchronous`, the busy timeout, reserved locks.
- The CLI's `import` and `export --store postgres` cases (`infinity-cube-cli.test.ts`, `database-cli-targets.test.ts`): out of scope, rust-host 17 and 26.

## Decisions for PostgreSQL

Settled by the user on 2026-11-26, after a grilling that also checked each against the `sqlx` 0.9.1 source and Rust practice. The tickets are written to them. "Unreachable" below is the glossary's term (Q17); TypeScript and #528 say "unavailable" for it, and both answer 503.

- **Q1. One Rust repository contract for both stores.** The Rust ports are written once, as a table every store runs (`crates/host/tests/repository_contract/`, invoked as `repository_cases!(harness)` the way `http_conformance::cases!` is), asserting the contract's absolute values; each store adds only its own cases. This rewrites #528's 03 (its ports test reads the table), 04, 05, 06, 12 and 13 (whose same-Resource race is a table case) before they start, and sets them blocked on 02 until it lands.
- **Q2. Mirror the TypeScript PostgreSQL protocol exactly**, as Where things stand describes it: no process serialisation on PostgreSQL; the same key and modes; no advisory lock for `list_spaces`, `load_space`, `load_meta_space_id`, `mark_exported` or the assets; separate transactions for the fast path and the aggregate decision; the revision re-read under the row lock, a conflict carrying the Space read afresh after rollback; the Meta row relocked (Rust may use `SELECT … FOR UPDATE` where TypeScript writes the row; rollback makes the two indistinguishable); every row relocked on replacement. Same key, so a TypeScript and a Rust host on one database exclude each other during the move to Rust (19). Rust's write order (every delete, then every trim, then every write, `sql.rs:302-330`) differs from TypeScript's request order, but every aggregate commit holds the exclusive lock, so row-lock order cannot deadlock two hosts. `close()` waits for operations under way through the pool's own close. Alternatives rejected: a process mutex (excludes within one process only, so two hosts on one database commit over each other); SERIALIZABLE with retry on `40001` (a different protocol, so no TypeScript race case ports as written, and a retry bound is a new decision); row locks alone (nothing orders an aggregate commit, which touches several Spaces and Meta, against the fast path); one exclusive lock around every write (breaks ST-5 and the race "lets Map-internal Edits to different Spaces commit side by side"); a different key (each runtime safe alone, not together).
- **Q3. Isolation level.** TypeScript inherits the server's default (nothing in `src/prisma/` sets it); on a server defaulting to SERIALIZABLE its losing row-lock write gets `40001` (probed), which it answers 503. Rust starts every locking transaction with `BEGIN ISOLATION LEVEL READ COMMITTED` (it must be the first statement, probed; `Pool::begin_with` takes the statement, `sqlx-core-0.9.1/src/pool/mod.rs:391`), and runs each unlocked read that takes more than one statement (`load_space`'s Space and Resource reads, `sql.rs:233-245`) as one `REPEATABLE READ READ ONLY` transaction, so a commit landing between its statements cannot tear the snapshot into a Space that fails intake. Both are recorded as accepted differences, and 01 files TypeScript's tearable read as an issue.
- **Q4. Lock waits stay unbounded**, as in TypeScript (no `lock_timeout` or `statement_timeout`). Recorded as a risk, not a quiet difference: Rust practice bounds waits, a stuck holder hangs every writer, and neither driver enables TCP keepalive, so a half-open connection can hang either runtime. Bounding waits is a separate decision for both runtimes (it needs a value and an answer for `57014`, which no allowlist names), filed by 01.
- **Q5. Failure classification.** Unreachable: the TypeScript SQLSTATE allowlist exactly (`08000 08001 08003 08004 08006 40001 40P01 53300 55P03 57P01 57P02 57P03`), read from `sqlx::Error::Database(e).code()` wherever the error arises, `COMMIT` included; socket failures by `io::ErrorKind` (`ConnectionRefused`, `ConnectionReset`, `ConnectionAborted`, `NotConnected`, `BrokenPipe`, `UnexpectedEof`, `TimedOut`, `HostUnreachable`, `NetworkUnreachable`, all stable on the pinned 1.97; a connection the server dropped reads `UnexpectedEof`, probed); `PoolTimedOut` and `PoolClosed`. Unclassified: `28P01`, `28000`, `3D000` and every other SQLSTATE (Q6 aside), `Tls`, `Protocol`, `Configuration` and every other `sqlx::Error` variant. `23505` is answered per operation as TypeScript does: inside initialization re-read and classify; inside replacement propagate; an update learns of another owner from the upsert, not from `23505`. One accepted difference: a temporary resolver failure (`EAI_AGAIN`) and a name that does not resolve both arrive as `Io(Uncategorized)` with no OS error, differing only in libc's message (probed), so Rust answers both unclassified where TypeScript answers `EAI_AGAIN` unreachable.
- **Q6. A missing table or an unmigrated database** (`42P01`) is an invariant failure, one rule for both Rust stores (#528's 01), where TypeScript answers it unclassified. Both answer 500 and stop start-up after the confirming retry; the name, the log and the problem detail (`crates/host/src/http.rs:130-139`) differ, recorded as a difference.
- **Q7. `DATABASE_URL` keeps parity with TypeScript, the Rust way.** `main` reads it once, before the runtime starts, and hands the store a typed URL; the store reads no environment. The process environment wins; when unset, the nearest `.env` fills it, read with `dotenvy`'s iterator (which writes nothing to the process environment; `set_var` is `unsafe` in Rust 2024), taking `DATABASE_URL` alone, as `sqlx-cli` loads `.env` with `dotenvy`. Trimmed, and refused naming `DATABASE_URL` when unset or blank. TypeScript's search starts at its module's directory (`src/prisma/db.ts:28`), which a binary has not; Rust's starts at the current directory, as `sqlx-cli`'s does, recorded as an accepted difference. `prisma-postgres-env-path.test.ts`'s cases are ported or exempt as `case-map.md` says.
- **Q8. Connection pool:** 10 connections and a 2 s acquire timeout (`sqlx`'s defaults are 10 and 30 s, `sqlx-core-0.9.1/src/pool/options.rs:151,160`), connections opened lazily and reopened after an outage. `sqlx`'s pool retries a refused connection, `53300` and `57P03` internally and surfaces them only as `PoolTimedOut` after its acquire timeout (probed), so an outage answers 503 after up to 2 s where TypeScript answers at once: an accepted difference. An operation holds one connection at a time (the fast path's transaction ends before the aggregate one begins), tested with a pool of one.
- **Q9. Where the PostgreSQL tests run, and how they cannot pass by skipping:** `#[ignore]`d, run by the `rust` job with `--run-ignored only` against Compose's server, each on a fresh database cloned from one migrated template; the support **panics** when the server variable is unset, so an ignored test run without a server fails rather than passing; the job fails if nextest reports zero PostgreSQL tests run. The `crap-rust` job starts PostgreSQL too and runs them, or the store scores as uncovered (a function of cyclomatic complexity 6 at 0% coverage scores 42, over the gate's 30). A local `cargo nextest run` without a server skips them; CI is where they are enforced.
- **Q10. TLS roots:** `tls-rustls-ring-native-roots`, which reads the system's store (`sqlx-0.9.1/Cargo.toml:231`), so an operator can trust a private CA by installing it. Node, and so TypeScript, checks against its own bundled roots instead, so the trusted set differs: an accepted difference. `ring` and `rustls-native-certs` are already in `Cargo.lock`, and `ring` builds for the musl release targets without a C toolchain.
- **Q11. A string holding `\u0000`.** Intake accepts the escape (`crates/intake/src/json.rs:412` refuses only a raw control character); `jsonb` refuses it with `22P05`; TypeScript answers the commit unclassified, 500 `internal-error`, which the browser retries (all probed). Rust answers the same, a Rust test pins it by `22P05`, and 01 files the defect in both runtimes; the fix belongs to intake, outside parity.
- **Q12. The mutation gate:** each ticket lists the named hand mutants its own tests kill (a mutant whose killer lands in a later ticket is listed there instead, so no ticket waits on a later one); its PR records the test that kills each, or why it is equivalent (several Resource-delete mutants are equivalent under `ON DELETE CASCADE`); a ticket does not merge with a survivor. 13 then runs `cargo-mutants`, pinned, over the store and the seam against every PostgreSQL test file as an audit with no threshold, not a CI gate.
- **Q13. Rust-host 16 is split:** 16 keeps `migrate`, the Prisma Next retirement, the CI `db verify` step and its docs; this plan replaces its store half. Rust tests migrate each database with `sqlx`'s migrator as setup, so neither half waits on the other; 10 and 16 both edit CI's `postgres` job and are rebased in whichever order they land.
- **Q14. Numbers `jsonb` changes are accepted.** `jsonb` stores numbers by value: `-0` reads back as `0`; `1e400` is accepted and reads back as infinity in both runtimes (probed). The browser cannot send either (`JSON.stringify` writes `0` and `null`), TypeScript behaves the same, and keeping them would move the shared column off `jsonb`. A Rust test pins that a committed `-0` loads as `0`. Intake rewriting `-0` to `0` in both runtimes, so every store agrees, would be its own issue.
- **Q15. `sslmode` means what it means to TypeScript's driver.** `sqlx` defaults to `prefer`, which falls back to plaintext, and its `require` encrypts without checking the certificate (`sqlx-postgres-0.9.1/src/options/ssl_mode.rs:9-26`). TypeScript's `pg` 8.22 with `pg-connection-string` 2.14 connects without TLS when the URL names no `sslmode`, and treats `prefer`, `require` and `verify-ca` as `verify-full` (from `pg`'s documentation, not run here; 05's first step runs it). Rust translates the URL's `sslmode` to the `PgSslMode` with `pg`'s meaning before connecting, a test per value (`disable`, absent, `prefer`, `require`, `verify-ca`, `verify-full`, and `pg`'s `uselibpqcompat` if 05 finds the parameter honoured). Passing the URL unchanged would weaken TLS; refusing all but `verify-full` would break local development, which has no TLS.
- **Q16. An operation runs to completion when its request is dropped.** A JavaScript promise always runs on; in Rust, when a client disconnects, hyper drops the request's future (`crates/cli/src/listener.rs:193`) and with it any transaction under way. `sqlx` rolls a dropped transaction back (`sqlx-core-0.9.1/src/transaction.rs:56-58`), but an operation spanning two transactions (the fast path handing to the aggregate decision, the Meta relock retry) could stop between them. Each repository operation runs in a `tokio::spawn`ed task that owns its connection, so dropping the request drops only the wait for the answer. A test drops a request at each of 04's pause points and checks the store reaches the state the operation would have reached, and that the next operation is not blocked by a lock left behind.
- **Q17. Unreachable, not Unavailable.** `CONTEXT.md` defines Unavailable as a command drawn in place and refusing to run. The store failure that may clear on asking again is **Unreachable** (503), with Unavailable on its _Avoid_ list; a pool that times out during an outage is Unreachable too. #528's 02 adopts it.

## Rust gaps the audit found that are not PostgreSQL-specific

Both are in shared code, so they reach SQLite too, and 04 fixes them failing test first:

- Rust's `upsert_resource` (`sql/sqlite.rs:303-313`) neither moves nor reads back the row's owner, so an update meeting a Resource row another Space owns rewrites that Space's Resource. TypeScript refuses it as `invalid-commit` (`sql-space-repository.ts:709-726`).
- Rust's `install` writes Spaces by upsert (`sql/sqlite.rs:232-241`, called from `sql.rs:338-358`) and `delete_space` does not check a row was removed, where TypeScript inserts and checks (`sql-space-repository.ts:578-592`).

## Not in scope

Any change to the HTTP contract, the browser application or the TypeScript repository's behaviour or contract. `migrate` and the Prisma Next retirement (rust-host 16, Q13). `import` and `export` against a store (rust-host 17, 26). Moving `pnpm dev` to Rust (rust-host 19). PgBouncer or any connection pooler. A coverage floor.
