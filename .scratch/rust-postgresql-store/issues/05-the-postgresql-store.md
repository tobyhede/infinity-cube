# 05 — The PostgreSQL store of statements and its test support

**Status:** ready-for-agent once 03 and 04 land (Q3–Q10, Q14 and Q15 answered)

**Blocked by:** 03, 04 (03's PostgreSQL adapter must exist to count this ticket's `// Case:` ports).

**What to build:** `crates/host/src/sql/postgres.rs`: PostgreSQL's `SqlStore` beneath the one SQL repository (ST-3), over the schema `migrations-sql/postgres/` produces, and the test support every later ticket uses.

- [ ] Statements for every `SqlStore` method: ids and `meta_space_id` bound and read as `uuid`; documents written as `jsonb` from the codec's compact text and read back as text; `created_at` kept by an upsert, `updated_at` set to `now()` on every write of a Space or Resource row (`src/prisma/contract.prisma:13,33`; neither column has a default, `migrations-sql/postgres/202607290142_drop_updated_at_defaults.sql` for `spaces`, `202609200949_rename_thing_to_resource.sql:8` for `resources`); the aggregate lock as `pg_advisory_xact_lock(1213812818, 1)` and `pg_advisory_xact_lock_shared(1213812818, 1)` (`src/prisma/sql-store.ts:242,255`); row locks by `UPDATE … RETURNING` the prior revision (`src/persistence/sql-store.ts:488-495`) and the Meta and replacement relocks by `SELECT … FOR UPDATE` or TypeScript's placeholder write (`:436-439`), either leaving nothing behind after rollback.
- [ ] Transactions begin as Q3 decides; no lock or statement timeout (Q4).
- [ ] `classify` as Q5 decides, `42P01` as Q6 decides, with a unit test per SQLSTATE in and out of the allowlist, per `io::ErrorKind`, and for `PoolTimedOut`, `PoolClosed` and `Tls`.
- [ ] The pool as Q8 decides; connections reopened after an outage. TLS as Q10 decides.
- [ ] `sslmode` as Q15 decides: first run TypeScript's `pg` against Compose's server with each value and record what it does, since Q15's mapping comes from `pg`'s documentation; then translate the URL's `sslmode` to `PgSslMode` with that meaning, one unit test per value.
- [ ] `DATABASE_URL` as Q7 decides: a unit-tested function `main` calls once, before the runtime starts, answering a typed URL; the environment wins, else the nearest `.env` at or above the current directory supplies it through `dotenvy`'s iterator (nothing written to the process environment, nothing but `DATABASE_URL` taken); trimmed; refused naming `DATABASE_URL` when unset or blank. `dotenvy` joins `[workspace.dependencies]`.
- [ ] Ports with `// Case:` lines of `prisma-postgres-env-path.test.ts` › "prefers the nearest .env above the starting directory" and "answers undefined rather than a path no file sits at", against a temporary directory tree; the other two cases are the accepted difference Q7 records (`case-map.md`).
- [ ] Test support (`crates/host/tests/postgres_support/`): a database per test, cloned from one template migrated with `sqlx`'s migrator from `migrations-sql/postgres/` and dropped afterwards; the server named by one variable of this plan's own (rust-host 16 deletes `shared_migrations`' variable), whose role may create databases; the support **panics** when the variable is unset, so a PostgreSQL test run without a server fails. Tests are `#[ignore]`d; the `rust` job runs them with `--run-ignored only` and fails if nextest reports zero run; the `crap-rust` job starts Compose's PostgreSQL and runs them too.
- [ ] Ports with `// Case:` lines: `prisma-postgres.test.ts` › "writes and reads a typed space document with its resource", "advances updatedAt when a space is updated" (the update in a second transaction after the first commits, as TypeScript waits, since `now()` is the transaction's start); `prisma-foundation.test.ts` › "advances %s.updatedAt when a record is updated" for both values (Space and Resource).
- [ ] Tests for what no port holds: a Resource upsert keeps `created_at` (read back before and after); a database whose `default_transaction_isolation` is `serializable` still answers two overlapping fast-path Edits to one Space as a commit and a conflict, not a 503 (Q3); a pool of one completes a commit handed from the fast path to the aggregate decision (Q8); `sslmode=disable` and an absent `sslmode` serve, and `sslmode=require` against Compose's server, which has no TLS, is unclassified (Q10, Q15); a committed `-0` loads as `0` (Q14).
- [ ] `sqlx` gains the `postgres` feature and the TLS feature Q10 names in `[workspace.dependencies]`; clippy and nextest stay green under the workspace lints.

**Named mutants (each killed by this ticket's tests):** `updated_at` not set on a Space or a Resource update; `created_at` overwritten by an upsert; no isolation set at all; READ COMMITTED replaced by SERIALIZABLE or REPEATABLE READ for locking transactions; `40001`, `UnexpectedEof`, `ECONNREFUSED`, `53300` or `57P03` classified unclassified (killed by `classify`'s unit tests over constructed errors: through the pool those three connect-time failures arrive only as `PoolTimedOut`, Q8); `28P01` or `3D000` classified Unreachable; every error classified Unreachable; `42P01` not an invariant failure; `PoolTimedOut` not Unreachable; `DATABASE_URL` not trimmed; the `.env` value preferred over the environment's; `sslmode` passed to `sqlx` unchanged (killed by the `require` test: `sqlx`'s `require` would not verify); the support returning early instead of panicking without a server. (The advisory key and mode, and `23505` handling, are killed in 07.)
