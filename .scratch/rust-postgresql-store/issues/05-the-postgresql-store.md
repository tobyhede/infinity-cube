# 05 — The PostgreSQL store of statements and its test support

**Status:** resolved

**Blocked by:** 03, 04 (03's PostgreSQL adapter must exist to count this ticket's `// Case:` ports).

**What to build:** `crates/host/src/sql/postgres.rs`: PostgreSQL's `SqlStore` beneath the one SQL repository (ST-3), over the schema `migrations-sql/postgres/` produces, and the test support every later ticket uses.

- [x] Statements for every `SqlStore` method: ids and `meta_space_id` bound and read as `uuid`; documents written as `jsonb` from the codec's compact text and read back as text; `created_at` kept by an upsert, `updated_at` set to `now()` on every write of a Space or Resource row (`src/prisma/contract.prisma:13,33`; neither column has a default, `migrations-sql/postgres/202607290142_drop_updated_at_defaults.sql` for `spaces`, `202609200949_rename_thing_to_resource.sql:8` for `resources`); the aggregate lock as `pg_advisory_xact_lock(1213812818, 1)` and `pg_advisory_xact_lock_shared(1213812818, 1)` (`src/prisma/sql-store.ts:242,255`); row locks by `UPDATE … RETURNING` the prior revision (`src/persistence/sql-store.ts:488-495`) and the Meta and replacement relocks by `SELECT … FOR UPDATE` or TypeScript's placeholder write (`:436-439`), either leaving nothing behind after rollback.
- [x] Transactions begin as Q3 decides; no lock or statement timeout (Q4).
- [x] `classify` as Q5 decides, `42P01` as Q6 decides, with a unit test per SQLSTATE in and out of the allowlist, per `io::ErrorKind`, and for `PoolTimedOut`, `PoolClosed` and `Tls`.
- [x] The pool as Q8 decides; connections reopened after an outage. TLS as Q10 decides.
- [x] `sslmode` as Q15 decides: first run TypeScript's `pg` against Compose's server with each value and record what it does, since Q15's mapping comes from `pg`'s documentation; then translate the URL's `sslmode` to `PgSslMode` with that meaning, one unit test per value.
- [x] `DATABASE_URL` as Q7 decides: a unit-tested function `main` calls once, before the runtime starts, answering a typed URL; the environment wins, else the nearest `.env` at or above the current directory supplies it through `dotenvy`'s iterator (nothing written to the process environment, nothing but `DATABASE_URL` taken); trimmed; refused naming `DATABASE_URL` when unset or blank. `dotenvy` joins `[workspace.dependencies]`.
- [x] Ports with `// Case:` lines of `prisma-postgres-env-path.test.ts` › "prefers the nearest .env above the starting directory" and "answers undefined rather than a path no file sits at", against a temporary directory tree; the other two cases are the accepted difference Q7 records (`case-map.md`).
- [x] Test support (`crates/host/tests/postgres_support/`): a database per test, cloned from one template migrated with `sqlx`'s migrator from `migrations-sql/postgres/` and dropped afterwards; the server named by one variable of this plan's own (rust-host 16 deletes `shared_migrations`' variable), whose role may create databases; the support **panics** when the variable is unset, so a PostgreSQL test run without a server fails. Tests are `#[ignore]`d; the `rust` job runs them with `--run-ignored only` and fails if nextest reports zero run; the `crap-rust` job starts Compose's PostgreSQL and runs them too.
- [x] Ports with `// Case:` lines: `prisma-postgres.test.ts` › "writes and reads a typed space document with its resource", "advances updatedAt when a space is updated" (the update in a second transaction after the first commits, as TypeScript waits, since `now()` is the transaction's start); `prisma-foundation.test.ts` › "advances %s.updatedAt when a record is updated" for both values (Space and Resource).
- [x] Tests for what no port holds: a Resource upsert keeps `created_at` (read back before and after); a database whose `default_transaction_isolation` is `serializable` still answers two overlapping fast-path Edits to one Space as a commit and a conflict, not a 503 (Q3); a pool of one completes a commit handed from the fast path to the aggregate decision (Q8); `sslmode=disable` and an absent `sslmode` serve, and `sslmode=require` against Compose's server, which has no TLS, is unclassified (Q10, Q15); a committed `-0` loads as `0` (Q14); a torn-read test for `load_space` (Q3): one connection holds a commit that changes a Space and its Resources together, and `load_space` is started with a hook between its Space read and its Resource read (a test-only seam in `postgres.rs`, or a `pg_sleep` the test injects there) that lets the commit land, after which `load_space` must answer the Space and Resources from one side of the commit, both old or both new, never a mix that fails intake.
- [x] `sqlx` gains the `postgres` feature and the TLS feature Q10 names in `[workspace.dependencies]`; clippy and nextest stay green under the workspace lints.

**Named mutants (each killed by this ticket's tests):** `updated_at` not set on a Space or a Resource update; `created_at` overwritten by an upsert; no isolation set at all; `load_space` run outside a transaction, or as one READ COMMITTED transaction rather than `REPEATABLE READ READ ONLY` (both killed by the torn-read test); READ COMMITTED replaced by SERIALIZABLE or REPEATABLE READ for locking transactions; `40001`, `UnexpectedEof`, `ECONNREFUSED`, `53300` or `57P03` classified unclassified (killed by `classify`'s unit tests over constructed errors: through the pool those three connect-time failures arrive only as `PoolTimedOut`, Q8); `28P01` or `3D000` classified Unreachable; every error classified Unreachable; `42P01` not an invariant failure; `PoolTimedOut` not Unreachable; `DATABASE_URL` not trimmed; the `.env` value preferred over the environment's; `sslmode` passed to `sqlx` unchanged (killed by the `require` test: `sqlx`'s `require` would not verify); the support returning early instead of panicking without a server. (The advisory key and mode, and `23505` handling, are killed in 07.)

## Comments

**2026-11-26, resolved.** `crates/host/src/sql/postgres.rs` (the store, `classify`, `connect_options`), `src/sql/database_url.rs` (`DatabaseUrl::resolve`, `nearest_env_file`), `tests/postgres_support/`, `tests/postgres.rs` (server tests, `#[ignore]`d) and `tests/postgres_url.rs` (no server). Run locally against PostgreSQL 16.15, three times in a row, and under nextest as CI runs it: 10 passed. CI: the `rust` job runs `cargo nextest run --run-ignored only --no-tests=fail -E 'binary(/^postgres/)'` with `INFINITY_CUBE_POSTGRES_TEST_URL` set to Compose's server; `crap-rust` starts the same server and runs `pnpm crap:rust:coverage:postgres`, which includes the ignored tests but `shared_migrations`.

- **`pg`'s `sslmode`, run first** (`pg` 8.22.0, `pg-connection-string` 2.14.0, against a server with no TLS): no `sslmode` and `disable` connect in plaintext; `prefer`, `require` and `verify-ca` are refused ("The server does not support SSL connections", with `pg`'s warning that it treats them as `verify-full`); `verify-full` likewise. `uselibpqcompat=true` is honoured: `prefer` is still refused (no plaintext fallback), `require` encrypts without checking, and `verify-ca` with no `sslrootcert` throws before connecting. From the source: `no-verify` encrypts without checking, any other value or `sslrootcert`/`sslcert`/`sslkey`/`ssl=true` asks for verified TLS. `connect_options` follows that, one unit test per value; it strips `sslmode`, `uselibpqcompat` and `ssl` before `sqlx` reads the URL, since `sqlx` refuses `no-verify`.
- **Torn-read seam:** a `Step::SpaceRead(id)` probe point between `load_space`'s two reads, used by `reads_a_space_and_its_resources_from_one_side_of_a_commit`.
- **`classify`** adds the SQLSTATE to the message (`… (SQLSTATE 22P05)`), which `sqlx`'s own words leave out, so the `\u0000` test pins it by code.
- **Template creation** takes a session advisory lock on the server, since nextest runs each test as its own process.

**Named mutants (checked by hand unless the killer is a unit test):** `updated_at` not set on a Space update: `advances_a_spaces_updated_at…` (run). Resource `updated_at`, `created_at` overwritten: `advances_a_resources_updated_at_and_keeps_its_created_at…`. Unlocked reads as READ COMMITTED: the torn-read test (run). Locking transactions without an isolation level: the serializable-default test (run); SERIALIZABLE or REPEATABLE READ for them: the same test (the loser's row lock answers `40001`). Each SQLSTATE and `io::ErrorKind` classified the wrong way, every error Unreachable, `42P01` not invariant, `PoolTimedOut` not Unreachable: `classify_a_failure`. `DATABASE_URL` not trimmed, the `.env` preferred over the environment: `postgres_url.rs`. `sslmode` passed unchanged: `verifies_the_certificate_and_host_for_prefer_require_and_verify_ca` (the server test cannot tell, since `sqlx`'s own `require` also refuses a server with no TLS). The support returning early without a server: run without the variable, every test fails at `server()`.

**2026-11-26, after CodeRabbit's second review.** The `sslrootcert` and `verify-ca` behaviour above is superseded: `sqlx` 0.9.1 adds a named CA to the system's roots rather than trusting it alone, so `connect_options` now refuses a non-empty `sslrootcert`, `ssl-root-cert` or `ssl-ca` before a port is taken, reads an empty one as absent, ignores `PGSSLROOTCERT`, refuses libpq's `verify-ca` pointing to `verify-full`, and refuses `sslnegotiation=direct`, which `sqlx` cannot do. ADR 0177's TLS bullet records the rule; the tests are in `src/sql/postgres/tests.rs`, module `read_sslmode_as_pg_does`.
