# Retaining a Resource’s aspect ratio during Resize

**Recommendation.** Let an author hold Shift before dragging the existing bottom-right handle to preserve the Resource’s current width-to-height ratio for that drag. Keep ordinary dragging free on both axes. Keynote uses Shift-drag for proportional resizing, so the gesture has a precedent in a presentation editor. Sampling Shift when the drag starts is a proposed InfinityCube decision. [Keynote keyboard shortcuts](https://support.apple.com/en-bn/guide/keynote/tanfde4a3e6d/mac)

## Which ratio?

Use the rect stored on this Map when the gesture starts. A Resource can have a different size on each Map. For example, a 400 × 300 rect dragged proportionally to 600 wide becomes 600 × 450. This works for an Ur, Markdown or Image Resource through the same control. [Map sizes and Resize, MG-22–26](../../docs/requirements/maps-and-graphs.md)

A picture’s proportions are a separate concern. An Image already draws its whole picture inside the authored rect. If the author has placed a square picture in a wide rect, preserving the rect’s ratio preserves the spare space too. Fitting the rect to the picture would be a separate command with different inputs. The Image contract allows saved files without natural dimensions and calls for retiring their measurement. [Rendering, RD-2–4](../../docs/requirements/rendering.md) · [Image dimensions, SR-26](../../docs/requirements/space-and-resources.md)

## How it fits the current gesture

The current control fixes the top-left corner. During a drag only the subject previews the new size. Release sends one Resize Edit, which also displaces any affected neighbours. Cancellation discards the preview. Proportional resizing can use that same path by changing only the proposed width and height. A transient modifier needs no new stored field. [Resize control, UI-66–70](../../docs/requirements/ui.md#resize-control) · [Resize preview, RD-57](../../docs/requirements/rendering.md) · [Resize and displacement, MG-23–25](../../docs/requirements/maps-and-graphs.md)

React Flow’s existing `NodeResizeControl` accepts `keepAspectRatio`, defaulting to false. In the installed versions (`@xyflow/react` 12.11.2 and `@xyflow/system` 0.0.79), the resizer captures the node’s measured width divided by height at drag start and calculates constrained dimensions before calling `shouldResize`. InfinityCube already takes those dimensions as a proposal and returns false so its own adapter controls the preview. That measured size is the browser’s box for the node, which can differ from the stored rect by sub-pixel rounding, especially away from the default zoom, so `keepAspectRatio` would take a slightly different ratio than the one “Which ratio?” chooses. The adapter should therefore compute the proportional size itself, from the stored rect, rather than turn on `keepAspectRatio`. [React Flow control API](https://reactflow.dev/api-reference/components/node-resize-control) · [React Flow’s installed resize implementation](https://unpkg.com/@xyflow/system@0.0.79/dist/esm/index.mjs) · [InfinityCube control](../../packages/react-flow-adapter/src/ResourceNode.tsx)

The timing matters. Changing the React prop during a gesture reconfigures the drag listeners. InfinityCube specifically keeps its callbacks stable because tearing those listeners down can interrupt touch resizing. For Shift-drag, read the mode once, from `shiftKey` on the mouse or touch event that began the drag, which React Flow passes to `onResizeStart` as `sourceEvent`, and hold it through release or cancellation. Nothing then changes a prop mid-gesture, and the modifier is read correctly even when Shift was pressed before the window had focus, which tracking Shift’s keydown and keyup would miss. A design that lets Shift change the ratio mid-drag would need a different implementation and its own browser proof. [Control lifecycle and cancellation](../../packages/react-flow-adapter/src/ResourceNode.tsx)

## Minimum size and verification

Both dimensions must satisfy the Closed Size of 260 × 146. Scale both axes by one factor, with a minimum of `max(260 / startingWidth, 146 / startingHeight)`. A 400 × 300 rect therefore stops at 260 × 195. A 600 × 200 rect stops at 438 × 146. Independently clamping the two dimensions would distort the rect at the limit. [Minimum dimensions, MG-22 and MG-82](../../docs/requirements/maps-and-graphs.md)

Shift already has a meaning on the canvas: it is the selection key for a selection box and a multi-selection key for a click (Navigation NV-9). Pressing on the control with Shift held must neither start a selection box nor, when the pointer does not move, deselect the Resource and take the control away. Proportional sizes are fractional unless rounded, so the saved rect should be whole canvas units, with the dimension that meets the floor set to exactly 260 or 146 and the other derived from it; scaling both by one floating-point factor can land just under the floor.

Before adopting the gesture, extend the browser Resize cases with both floor examples, a drag at non-default zoom, release after letting go of Shift, a Shift-press on the control that does not move, and cancellation. Check the preview and saved rect agree, the top-left stays fixed, and neighbours first move on commit. Retain the free mouse and touch drag cases. The product choice for touch is whether proportional resizing also needs a visible control. Keynote for iCloud offers a “Constrain proportions” option for that interaction.
