# 08: Teach the getting-started skill the desktop application path

**What to build:** An agent following `infinity-cube-getting-started` can set a person up to open their Space in the desktop application, which the README's Getting started now leads with, as well as with `pnpm cube run`. When it passes on the README's "Running a Space" and "Stopping and lost edits" points, it tells the person only what applies to the host they are using. That needs one README change too: "Stopping and lost edits" is scoped whole to `pnpm cube run`, though some of its points hold for both hosts.

**Blocked by:** none. The README's Getting started landed in PR #514; the "Stopping and lost edits" change is part of this ticket.

**Status:** ready-for-agent

**Why:** PR #514 rewrote the README's Getting started around the desktop application, built from source, with `pnpm cube run` as the alternative. The skill (`plugins/infinity-cube/skills/infinity-cube-getting-started/SKILL.md`) still starts only `pnpm cube run`. Its step 6 tells the agent to read "Running a Space" and "Stopping and lost edits" and pass on each point. "Running a Space" now covers both hosts and marks its clauses that apply only to `pnpm cube run` ("Under `pnpm cube run`, …"); "Stopping and lost edits" opens by saying it is about `pnpm cube run`. So a desktop user gets no build or open steps from the skill, and the skill's own done-signals (a printed address) never occur on the desktop path. This was raised in review on PR #514 and left out of it, because a skill change needs a plugin version bump.

- [ ] The skill offers the desktop path by pointing at README Getting started steps 1–5 as a whole (tools, install, `pnpm cube init`, the browser build before `cargo build -p infinity-cube-desktop`, opening the Space, and running `pnpm install` and both builds again after a pull), rather than listing or restating parts of them, as ticket 07 did for Running.
- [ ] The skill says which path to choose, taking the platforms from README Getting started rather than restating them: desktop only where that section says it runs (on macOS only with its warning that it has not been tried), `pnpm cube run` everywhere else, and `pnpm cube run` when the agent will start the run itself (`--no-open`).
- [ ] For the desktop path, the skill passes on all of README Getting started step 8 and ends on its done-signal, including why not to send a signal: the shell has none of `cube run`'s handling, so a signal ends it at once and edits not yet written are lost. (The shell otherwise writes about a second after editing stops, as `cube run` does.)
- [ ] The README's "Stopping and lost edits" marks which of its points apply only to `pnpm cube run` (Ctrl-C, the printed lines, the retry and exit messages), as "Running a Space" does, and keeps unmarked the points that hold for both hosts (a kill or power cut loses the last second; a crash mid-write can leave files mixed, and git restores them).
- [ ] Step 6 passes on only the points of those two sections that apply to the chosen host.
- [ ] Steps 5 and 6 get desktop done-signals in place of the address, which a desktop run never prints. Signals only the person can see (the Space window showing the Map with `Resource 1`, both windows closed with no dialog) are the person's to confirm, and the agent asks them. Where the agent starts the application itself, it can also check that the process is running and `.infinity-cube.lock` exists in the directory.
- [ ] The skill's `description` frontmatter names the desktop application, so a request to set it up routes to this skill.
- [ ] The plugin version is bumped in all three manifests (`plugins/infinity-cube/plugin.json`, `plugins/infinity-cube/.claude-plugin/plugin.json` and `plugins/infinity-cube/.codex-plugin/plugin.json`; not the root `.claude-plugin/marketplace.json`), per the Workflow doc's skills section; `test/unit/skills-marketplace.test.ts` fails if they disagree. Links stay absolute, since the skill is installed outside this repository. No test checks this skill's links (`test/unit/agent-skill-commands.test.ts` checks only `infinity-cube-authoring`'s), so either add one or check by hand.
