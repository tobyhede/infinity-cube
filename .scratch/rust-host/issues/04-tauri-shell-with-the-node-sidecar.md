# 04 — The Tauri desktop shell, with the Node host as its sidecar

**Status:** ready-for-human

**Blocked by:** 03. Not blocked by 01: like 03, this implements ADR 0155's first stage, and its code landed ahead of the ADR's acceptance by the maintainer's choice (17 November 2026).

**What to build:** A Tauri v2 application in `packages/desktop/` (its `src-tauri/` a member of the Cargo workspace since 09) that opens each Aggregate directory in a window of its own, served by its own run, closes each run only once its last edit is on disk, and shows why a folder did not open in a native dialog, never an empty window. macOS Apple Silicon first. Every box but macOS is checked on Linux; what is left needs a person with a Mac, and a decision on the independent window's box.

**The design now.** 13 replaced this stage's Node sidecar with the Rust host in the shell's own process, served through the `infinitycube` URI scheme at an origin per Aggregate, so there is no port, launch secret or five-second kill, and the colour scheme survives a restart (Storage ST-121, ST-122). There is no home window: a folder named on the command line opens at once; with none named, or none that opens, the shell asks for one, and cancelling ends the application; File › Open… (`CmdOrCtrl+O`) opens another folder while it runs (`src-tauri/src/launch.rs`). A missing or empty folder is offered a new Space rather than refused with text naming `pnpm cube init`, and File › New Space… writes one (24). Space windows hold no IPC permission. The boxes below are held to that design; the sidecar text they replaced is in git.

Two additions beyond the first list were accepted for this stage: a directory named on the command line opens at once, and `tauri.conf.json` bundles for every target (`"targets": "all"`). Windows and Linux bundles stay unverified until 22 and 23.

- [x] Closing a window after an edit leaves the directory with the edit.
- [x] Opening a Space and closing it without an edit leaves the directory unchanged (ST-65).
- [x] A 10 MiB asset upload works.
- [x] Two Spaces' sessions do not overwrite each other. With the sidecar this was each sidecar's cookie named for its port (`test/unit/desktop-handler.test.ts`); now each Aggregate has an origin of its own, and two Spaces edited at once each wrote only their own directory (Evidence below).
- [x] Two Spaces open at once in the shell, each in its own window, without interfering.
- [x] The Notes window opens from a Space window and stays in step with it in the shell.
- [x] Opening a Resource independently opens from a Space window and stays in step with it in the shell. It opens, under the Space's origin, and its Edits are written; the Space window does not redraw them until it reloads or its own next Edit meets the conflict notice (Editing ED-41, ED-49), as two browser tabs on one Space behave. The maintainer accepted that as "in step" on 2026-11-23 (ADR 0167, Consequences); live redrawing between the two windows is not part of this issue.
- [x] A folder that fails to start, or that the run refuses, shows the intake's errors in a native error dialog and opens no Space window.
- [ ] Every box above checked on macOS Apple Silicon. Not run: no Mac was available. 13's "macOS check by hand" lists the steps.

## Comments

**2026-11-17 (progress).** Built in `packages/desktop/`: `src-tauri/src/main.rs` (home window, `open_talk` the only command and granted to the home window alone by `capabilities/home.json`, one sidecar per talk window, close held until the sidecar exits or five seconds pass, every sidecar stopped on exit, a folder named on the command line opened at once), `src-tauri/src/sidecar.rs` (start, read the announcement, stop by closing stdin), `scripts/build-sidecar.ts` (browser build, sidecar bundle, Node single executable named for Tauri's `externalBin`, ad-hoc signed on macOS). Talk windows load `http://127.0.0.1:<port>/?launch=<secret>` and are given no capability, so they cannot invoke the shell.

Checked on Linux x64 only (no macOS here): `cargo clippy --all-targets -D warnings` and `cargo test` (2) clean; under Xvfb with Openbox the app opened the fixture in its own WebKitGTK window and drew the Map; closing that window through the window manager stopped its sidecar and left the home window open; `tauri build --bundles deb` produced a 52 MB package. Not checked: macOS at all, an edit made through the window and written on close (the stdin-close write is held by `test/integration/desktop-sidecar.test.ts`), a 10 MiB upload, two talks at once.

**2026-11-17 (review).** Still not checked on macOS, so the macOS box and every behaviour box tried only in the shell stay open; the one box ticked is held by a unit test, not by the shell. Since the first comment: the shell gives up on a sidecar that has not announced within 30 seconds (`ANNOUNCE_DEADLINE`, `src-tauri/src/sidecar.rs`), and every error path stops and reaps the sidecar before returning (`sidecar.rs` tests `gives_up_on_a_sidecar_that_never_announces_and_reaps_it` and `reaps_a_sidecar_whose_announcement_cannot_be_read`); talk windows navigate only within their own sidecar's origin. A refusal is shown as a native error dialog (`show_error`, `src-tauri/src/main.rs`), not in the window.

**2026-11-17 (review fixes).** Talks are kept by canonical directory in `src-tauri/src/talks.rs` (`Registry`): opening a directory already open, starting or closing focuses its window rather than starting a second sidecar, and a repeated close request keeps the window held until the sidecar has stopped. Closing a window shows a native error dialog before the window goes when the sidecar exited non-zero or was killed (`Stopped::unwritten`, `sidecar.rs`); on quitting, the event loop is ending, so that case goes to standard error only. A thread looks every half second for a sidecar that stopped by itself (`Sidecar::exited`) and closes its window with a dialog saying so. On Windows the sidecar is spawned with `CREATE_NO_WINDOW`. `scripts/build-sidecar.ts` refuses a Rust host triple naming another platform or architecture than the Node it copies (`test/unit/desktop-build-sidecar.test.ts`). Held by `cargo test` (20, Linux x64) for the registry's transitions, the stop classification and the watcher's view of a fake sidecar; the dialogs, focusing and the Windows flag are not tried in the shell.

**2026-11-22 (evidence, current design).** Run by hand under Xvfb with Openbox and WebKitGTK 2.52, `target/debug/infinity-cube-desktop` built from this branch, clicks and keys sent with `xdotool`, read from screenshots; each Space a fresh directory (`pnpm cube init`, or a copy of `packages/app/fixture`). Linux only.

- *Edit on close.* A Markdown Resource created and titled "Written on close", and the window closed by the window manager at once, under the one-second quiet period: the window went, and the Resource's file held the title.
- *No edit, no write.* Two Spaces opened and the application quit with no edit: every file's SHA-256 and modification time the same before and after.
- *10 MiB upload.* The first try found a crash: picking any file for an Image Resource (64×64 or 10 MiB) ended the process, a segfault in `libwebkit2gtk-4.1.so` (`segfault at 28 … in libwebkit2gtk-4.1.so.0.21.10`, the kernel log). 13's 10 MiB evidence sent bytes from a script, never a picked file. The page now sends a picked file's bytes from memory (`packages/http/src/backend.ts` `storeAsset`, held by `asset-http-client.test.ts` › "sends the bytes from memory, never the Blob itself"); rebuilt, a 10 485 760-byte PNG picked in the file chooser was stored under `assets/` byte for byte (the same SHA-256) and drawn as a new Image Resource.
- *Two Spaces.* Two Spaces open at once, each in its own window titled by its folder; "Only in A" made in one and "Only in B" in the other each landed only in its own directory. With the fixture in both, each presented at once: the Notes window of one ("Presenting B", its timer running) did not move when the other advanced to C, and said "Not presenting" when its own presenting stopped while the other still presented. A Dark colour scheme set in one Space stayed Dark after closing and reopening it and after quitting and relaunching, the other staying Light (13's colour scheme box).
- *Notes window.* S while presenting opened the Notes window under the Space's origin; it showed the presented Resource and its moves, Go to B in it moved the Stage to B, and Escape on the Stage set it to "Not presenting".
- *Resource opened independently.* Open in New Tab on the Space Resource "Deep dive" opened a window on that Space, under the same origin. A Resource renamed there was written; the Space's window, entered into the same Space, still drew the old title, and its next Edit showed "Changes conflict" with Reload and Keep local and retry; Reload drew the rename.
- *Refusal.* A folder holding only `notes.txt` showed "… is not a Space InfinityCube can open: - aggregate.json: a canonical aggregate directory must contain aggregate.json (aggregate-file-missing at aggregate.json)" in an error dialog, with no Space window; dismissing it asked for a folder, and cancelling ended the application.
