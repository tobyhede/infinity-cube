# 15 — The Rust SQLite store

**Status:** ready-for-agent

**Category:** enhancement

**Blocked by:** 11, 14.

**What to build:** One SQL repository over `sqlx` implementing the storage trait, with SQLite first. The TypeScript SQLite host is not a CLI verb but `pnpm dev:sqlite` (`scripts/dev-sqlite.ts`, through Vite): the Rust binary gains a `serve --store sqlite` verb that serves the file `SQLITE_PATH` names, as `pnpm dev:sqlite` does. The SQLite restart proof (`test/e2e/sqlite-persistence.spec.ts`, `pnpm e2e:sqlite`) starts its two hosts with Vite's `createServer` today; it gains a way to start a host by command instead (the command and its environment given to the spec), so the same spec runs against the Rust binary unchanged. The HTTP conformance suite (08) holds it through the Rust port's wire and store-condition cases, as the Agent Brief below sets out.

The acceptance criteria are the Agent Brief's, below; they replace the two this ticket was written with.

### Agent Brief (triage, 2026-11-22)

**Category:** enhancement
**Summary:** A SQL `SpaceRepository` over `sqlx`, SQLite first, served by a new `serve --store sqlite` verb of the Rust binary, held to the HTTP contract and to the SQLite restart proof.

**Current behavior:** The Rust host has a `SpaceRepository` trait (list, load, load aggregate, commit through the pure `decide_commit`, store and load asset, initialize, replace, mark exported, load Meta id) and a memory store only. `sqlx` (SQLite and PostgreSQL drivers, `migrate`) is a dev-dependency of `host`, used only by the shared-migrations test (14). The CLI answers `run`, `check`, `init` and `--version`; it has no `serve`. The TypeScript SQLite host is `pnpm dev:sqlite`, through Vite, over the one TypeScript SQL repository (Storage ST-3). Both restart proofs start their hosts with Vite's `createServer`.

**Desired behavior:**
- One SQL repository in `host` implementing `SpaceRepository`, written so that 16 adds PostgreSQL as a second small store of statements over the same repository rather than a second repository (ST-3). It answers every trait method as the memory store does, by the same `decide_commit`.
- `infinity-cube serve --store sqlite [--port <port>]` serves the file `SQLITE_PATH` names on `127.0.0.1`, behind the same listener and `Host` check `run` uses (421 for any other `Host`), announcing itself on standard output as `run` does. It runs no Import, no Export and takes no directory lock. It stops on SIGINT, SIGTERM or SIGHUP.
- **Start-up** follows ST-10: an uninitialized file is initialized from Default Content once, never reseeded. The host serves at once, announcing as soon as it listens, and establishes the Meta Space in the background, as the TypeScript database host does: an unreachable store is retried with the TypeScript start-up's back-off (doubling from the first delay to a cap, then holding), and start-up stops on a failure that a second consecutive attempt confirms no wait cures (broken stored state, or an unclassified failure); contradictory stored state is an invariant failure (ST-7), never repaired. There is no Rust Default Content aggregate to call yet: `init`'s generator is private and builds the directory's files, not an aggregate the lifecycle door takes, so making one generator answer both (held to `conformance/init/` as `init` is) is part of this ticket.
- **Path rules** follow ST-126 for a host: an unset, blank or relative `SQLITE_PATH`, or a missing or unwritable parent, is refused with the TypeScript host's messages. A file that does not exist is not refused up front: that refusal (naming `pnpm db:migrate:sqlite`) is the CLI's alone, and the host does not add it.
- **Migrations:** `serve` does not migrate. It expects a file already migrated, as the TypeScript host does, by whichever migrator the repository has at the time. Migrating from Rust is 16's (ADR 0173), and no applied-migration record is ever seeded.
- **File settings** follow ST-128: rollback journal in `delete` mode and `synchronous=FULL`. `sqlx`'s SQLite connect options default to WAL, so this must be set explicitly. A test reads `journal_mode` back from the file, and `synchronous`, which is per connection and not stored in the file, through a connection from the repository's own pool.
- **Concurrency** follows ST-127: repository operations are serialised inside the process, so overlapping Edits to one Space answer as conflicts; a file locked by another process fails at once or after a bounded busy timeout as `persistence-unavailable`, answered over HTTP as retryable 503, never 409, leaving no partial write or stuck lock.
- **The restart proof** (`pnpm e2e:sqlite`) gains a way to start each of its two hosts by a command given to the spec (program, arguments and environment), defaulting to the Vite host it starts today, so the same spec runs unchanged against `infinity-cube serve --store sqlite`. The proof's seeding and Export still go through the TypeScript repository against the same file, which also checks that the two runtimes read each other's rows; keep its rule of one open connection to the file at a time.

**Conformance:** the process cases of the HTTP conformance suite always run a `{directory}` and check Export, which a store-backed host has neither of, so they are not the gate here. Instead:
- the wire cases (`http_conformance::cases!`) run against `Application` over the SQLite repository, seeded with the tracked fixture through the lifecycle doors, each case on a fresh temporary file;
- the store-condition cases (`uninitialized`, `unavailable`, `broken-stored-state`) run against `Application` over a SQLite repository in each condition;
- `test/unit/http-conformance-rust-ports.test.ts` knows the new adapter, so a case without a SQLite port fails unless exempted with why.

**Acceptance criteria:**
- [ ] Every wire case and store-condition case passes against `Application` over the SQLite repository in CI's `rust` job, and the ports test covers that adapter.
- [ ] Rust tests hold ST-126's host refusals, ST-128's pragmas, ST-127's conflict and busy-file answers, and ST-10's initialize-once, never-reseed, bounded back-off and confirmed stop, with the host announcing before the store is reachable.
- [ ] The SQLite restart proof passes in CI's `sqlite` job both on the Vite host (unchanged default) and on `infinity-cube serve --store sqlite`.
- [ ] A file migrated by `pnpm db:migrate:sqlite` is served by `serve --store sqlite` with no Rust migration step.
- [ ] `sqlx` becomes a dependency of `host` (not only a dev-dependency); `cargo clippy` and `cargo nextest` stay green with the workspace lints.
- [ ] Storage requirements (the SQLite host section and the Operations index) and the `AGENTS.md` Commands section name `serve --store sqlite` beside `pnpm dev:sqlite`.

**Out of scope:**
- PostgreSQL, `serve --store postgres`, and the `migrate` verb (16).
- `import` and `export` against a store, and `init` (17); moving `pnpm dev:sqlite` or any Playwright config's default host to Rust (19).
- Any change to the HTTP contract, the browser application or the TypeScript SQL repository's behaviour.
