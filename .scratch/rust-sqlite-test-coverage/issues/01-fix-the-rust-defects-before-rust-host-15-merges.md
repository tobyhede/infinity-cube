# 01 — Fix the Rust defects before rust-host 15 merges

**Status:** ready-for-agent

**Blocked by:** None. This lands on the rust-host 15 branches (PR #520 for the repository and start-up, PR #521 for `serve`) before either merges, not on `main`.

**What to build:** The seven behaviours the spec's Decisions name as Rust defects, each fixed with a failing Rust test first, and the owning requirement changed in the same commit. The behaviours the spec calls already right (well-formed Unicode at entry, the four broken stored states) are tested in 05, not here.

- [ ] **Revision ceiling.** A commit from a Space stored at revision 2^63−1 is refused as an invariant failure and leaves the stored revision where it was, on the memory store and on SQLite, on the single-Space fast path and the aggregate write path. Today `Revision::next` (`crates/host/src/repository.rs`) saturates at the ceiling, so the commit succeeds and a second commit with the same expected revision overwrites the first. The test commits twice with one expected revision and asserts the second is not committed and the first's content stands. Deleting a Space stored at the ceiling still commits, as in TypeScript, and a test holds it. The SQLite test carries `// Case: refuses to store a revision above the 2^63-1 ceiling` and is that case's port (03), so 04 writes no second one. (ST-6.)
- [ ] **A file SQLite cannot open, split by cause.** In the SQLite store's `classify` (`crates/host/src/sql/sqlite.rs`), code 14 (`SQLITE_CANTOPEN`) is an unclassified failure (HTTP 500, start-up stops after the confirming retry) unless the file does not exist, which stays unavailable (503, start-up keeps retrying) as ST-126 says. Tests: a directory at the path and a file the process may not read each answer unclassified; the existing `answers_a_file_that_does_not_exist_as_unavailable_creating_nothing` and `opens_the_file_once_it_exists_after_failing_to` (`crates/host/tests/sqlite.rs`) and the rustdoc example in `sql/sqlite.rs` stay green unchanged. The unreadable-file test skips, saying so, when run as root. `serve --store sqlite` refuses a `SQLITE_PATH` naming something other than a regular file (a directory) before it takes a port, as it refuses a missing file; a process test in `crates/cli/tests/serve.rs` holds it. ST-126 gains both clauses.
- [ ] **A schema missing a table.** A migrated file with any one of `spaces`, `resources`, `repository_state` or `assets` dropped answers broken stored state (500) from every repository operation (`load_aggregate`, `load_space`, `list_spaces`, `commit`, the lifecycle doors, `mark_exported`, `store_asset`, `load_asset`), not `Uninitialized`, an unclassified failure, or success. A 0-byte file answers the same. One test per table, each calling every operation, and one for the 0-byte file. Today the emptiness check reads only `spaces` (`crates/host/src/sql.rs`), a dropped `assets` table goes unnoticed by load and commit, `list_spaces` and `load_space` succeed with `repository_state` dropped, and a 0-byte file answers unclassified.
- [ ] **A document stored as a BLOB.** A `spaces` or `resources` row whose document is a BLOB answers broken stored state (500), as TypeScript answers it, from `load_aggregate`, `load_space` and `list_spaces`. Today `CAST(document AS TEXT)` reads it as text.
- [ ] **A `SQLITE_PATH` that is not UTF-8.** `serve --store sqlite` refuses it with a message naming `SQLITE_PATH`, before it takes a port, instead of converting it lossily and opening a file of the mangled name if one exists. A process test in `crates/cli/tests/serve.rs` holds it on Linux, with a file of the mangled name present. ST-126 gains that clause.
- [ ] **A file replaced or deleted under the host.** Before each repository operation the SQLite store checks that `SQLITE_PATH` still names the file it opened (same device and inode, read at open). If the file was replaced or deleted, the operation answers unavailable (503) and reads or writes neither the old file nor the new one. Tests on SQLite: open, load, then replace the file with another migrated file (rename over it) and assert the next `load_aggregate` and `commit` answer unavailable and neither file changes; the same after deleting the file. ST-126 gains the clause. The test may be Unix-only if Windows refuses to replace or delete a file the host holds open.
- [ ] **One broken Space must not hide the others.** `list_spaces` lists every Space when one Space's document is not JSON, is JSON with no string `title`, or holds a lone UTF-16 surrogate, as it already does for a titled document that fails intake. ST-7 records how a Space with no readable title is listed. The tests are written here, failing first: on SQLite, for each broken document shape (JSON failing intake, JSON with no string `title`, not JSON, a lone surrogate), `list_spaces` lists every Space, the broken one included, and loading the broken Space answers broken stored state. 05 points its port lines at them.
- [ ] The tests above run in CI's `rust` job, and #520 and #521 stay green. #521 is rebased onto #520 after #520's fixes land, never merged.
