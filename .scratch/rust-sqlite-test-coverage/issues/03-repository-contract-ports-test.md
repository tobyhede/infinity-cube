# 03 — A ports test for the repository contract

**Status:** resolved

**Blocked by:** 02 (the ADR its exemptions cite).

**What to build:** A unit test, shaped as `test/unit/http-conformance-rust-ports.test.ts` is, that reads the cases of the TypeScript repository contract (`test/support/repository-contract.ts`) and fails for any case with no Rust test carrying its `// Case:` line in the Rust SQLite repository's test files (`crates/host/tests/sqlite*.rs`, `crates/host/tests/startup.rs`, `crates/host/src/**` unit tests and `crates/cli/tests/serve.rs`, listed in the test), unless the test exempts it with its reason. TypeScript's contract is not changed. The test reads, the same way, the `it` cases of the TypeScript SQLite files outside the contract: `test/integration/sqlite-space-repository.test.ts` beyond its contract call, `sqlite-contention.test.ts`, `sqlite-fast-path-races.test.ts` with `test/support/fast-path-races.ts`, and `sqlite-http-runtime.test.ts`.

- [x] Case names come from each `it` call's first argument: the leading `${name} ` (the harness's store name) is dropped and any other substitution is written `*`. The contract gives 73 names (the four further files add their own, which the test counts per file rather than to a fixed total). Three of the contract's are written once and run for two values each (the loops at lines 530, 889 and 2444 today, 76 runs in all); the ports test lists each such name's values, and one Rust test per value carries `// Case: <name> (<value>)`.
- [x] The test fails on a case with neither a port nor an exemption, on an exemption or port naming no case, and on a case both ported and exempt, as the HTTP ports test's `exemptAndPorted` does.
- [x] "writes a moved Resource through the ownership check, which refuses it before its Space releases it" is exempt, naming the spec's decision on change order.
- [x] "names a broken stored document broken stored state on the single-Space fast path, and leaves loadSpace's answer narrower" is **ported**, not exempt: the Rust port asserts the fast-path half as the case does, and asserts Rust's `load_space` answers broken stored state, with a comment naming ST-7 (02) for why Rust's answer is not TypeScript's narrower one.
- [x] An exemption is one of two kinds: **pending** (names the ticket that ports it) or **does not apply** (names why, e.g. the TypeScript row-lock recreation cases, which Rust decides inside one `BEGIN IMMEDIATE` transaction). The ports test tells them apart.
- [x] Until 04, 05, 06, 10, 11, 12 and 13 land, every other case unported today is listed as a pending exemption naming the ticket that ports it, so the test is green from its first commit and each port deletes a line. Every pending case names exactly one of those tickets: commits and lifecycle doors to 04, broken state and classification to 05 (with the repository cases outside the contract), assets to 06, contention to 10, HTTP runtime cases to 11, stored content and Export to 12, in-process races to 13.

## Comments

### Resolved (2026-11-26)

`test/unit/repository-contract-rust-ports.test.ts`, reading cases through `test/support/case-names.ts`. It reads the 73 contract cases (76 runs, the three looped ones named `<name> (<value>)`) and the cases of the four outside files, and the `// Case:` lines of `crates/host/tests/sqlite*.rs`, `startup.rs`, every `.rs` under `crates/host/src` and `crates/cli/tests/serve.rs`. A mark naming an HTTP conformance case is allowed, since `sqlite_wire.rs` carries the HTTP ports test's marks. Each exemption is `pending(<ticket>)` or `doesNotApply(<reason>)`. Ported from the first commit: the revision ceiling (01), and three tests already in `crates/host/tests/sqlite.rs` that now carry their lines: the journal settings, the same-Space race and the lock let go inside the busy timeout. Does not apply: the change-order case (ADR 0176), the two row-lock recreation runs and the row-moved-before-the-lock case (one `BEGIN IMMEDIATE` transaction), and the PostgreSQL contention code.
