# Fresh hand mutants of the PostgreSQL store and the concurrency seam

24 mutants of `crates/host/src/sql/postgres.rs` (the statements) and `crates/host/src/sql.rs` (the seam every PostgreSQL operation runs through), written for this audit. None is in ticket 13's catalogue (`.scratch/mutation-testing/rust-postgresql-store.md`): each was checked against its tables, and against `cargo-mutants`' function-level mutants, before it was run. The aim was the statement-level and protocol-level changes a function-level tool cannot make: a `FOR UPDATE` dropped or weakened, a predicate loosened, a session-level lock where a transaction-level one belongs, an operation given a lock it must not take.

## How they ran

Each mutant was applied to the working tree alone, then every PostgreSQL test ran, then the file was restored with `git checkout` (`evidence.md` › `mutate.py`, `evidence.md` › `run-pg.sh`). "Every PostgreSQL test" is ticket 13's set: each `postgres*` test binary of `host` and the CLI's `serve_postgres`, ignored or not, and the library unit tests of the mutated files (`sql::tests`, the seam's scripted store; `sql::postgres::tests`; `commit::tests`). 403 tests.

- Server: a throwaway PostgreSQL 14.19 cluster on `127.0.0.1`, password login, started for this audit and deleted after. CI runs 17.5. Ticket 13 ran against 14.19 too.
- Unmutated, at `32d316f3`: `403 tests run: 403 passed, 62 skipped` in 52.9 s (`evidence.md` › `baseline-summary.txt`).
- A test ran at most 240 s for A01 to A07, and 60 s from A08 on (`evidence.md` › `nextest.toml`); the slowest unmutated test takes 20.2 s.
- A07 and A08 make every later aggregate lock wait forever, so once each had failed and timed out several tests I stopped its run (189 and 244 of 403 run). Both were already killed.

Result: **16 killed, 8 survived.** Of the 8, 2 are equivalent (A06, A23) and 6 are test gaps (A02, A05, A09, A19, A22, A24), each now in a ticket. None is a correctness gap in the code at `32d316f3`.

## What the survivors say

- The PostgreSQL row-lock statements are held where a race test exercises them (A01, A03, A04, A13, A21), and weakened where none does: no test runs two Edits to one Space side by side (A05).
- The refusals that guard against rows changed outside a decision are held on SQLite by trigger tests and on PostgreSQL only for creation and gone rows (A09, A22).
- The Meta relock's identity comparison is held only against a replacement that lands while the relock waits on the row, not one that lands between the read and the relock (A02).
- The isolation of unlocked writes is set in code, not in ADR 0177, and no test depends on it (A19).
- The lock-mode choices of every operation are held, often only by the seam's scripted store (`sql::tests`) rather than against a server (A12, A14, A15).
