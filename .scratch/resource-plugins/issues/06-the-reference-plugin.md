# 06 — The Reference plugin

Status: done

**Blocked by:** 04 — The Image plugin; 05 — The Markdown plugin.

**What to build:** the Resource embedding, and Reference as an ordinary plugin on it. It keeps `{ open }` in its Map content. Closed, it draws its own Title. Open, it embeds its Target on a surface offering no authoring of the Target, passing the Reference's Title and rename, so the Target's plugin draws that Title as it draws any (ADR 0070). The embedding guards recursion and a deleted Target. A Reference to a Space keeps today's path until `07`.

**Roll forward:** stored `open` on Reference entries moves to Map content, the Reference sites in `.scratch/resource-kind-modules/kind-sites.md` go, and ADR 0123's "own name over the Target's content" gives way for a Target that draws no Title.

**Acceptance:**

- An Open Reference to Markdown or Ur draws its own Title once, with no Target commands.
- An Open Reference to an Image is a picture with the Reference's Title as its text alternative, renamed from the rail.
- Renaming it leaves the Target's Title alone.
- Referencing stays one hop, and a deleted Target draws a note.
- `CI passed` is green.

## Decisions

- **The plugin is `packages/plugin-reference`**, shaped as the other plugins are: its domain half (`{ target }` content, its one Resource reference and content Target, `{ open }` Map content, Closed by default and Open where there is no Map, no `newContent` since it is created from its Target) imports only `@project/resource-api/domain`, and its view half only `@project/resource-api/view`. Closed it draws its Title and its glyph (labelled with the plugin's name, at the top-right corner of its rect, as the canvas drew a kind glyph); Open it draws `surface.Embed` with its Target and its own `surface.title`; Open and Close are rail commands committing `{ open }` with no size hint, and a refusal is said in an alert line (`role="alert"`), as every plugin's refusal notice is.
- **The embedding is the host's, `HostEmbed` in `packages/ui/src/ResourceEmbedding.tsx`**, one component for every surface's lifetime that reads what it draws from context (`EmbeddingProvider`), so a render of the surface never remounts what it embeds. It mounts the Target's plugin entry on a surface with the plugin's `withoutMap` Map content, no content, Map content, Claim, store or pick, and one commit: the passed Title's. It shares the embedding Resource's rail and own region, so the Target's rail commands join the Reference's rail, which is where a picture's rename is. They are drawn after the Reference's own (Close, then Rename), through the rail store's `embedded` outlet, because a child's layout effect publishes before its parent's and ordering by first publish made a Reference drawn Open and one Opened since list them in opposite orders.
- **The embedding offers only what the surface's own content references.** The Map projection and the Stage hand a plugin-drawn Resource `embeddable`, the Resources its content references (`referencedResources` in `@project/graph`), and a Resource embedded inside an embedding embeds nothing further. Notes, drawn in the rect with the shared `.resource-failure` class: recursion, an embedding inside an embedded Resource (the `Embedding`'s `nested` flag, so an existing Resource is never reported deleted), a deleted Target, and a Target whose kind may not be one (not a plugin kind, or not `mayBeTarget`).
- **A Title commit the embedded plugin kept is refused once the embedded surface is gone** (`commitWhileDrawn`), whatever the surface around it still offers. Its test is a unit test of that function: the embedded plugin is resolved from the registry, so no test plugin can be dropped in to retain a commit, and adding a seam for one was more machinery than the rule.
- **On the Map, the passed Title is drawn with the Map's own rename** (the embedding Resource's: Edit Title, the inline editor), read-only where the passed Title carries no commit. Over a Target that draws no Title (an Image), the Map's Title editor is drawn over the plugin while a rename runs, which is where ADR 0123's "own name over the Target's content" gives way: the Reference's name is the picture's text alternative and is not drawn over it.
- **A Reference to a Space Resource keeps today's path until issue 07.** Whether a Resource is drawn by its plugin is `drawnByPlugin` (a plugin kind whose content Target, if any, is a plugin kind), and whether the application keeps its Open is `takesOpen(resource, resourceOf)`, both in `core/src/kinds/registry.ts` and naming no kind; intake, the Open Edit, the canvas and the projection read them. Such a Reference keeps `open` on its Map entry, gets no Map content from the projection, and is drawn by `CanvasResource`. `ResourceNodeData` carries `takesOpen`, so the canvas decoration needs no lookup of the Target.
- **Roll forward:** the fixtures' `"open": false` on Reference entries to Markdown Resources is dropped (the plugin's default is Closed). Tests that used a Reference as "a kind the host keeps Open for" now use a Space Resource or a Reference to one. The Ladle stories draw the Reference through the plugin with `mapContent`/`commitMap`/`commitTitle` on `CanvasResourceNodeSpecimen`; the application e2e and Ladle Reference proofs Open from the rail (Enter now leaves a plugin's Open alone, as for Markdown) and the Image Reference proof renames from the rail and reads both stored Titles.
- **Image and Markdown in `ui`'s `kinds/` no longer carry a `canvas` content view**, since nothing draws an Image or Markdown Target in `CanvasResource`'s content area on the Map any more; `EmbeddedPluginContent` and `NoEmbed` are gone. Their `presented` view stays, drawn by `PresentedPluginContent` (the plugin read-only below a name `PresentedResource` draws), because the Notes window draws presented notes and each move's preview through `PresentedResource`. `CanvasResource`'s content-area machinery stays for issue 10, and its tests now use unresolved content.
- **The Reference's dotted border is drawn on the plugin path too**: `reference-canvas.css` selects `.canvas-resource[data-kind='reference']`, which the plugin host's article carries, so the Ladle `Closed` proof reads a dotted border on the plugin-drawn Reference as it does on `CanvasResource`'s.
- **The plugin keeps the band its surface reserves for the rail (`useRailBand()` from `@project/resource-api/view`: `RAIL_BAND`, 30px, on the Map; 0 on the Stage and inside an embedding) at the top of its rect free of controls**, as the Markdown plugin does, so a click there selects a Closed Reference: Closed, its Title sits at the foot of its rect with the band as its top padding, and the glyph is absolutely placed beside it. Open and Close are one `open-close` rail command whose name swaps.
- **Specs rolled forward after the restack**: the Create Reference unavailable proofs (`editing.spec.ts`, `command-dock.spec.ts`) no longer expect `Open and Expand`, which a plugin-drawn Resource is not offered. The Ladle `Closed` Reference specimen carries real `{ target }` content (`CanvasResourceSpecimen` takes a `content`), the reduced-motion proof reads the `Actions` story, whose Reference Instance shows unresolved content, and the Title proof's Open specimen is a plugin-drawn Markdown Resource. `overview.spec.ts`'s Close proof closes a plugin Reference opened from the rail and reads its embedding gone; no fixture Resource now has a `CanvasResource` content area to fade, and the fade is held by `packages/ui/test/CanvasResource.test.tsx`.
- **The three resize proofs in `editing.spec.ts` that Open Resource A wait for revision 1 before reading the opened revision.** The Markdown plugin commits the Open after the click, so "Persisted" could still be revision 0 and the Open's Edit then landed mid-gesture; it reproduced on the base under `--repeat-each=10 --workers=6` and CI marked both proofs flaky.
- **Reference creation is unchanged until issue 08**, so its two kind-sites rows stay (with refreshed line numbers), as does `icons.tsx`'s badge type.
- **The `infinity-cube-authoring` skill and `docs/aggregate-directory.md` say where a Reference keeps its Open**, and the plugin manifests are bumped to 0.1.4.
- **Intake diagnoses a bad Target once.** A Reference stored Open (`open: true` on its entry) whose Target is missing or may not be a Target reports only `reference-target-missing` or `reference-target-not-targetable`: the `open-requires-content` check waits on the Resource's references resolving, since whether it may be stored Open depends on its Target. A Target that is not a UUID is one `invalid-resource-file`: the core's UUID refine over a plugin's declared ids runs only on content the plugin's schema accepted, and reads an id declared twice (Target and Resource reference) once.
- **Map content on a Resource no plugin draws is described as such**, `which no plugin draws here, so it keeps none`, still as `map-content-invalid`; only content a drawing plugin's schema refuses says "that its plugin refuses".
- **One lookup per question:** `targetIn` in `core/src/kinds/registry.ts` resolves a content Target for `drawnByPlugin` and `takesOpen`, `documentIn` in `snapshot-edits.ts` is the snapshot's document lookup, and `resourceTakesOpen(space, resource)` in `@project/graph` sits beside `resourceDrawnByPlugin` for the projection and the canvas.
- **`ur-stage.css` goes again.** Issue 05 restored it to centre a Reference to an Ur Resource that `PresentedResource` drew; here the Reference plugin draws that Reference on the Stage, embedding the Ur plugin, which centres the Title itself, so nothing carries `data-content-kind="ur"` outside `.resource--plugin` and the Stage imports no kind stylesheet. `presenting.spec.ts`'s Reference-to-Ur proof reads the plugin-drawn Reference with the embedded Ur inside it, still centred.
