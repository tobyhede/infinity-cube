# 09 — The default plugin

Status: done

**Blocked by:** 03 — The asset store; 07 — The Space plugin.

**What to build:** the default plugin, an ordinary plugin the host selects when a stored Resource's `kind` names no plugin in this build, in place of ADR 0120's refusal (`KIND_UNREGISTERED`). It draws the Title and says the kind is not available, in a rectangle. The Resource keeps every canvas capability and offers no authoring of its content or a Create.

Such a Resource is the same `Resource` value as any other, so the host carries it without reading it. A rename changes `title`, `content` and Map content stay unread JSON, and its assets travel by the walk from `03`. Delete removes the Resource, and an asset leaves the Export once nothing references it, while the store keeps it (ADR 0106). A plugin that returns reads the Resource as it stands.

While any plugin is missing, an unrooted Space is held rather than refused. A Resource with no `kind`, and content a present plugin's schema rejects, stay refused.

**Roll forward:** `packages/core/src/schema.ts`'s `kindedContent`, `docs/schema/resource/resource.schema.json`, `packages/graph/src/resource-file.ts`, the unrooted-Space check in `space-aggregate.ts`, `docs/aggregate-directory.md`'s ownership rules, `docs/agents/editing-and-persistence.md`, the `infinity-cube-authoring` skill, and tests asserting the refusal.

**Acceptance:**

- An Aggregate holding an unknown kind opens, and that Resource moves, connects, renames, deletes and presents.
- Run, edit another Resource and Export leave its canonically written `<id>.json` and its assets byte-identical, and its Map content unchanged as JSON.
- Rename → Export → Import shows the new Title, with `content` unchanged as JSON and its assets byte-identical.
- Delete → Export → Import leaves no such Resource and no asset only it referenced, and an asset another Resource references stays.
- For each of PostgreSQL and SQLite: Import, discard the source directory, Export into an empty directory, restore the plugin and Import that directory. The Resource reads through its plugin, and an asset that is not valid UTF-8 is byte-identical.
- Deleting a Resource with no plugin that alone rooted a Space, then restoring the plugin, refuses the aggregate naming that Space.
- Where a Resource with no plugin and a Space Resource both own one Space (ADR 0074's shared ownership), the host cannot read the first's reference, so deleting the Space Resource deletes the Space with it, and restoring the plugin refuses the aggregate naming the Resource whose Space is gone. This is the cost ADR 0142 accepts, not a held Space.
- An asset's file name and media type survive the round trip, under issue 03's naming rule.
- A build that gains the plugin over a store already holding the Resource reads it through the plugin, with no Export or Import.
- `CI passed` is green, including the PostgreSQL and SQLite jobs.

## Decisions

1. The default plugin is its own package, `@project/plugin-default`, built with `definePlugin` and `definePluginView` like any other, and listed in no `plugins.ts`. Its declared kind `default` is never matched, because only listed plugins are matched by kind. Its surface is handed the stored kind instead, so the note names the kind that is missing. Core reads its flags and Map content through `defaultKind` (`packages/core/src/kinds/default.ts`). ui and app reach it through the fallback in `pluginEntryFor` and `defaultDecorator`.
2. A missing kind is the `MissingKind` arm of core's `Resource` union: a branded string, carried as `ResourceKind = KindId | MissingKind`. Comparing a kind with `===` cannot rule out a branded string, so narrowing to one kind is done with `isOfKind(value, kind)`. Tests, scripts and fixtures were rewritten to use it.
3. A missing kind's `content` must be a JSON object. This agrees with the envelope JSON Schema, whose `content` is `object`. A non-object is refused. A kind that is not a well-formed id is still refused, now as `kind-malformed` (`KIND_MALFORMED` replaces `KIND_UNREGISTERED`).
4. A misspelt or miscased bare kind, such as `Markdown`, is well formed. It is now carried as a missing kind and drawn as "not available" instead of being refused. The authoring skill tells authors to check the spelling when a Resource draws that note.
5. A Resource with a missing kind may not become a Target. The default plugin declares no `mayBeTarget`, so `createInMap` refuses `reference-target-not-targetable` and the rail draws Create Reference unavailable, naming the kind. Intake still carries a Reference that already names one (`storedResourceReferenceProblems`), and that Reference embeds the default view. ADR 0142 now says so: a Reference that already names it is kept, and no new Reference to it is created. The other reading, that a new Reference may be created, would let a returning plugin that declares no Target leave the aggregate refused, which is the outcome decision 7 rejects. A missing kind declares no Resource or Space references, and its content resolves as `unresolved`. Also, deleting a Resource that the missing plugin's own references would have named is not refused, because those references cannot be read.
6. The host gives a missing kind's surface only its Title commit, withdrawn by the exclusive gate like any other surface. It gets no content, Map content, store, pick or Claim operation.
7. The held rule applies while any Resource in the aggregate has a missing kind (`loadSpaceAggregate`), and holds only a Space the stored aggregate already holds. A commit that leaves a Space unrooted which the stored aggregate rooted is refused, as it is with every plugin present: the loaded aggregate names the Spaces it holds (`heldSpaceIds`), and `decideCommit` refuses a held Space the baseline neither held nor already refused (`packages/persistence/test/commit-decision.test.ts`). That rule is one pure function in `@project/graph`, `refusedUnrootedSpaceIds`: given the Spaces already held and, after a change, the Spaces nothing refers to and the Spaces' Resources, it answers the unrooted Spaces that are refused — all of them once no Resource of a missing kind remains, and otherwise those not already held (`packages/graph/test/space-aggregate.test.ts`). Space Authoring calls the same function (decision 14). Refusing on restore was not done, because it would leave an accepted store that no longer opens. Instead, if a commit deletes the last such Resource while a Space is held only by the rule, the commit is refused at that point, naming the Space: the baseline is held and the candidate is not. If another missing-kind Resource remains, the delete is accepted, and deleting the last is then refused (`test/unit/missing-plugin-round-trip.test.ts`). ADR 0142's text says the same.
8. "A plugin that returns" and "a build that gains the plugin" are simulated by relabelling: the plugin list is fixed at build time, so the repository contract stores a Resource under a kind id no plugin names, carrying content the Image plugin reads, and the plugin's return is that id becoming `image`. "hands a Resource whose plugin is missing to that plugin when it returns" reads it through the Image plugin from the store with no Export or Import, and from an Export into an empty directory once the source is gone, with an asset that is not valid UTF-8 byte-identical, on memory, SQLite and PostgreSQL. "carries a Resource whose plugin is missing through Import and Export byte-identical" holds the files byte-identical.
9. `resource.schema.json` now uses an `if` that lists the built-in kind ids, and applies `builtInKinds` only to them. Any other kind's `content` is an object. Adding a bundled kind means adding its id to that list.
10. The round-trip tests use `application/pdf` assets, a type the host table lists. Under issue 03's naming rule a type the table does not list is written as `.bin` and reads back as `application/octet-stream`, so only a listed type's name and media type survive the round trip.
11. Export writes a missing kind's `content`, and the `content` of that Resource's Map entries, in one canonical form: keys sorted by code unit at every depth, except that JavaScript lists integer-like keys first (`canonicalJsonValue` in `packages/core/src/json-value.ts`). It is applied in `canonicalResource` and in `write-space-directory.ts`. Without it, PostgreSQL's `jsonb` hands keys back in its own order and an Export rewrites untouched files. On PostgreSQL the contract case fails without this change and passes with it. A present plugin's content and Map content keep their order, as before (`test/unit/space-directory-files.test.ts`).
12. The Dock's Resources and Connect lists show every missing kind under one `unavailable` toggle, "Resources of a kind not in this build". The toggle is drawn only while the Space holds such a Resource, so it is not a permanent zero.
13. Issue 08's creation host refuses a `from: 'resource'` creation whose Reference Target has a missing kind. The refusal comes from `createInMap`, and its notice uses the rail's sentence, "“<kind>” is not available in this build, so it cannot be referenced." (`describeAuthoringRefusalIn` in `packages/app/src/authoring-refusal.ts`, which now also holds `referenceTerminal`). The default plugin offers no creation, so `pluginCreations` never lists it.
14. Space Authoring refuses deleting the last Resource of a missing kind in its Space while the aggregate holds a Space only because a plugin is missing, as `missing-plugin-holds-space`, whose sentence names the kind. Without it the store's refusal (decision 7) arrived after the working state had dropped the Resource, and every later commit of that Space was refused behind it. It asks the store's own question, `refusedUnrootedSpaceIds` (decision 7), of the deletion: the Spaces held stay unrooted, and the Resources that remain are its Space's. Space Authoring reads one Space and commits synchronously, and the browser has the other Spaces' current Resources only for the Spaces it has opened, so another Space's Resource of a missing kind is not counted; that refuses a deletion the store would accept, never the reverse. Feeding it the whole current aggregate would need an aggregate read before each such deletion, which this issue does not build. Which Spaces are held is read from the aggregate loaded at opening (`heldSpaceIds` in `packages/app/src/space.ts`), through intake only when some Resource has a missing kind. Because decision 7 refuses a commit that newly leaves a Space unrooted, no Space is held later that was not held then. The e2e serves an imported directory holding such a Space, since no commit can make one (`packages/app/e2e/default-plugin.spec.ts`).
15. A number in a missing kind's `content` or Map content is carried as the JSON value it parses to, so its spelling is not kept: `1.0` is written back as `1`, and an integer beyond 2^53 loses precision. Keeping the spelling would need a raw JSON carrier through every store and the wire, which this issue does not build.
