# Prior art: application hosts with typed extensions

**A pre-ADR assessment.** Written on 2026-11-10 against the draft design, before ADR 0142 was accepted, and kept as written. Where it disagrees with the design it read, the ADR and [`spec.md`](spec.md) record what was decided: a missing plugin's Resource is drawn by the default plugin rather than refused, each Resource has its own failure boundary, the spec settles ties among plugins (exact beats wildcard, then build order), and `ResourceFrame` is not part of the API.

Read on 2026-11-10: JupyterLab `v4.6.6`, Lumino `main@44aea97`, VS Code `1.145.2`, vscode-docs `main@2558307`, Grafana `v13.3.0`, plugin-tools `main@263b63c`, Scenes `v9.2.2`, Backstage `v1.56.4`. Theia was skipped. "Inference" marks my reasoning; no source states it.

## Bottom line

Build-time compilation and an exact `kind` key remove the two hardest problems here: runtime dependency sharing and ranking. Absent-capability authoring has direct support in VS Code. Three decisions are the outliers: refusal of stored content (no host here refuses it), no unstable channel (three of four hosts keep one), and no per-Resource failure boundary. The design also records no plugin version beside stored content, which is the one input Grafana's migrations depend on.

## Findings

**1. Same API?** Backstage: yes. [Catalog](https://github.com/backstage/backstage/blob/v1.56.4/plugins/catalog/src/alpha/plugin.tsx) uses public `createFrontendPlugin`. JupyterLab: largely. Extensions ["provide nearly every function"](https://github.com/jupyterlab/jupyterlab/blob/v4.6.6/docs/source/extension/extension_dev.md), and [PDF](https://github.com/jupyterlab/jupyterlab/blob/v4.6.6/packages/pdf-extension/src/index.ts#L138) is an ordinary `IExtension`. The cost is surface: a token ["wrongfully made public"](https://github.com/jupyterlab/jupyterlab/blob/v4.6.6/docs/source/extension/extension_migration.md) waits until 5.0 for removal. VS Code: same contributions ([Markdown preview](https://github.com/microsoft/vscode/blob/1.145.2/extensions/markdown-language-features/package.json#L1949) is a `customEditors` entry), but [built-ins alone keep proposed APIs](https://github.com/microsoft/vscode/blob/1.145.2/src/vs/workbench/services/extensions/common/extensionsProposedApi.ts) unless allowlisted or in development. [Git](https://github.com/microsoft/vscode/blob/1.145.2/extensions/git/package.json#L12) uses them. Grafana: no. [AnnoList](https://github.com/grafana/grafana/blob/v13.3.0/public/app/plugins/panel/annolist/AnnoListPanel.tsx) imports `app/*` and [`@grafana/ui/internal`](https://github.com/grafana/grafana/blob/v13.3.0/packages/README.md). No source quantifies what a private door cost.

**2. Build versus runtime.** JupyterLab moved to prebuilt in 3.0 because rebuilding [needs Node and memory, and multi-user users cannot rebuild](https://github.com/jupyterlab/jupyterlab/blob/v4.6.6/docs/source/extension/extension_dev.md#L68-L73). Source extensions are now deprecated. The cost is federation: deduplication is "more nuanced", and authors configure `singleton` shared packages. Grafana [links `@grafana/*` to the host's version at runtime](https://github.com/grafana/plugin-tools/blob/263b63c0667cb66cd23d1e45983f744a94aa69b2/docusaurus/docs/key-concepts/manage-npm-dependencies.md). Backstage offers [federation](https://github.com/backstage/backstage/blob/v1.56.4/docs/frontend-system/building-apps/07-module-federation.md) as an opt-in; I found no stated reason.

**3. Versioning.** VS Code [requires `engines.vscode` and rejects a mismatch, exempting built-in and declarative extensions](https://github.com/microsoft/vscode/blob/1.145.2/src/vs/platform/extensions/common/extensionValidator.ts#L333-L341). Grafana [requires `grafanaDependency`](https://github.com/grafana/grafana/blob/v13.3.0/docs/sources/developers/plugins/plugin.schema.json#L177) and [enforces it at install](https://github.com/grafana/grafana/blob/v13.3.0/pkg/plugins/repo/version.go); my code search found no load-time check. JupyterLab [marks incompatible extensions](https://github.com/jupyterlab/jupyterlab/blob/v4.6.6/jupyterlab/commands.py#L1659-L1672) and warns they ["may break"](https://github.com/jupyterlab/jupyterlab/blob/v4.6.6/docs/source/extension/extension_dev.md#L76-L82).

Breakage often comes from outside the typed API: [React 19 in Grafana 13](https://github.com/grafana/plugin-tools/blob/263b63c0667cb66cd23d1e45983f744a94aa69b2/docusaurus/docs/migration-guides/update-from-grafana-versions/v12.x-v13.x.md), and [CSS classes and theme variables in JupyterLab](https://github.com/jupyterlab/jupyterlab/blob/v4.6.6/docs/source/extension/extension_migration.md).

Tiers: VS Code's [proposed API exists because shipped API "cannot easily change"](https://github.com/microsoft/vscode-docs/blob/2558307808dfcdac2a566e14079578b18a56249f/api/advanced-topics/using-proposed-api.md#L12-L14), and it is gated in code. Labels alone promise less: Grafana's stable packages are ["considered ALPHA until further notice"](https://github.com/grafana/grafana/blob/v13.3.0/packages/README.md). Backstage has [`@alpha`/`@beta`/`@public`](https://github.com/backstage/backstage/blob/v1.56.4/docs/overview/versioning-policy.md#L145-L159), yet `frontend-plugin-api` is [0.18.2](https://github.com/backstage/backstage/blob/v1.56.4/packages/frontend-plugin-api/package.json), three years after [its first commit](https://github.com/backstage/backstage/commit/c795a3ae0a3ad3f2cb6de6ae4c0f8556e971f377), and plugins are [told to export under `/alpha`](https://github.com/backstage/backstage/blob/v1.56.4/docs/frontend-system/index.md).

**4. Data versus code.** VS Code's manifest holds [`viewType`, `selector`, `priority`](https://github.com/microsoft/vscode-docs/blob/2558307808dfcdac2a566e14079578b18a56249f/api/references/contribution-points.md#L654-L660) and [`when` on menus](https://github.com/microsoft/vscode-docs/blob/2558307808dfcdac2a566e14079578b18a56249f/api/references/when-clause-contexts.md). The stated motive is [lazy loading](https://github.com/microsoft/vscode-docs/blob/2558307808dfcdac2a566e14079578b18a56249f/api/advanced-topics/extension-host.md#L58-L66), and [since 1.74 contributions imply activation](https://github.com/microsoft/vscode-docs/blob/2558307808dfcdac2a566e14079578b18a56249f/api/references/activation-events.md#L204). Backstage extensions declare [`attachTo`, inputs, output and config schema around one `factory`](https://github.com/backstage/backstage/blob/v1.56.4/docs/frontend-system/architecture/20-extensions.md), so integrators can reattach by configuration. Grafana keeps identity in `plugin.json` and [option editors in code](https://github.com/grafana/grafana/blob/v13.3.0/packages/grafana-data/src/panel/PanelPlugin.ts#L386).

**5. Missing plugin.** None refuses stored content. VS Code [resolves an untyped open to the default editor](https://github.com/microsoft/vscode/blob/1.145.2/src/vs/workbench/services/editor/browser/editorResolverService.ts#L183-L194). JupyterLab's [file editor claims `*`](https://github.com/jupyterlab/jupyterlab/blob/v4.6.6/packages/fileeditor-extension/src/index.ts#L154), and an output with no renderer [becomes an empty widget](https://github.com/jupyterlab/jupyterlab/blob/v4.6.6/packages/outputarea/src/widget.ts#L686-L691). Grafana draws ["Panel plugin not found"](https://github.com/grafana/grafana/blob/v13.3.0/public/app/features/panel/components/PanelPluginError.tsx) in that panel. Its placeholder has no version, so Scenes [records the Grafana build version as `pluginVersion`](https://github.com/grafana/scenes/blob/v9.2.2/packages/scenes/src/components/VizPanel/VizPanel.tsx#L354-L394). Inference, save path untraced: saving then could misdirect a later version-branching migration. Backstage refuses only wiring: a [non-warning error](https://github.com/backstage/backstage/blob/v1.56.4/packages/frontend-defaults/src/maybeCreateErrorPage.tsx) yields an app error page.

**6. Migration.** Only Grafana has it: the host triggers, the plugin authors. [`setMigrationHandler`](https://github.com/grafana/grafana/blob/v13.3.0/packages/grafana-data/src/panel/PanelPlugin.ts#L313) runs [when stored and installed versions differ](https://github.com/grafana/grafana/blob/v13.3.0/public/app/features/dashboard/state/PanelModel.ts#L422-L426). Results [are not persisted until the user saves](https://github.com/grafana/plugin-tools/blob/263b63c0667cb66cd23d1e45983f744a94aa69b2/docusaurus/docs/how-to-guides/panel-plugins/options-migration-handler.md#L43), and handlers branch on version strings. No source reports its cost. I found no equivalent in `IRenderMime` or `CustomDocument`.

**7. Capabilities.** VS Code derives [`editable` from the provider's shape](https://github.com/microsoft/vscode/blob/1.145.2/src/vs/workbench/api/common/extHostCustomEditors.ts#L263), and [the main thread throws on edits otherwise](https://github.com/microsoft/vscode/blob/1.145.2/src/vs/workbench/api/browser/mainThreadCustomEditors.ts#L733-L747). That covers the author's choice only. A text custom editor gets no read-only property on `TextDocument`, only [`applyEdit`'s boolean](https://github.com/microsoft/vscode/blob/1.145.2/src/vscode-dts/vscode.d.ts#L14376) and scheme-level [`isWritableFileSystem`](https://github.com/microsoft/vscode/blob/1.145.2/src/vscode-dts/vscode.d.ts#L9879).

Grafana passes [one large `PanelProps`](https://github.com/grafana/grafana/blob/v13.3.0/packages/grafana-data/src/types/panel.ts) with a mandatory `onOptionsChange`, plus [`PanelContext`](https://github.com/grafana/grafana/blob/v13.3.0/packages/grafana-ui/src/components/PanelChrome/PanelContext.ts) with `app`, "what the outer container is". [LogsPanel](https://github.com/grafana/grafana/blob/v13.3.0/public/app/plugins/panel/logs/LogsPanel.tsx#L235-L237) branches on that list, the failure ADR 0142 predicts. JupyterLab uses tokens, gives renderers [nullable services](https://github.com/jupyterlab/jupyterlab/blob/v4.6.6/packages/rendermime-interfaces/src/index.ts#L357-L389), and draws the same renderer in outputs and documents without telling it which. Backstage injects [`{node, apis, config, inputs}`](https://github.com/backstage/backstage/blob/v1.56.4/packages/frontend-plugin-api/src/wiring/createExtension.ts#L183-L191).

**8. Failure.** VS Code uses a [separate host process](https://github.com/microsoft/vscode-docs/blob/2558307808dfcdac2a566e14079578b18a56249f/api/advanced-topics/extension-host.md#L58-L66) and [iframe webviews](https://github.com/microsoft/vscode-docs/blob/2558307808dfcdac2a566e14079578b18a56249f/api/extension-guides/webview.md). The cost: hidden webviews lose content, [`retainContextWhenHidden` is memory-heavy](https://github.com/microsoft/vscode/blob/1.145.2/src/vscode-dts/vscode.d.ts#L10077), and [save should not depend on the webview](https://github.com/microsoft/vscode-docs/blob/2558307808dfcdac2a566e14079578b18a56249f/api/extension-guides/custom-editors.md#L294). In-page hosts contain per unit: Scenes' [`ErrorBoundaryAlert`](https://github.com/grafana/scenes/blob/v9.2.2/packages/scenes/src/components/VizPanel/VizPanelRenderer.tsx#L327), Backstage's [`ExtensionBoundary`](https://github.com/backstage/backstage/blob/v1.56.4/packages/frontend-plugin-api/src/components/ExtensionBoundary.tsx#L126), JupyterLab's [render rejection caught in place](https://github.com/jupyterlab/jupyterlab/blob/v4.6.6/packages/outputarea/src/widget.ts#L760-L772) and [Lumino's activation catch](https://github.com/jupyterlab/lumino/blob/44aea979d5d2c77665d651383d27179a63596957/packages/coreutils/src/plugins.ts#L355). Grafana's [same-thread sandbox](https://github.com/grafana/grafana/blob/v13.3.0/public/app/features/plugins/sandbox/README.md) [excludes Grafana-signed and internal plugins](https://github.com/grafana/grafana/blob/v13.3.0/public/app/features/plugins/sandbox/sandboxPluginLoaderRegistry.ts#L53).

**9. Harness.** Backstage is closest to our need, in-process: [`createExtensionTester`, `renderInTestApp`, `mockApis`](https://github.com/backstage/backstage/blob/v1.56.4/docs/frontend-system/building-plugins/02-testing.md). VS Code runs [Mocha in a real Extension Development Host](https://github.com/microsoft/vscode-docs/blob/2558307808dfcdac2a566e14079578b18a56249f/api/working-with-extensions/testing-extension.md). Grafana's [`plugin-e2e`](https://github.com/grafana/plugin-tools/blob/263b63c0667cb66cd23d1e45983f744a94aa69b2/docusaurus/docs/e2e-test-a-plugin/index.md) and JupyterLab's [Galata](https://github.com/jupyterlab/jupyterlab/blob/v4.6.6/galata/README.md) are Playwright fixtures; Grafana's guarantees its API across versions.

**10. Matching.** JupyterLab has [numeric rank, lower wins, default 100](https://github.com/jupyterlab/jupyterlab/blob/v4.6.6/packages/rendermime/src/registry.ts#L237-L255), filtered by `safe` for untrusted data, and an [ordered factory ladder ending in registration order](https://github.com/jupyterlab/jupyterlab/blob/v4.6.6/packages/docregistry/src/registry.ts#L369-L420). VS Code has [`default`/`option`/`explicit`](https://github.com/microsoft/vscode/blob/1.145.2/src/vs/workbench/contrib/customEditor/common/extensionPoint.ts#L30-L40), user associations, and a [conflicting-defaults prompt](https://github.com/microsoft/vscode/blob/1.145.2/src/vs/workbench/services/editor/browser/editorResolverService.ts#L221-L223). Grafana's panel id and [Backstage's extension id](https://github.com/backstage/backstage/blob/v1.56.4/docs/frontend-system/architecture/20-extensions.md#L18) are exact, like `kind`.

**11. Save and drafts.** [`CustomTextEditor`](https://github.com/microsoft/vscode-docs/blob/2558307808dfcdac2a566e14079578b18a56249f/api/extension-guides/custom-editors.md#L48) leaves save, backup and undo to the host's `TextDocument`. `CustomEditor` makes the extension [implement save and backup and fire undo/redo closures](https://github.com/microsoft/vscode-docs/blob/2558307808dfcdac2a566e14079578b18a56249f/api/extension-guides/custom-editors.md#L229-L258) onto the host stack. Reported friction: [an author "had to throw the towel"](https://github.com/microsoft/vscode/issues/93963), and [no way to clear dirty after an in-iframe save](https://github.com/microsoft/vscode/issues/97348). JupyterLab renderers [write through `setData`](https://github.com/jupyterlab/jupyterlab/blob/v4.6.6/packages/docregistry/src/mimedocument.ts#L181-L196) to a host-saved model.

## Where this family disagrees with our design

- **Refusal is the outlier.** ADR 0120 rejects Jupyter's fallback knowingly, but Grafana's placeholder is the sharper counter: one panel fails, its neighbours draw. Build-time listing justifies refusal for bundled kinds; an external plugin dropped from a build makes a whole Aggregate unopenable.
- **No tiers has no precedent among growing APIs here.** JupyterLab is the exception, and it pays in major-version break lists. Building Space last, on an API already public, is exactly what VS Code's proposal tier protects against. A workspace-only API change is atomic for bundled plugins and silently breaking for external ones.
- **A build-time `apiVersion` checks a number, not the contract.** The breakage above came through React and CSS. `Embed`, the Title component and `ResourceFrame` make DOM and styling API.
- **Plugin-owned old content lacks an input.** Nothing stores which plugin version wrote content, so a schema must infer format from shape. Grafana's handlers branch on exactly that value.
- **No boundary is specified.** ADR 0142 and the spec name none; one throw could take a canvas drawn from many plugins.
- **Commands exist only after render.** VS Code's menu data works before code loads. `<Rail commands>` cannot serve an unmounted Resource, and it carries no key bindings or `when` equivalent.
- **Drafts have no host recovery.** Remount discards them. VS Code requires backup hooks for this case, and an external plugin gets no signal to join host Undo.
- **Ties are unspecified.** ADR 0120 selects by media type with wildcards on drop. Two plugins accepting `image/*` need a rank or a prompt.

## Worth copying

- VS Code's enforcement behind absence: `Kept.commit` absent, plus a host that refuses a commit from a withdrawn surface.
- A per-Resource error boundary, and Grafana's in-place "kind not available" as the render for anything intake ever admits.
- Backstage's [consumer/producer stability split](https://github.com/backstage/backstage/blob/v1.56.4/docs/overview/versioning-policy.md#L126-L140), adapted: state what plugins may rely on separately from what the host may add.
- A `createExtensionTester` equivalent: a fake surface toggling each capability.
- Grafana's stored version beside content, if external plugins become real.
