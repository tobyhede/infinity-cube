**Terms** (definitions are in `CONTEXT.md`):
- **Toolbar**: a selected Resource's commands, floated beside it. Code calls it the rail. The host draws it; the commands in its kind group are the Resource plugin's (UI-13).
- **Command Dock**: the Space's one command surface, floating over the canvas.
- **Surface**: the control conducting an interaction (a Title field, an Open Markdown body, a menu, a list). It decides commit and Escape.
- **Absent**: a command not drawn at all (UI-28).
- **Unavailable**: a command drawn in place, focusable and marked `aria-disabled`, which refuses to run (UI-29). It is not a refusal: nothing was attempted.
- **Editing**: a running Title, or work a Resource plugin holds a Claim for (a Markdown body, a drawn Map's Edit, an image replacement). It ends in an Edit or in nothing.
- **Canvas command**: one named action on the canvas, reached by a key, a toolbar or menu item, or both (UI-102).
- **Full View**: reading one Resource on the Stage over the canvas, without presenting (UI-105).
- **Notice**: a standing report in the one notice area at the top end of the canvas (UI-94), worded by UI-89, dismissible, and cleared by the next press of the command it reports.
- **Continue at**: where the caret and selection land after an Edit completes.

**Status:** **built** means code and a named test match the rule. **built (untested)** means code matches and no test covers it. **not built** means the rule is decided and no code implements it. **bug: code differs** means the code does what the note says instead. **undecided (`conflicts/<doc>.md` Cn)** means the rule waits on that conflict (this doc's when no doc is named); the note says what the code does meanwhile. A test is named as `file` › "test name". Paths that start with `test/` are at the repo root; all others are under `packages/`.

## Foundation

- **UI-1** Where shadcn ships a component for a surface, the product builds on it and its headless primitive and keeps that primitive's keyboard, focus, dismissal and accessibility defaults. A hand-rolled component or stylesheet block is a deviation, recorded with its reason before it ships. *Why:* a local reason for a hand-roll always reads well and is rarely tested against the primitive. **built**: `test/unit/ui-catalog.test.ts` › "reports a production component no stable story renders", "requires a recorded reason for every block the stylesheet declares".
- **UI-2** Base UI is the one primitive layer (shadcn `base-nova`). No Radix wrapper is used. *Why:* two primitive families mean two focus and dismissal models in one pane. **built (untested)**: `ui/components.json`; no `@radix-ui` import in any `packages/*/src` or manifest.
- **UI-3** Lucide is the default icon set. A custom icon is drawn only where no Lucide glyph says an InfinityCube-specific meaning, and that meaning is named. *Why:* one maintained vocabulary, not a component-by-component choice. **built**: `ui/test/icons.test.tsx` › "uses Lucide for every general-purpose interface glyph".
- **UI-4** The application and the React Flow adapter reach Base UI, cmdk, Lucide and the Markdown editor only through `@project/ui`'s root. *Why:* one package owns the UI foundation. **built**: `test/unit/ui-import-restrictions.test.ts` › "rejects %s from app composition", "rejects %s from the React Flow adapter".
- **UI-5** `@project/ui` names no React Flow type. The toolbar reaches React Flow through a seam the adapter fills. *Why:* reusable UI stays free of the canvas library. **built (untested)**: `eslint.config.js` `no-restricted-imports`; `ui/src/PluginResource.tsx` `renderToolbar`, filled by `react-flow-adapter/src/ResourceNode.tsx`.
- **UI-6** The Command Dock and every canvas toolbar wear one shared command surface, and the Dock and an Open Space Resource draw one shared Map and Graph choice. *Why:* one surface drawn twice cannot drift into two. **built**: `test/unit/command-surface-sharing.test.ts` › "is mounted by both the Command Dock and the canvas command toolbar", "is the same shared menu on the Dock and on a Space Resource".

## Keys

- **UI-7** Every application shortcut is declared once, with its keys, its `aria-keyshortcuts` and a description, and everything that answers, announces or lists a key reads it from that declaration by the command's id. *Why:* one table is the only place a binding can be checked against the others. **built**: `test/unit/key-bindings.test.ts` › "names every live binding once and no binding that has disappeared"; `app/test/key-bindings.test.tsx` › "announces a non-empty shortcut and description for every binding"; `app/test/command-ids.test.tsx` › "gives each command its own binding".
- **UI-8** No binding answers under Ctrl, Meta or Alt, and a plain binding takes no Shift. *Why:* modified keys belong to the browser and the system. **built**: `app/test/key-bindings.test.tsx` › "tells a Shift binding from the plain one on the same key"; `app/test/SpaceCanvas.test.tsx` › "ignores a modified press and a key repeat".
- **UI-9** A key belongs to the focused control in these cases:

  | Focused control | Keys it keeps |
  |---|---|
  | text entry, select, combobox, editable region, menu, listbox, dialog | every key |
  | any other focusable control | the Space and Enter that activate it |
  | range, slider, spin button | arrows, Home, End, PageUp, PageDown |

  Every other key goes to the shortcut table, wherever focus is, the Dock included. *Why:* a shortcut must still work after a click on chrome. **built**: `app/test/key-bindings.test.tsx` › "leaves a focused button its own Space and Enter and nothing else", "answers a key inside the Command Dock, which is marked for React Flow alone", "keeps every key in an editable region switched on, not one switched off"; `app/e2e/keyboard-shortcuts.spec.ts` › "C adds a Resource while a Dock control has focus".
- **UI-10** The canvas keys are:

  | Key | Does | Effect owned by |
  |---|---|---|
  | `C` | adds a Resource of the first kind in the build's plugin list whose Resources start empty (Markdown) | space-and-resources.md |
  | Space | reads the focused Resource in Full View (UI-105) | — |
  | `F2` | renames the selected Resource (UI-46) | — |
  | arrows | Graph navigation | navigation.md (NV-13) |
  | Shift + arrow | moves the selected Resource | maps-and-graphs.md (Move) |
  | `P` | presents from the selected Resource | navigation.md |
  | Escape | unselects | navigation.md |
  | Delete, Backspace | removes the focused Resource from this Map (pressed on the pane, the selected Resources), or asks to delete the selected Edge | maps-and-graphs.md |
  | `?` | shows the keyboard shortcuts (UI-104) | — |

  No key opens a Resource, and Enter is bound to nothing on the canvas: every Open is a plugin's own command on its toolbar (UI-53). Space, Delete and Backspace act only when aimed at the canvas or a Resource, one press per Edit; a region inside a Resource that keeps its keys keeps them. *Why:* removing from a Map cannot be taken back, so a key meant for chrome must not reach the canvas. **built**: `app/test/SpaceCanvas.test.tsx` › "shows the focused Resource on Space, without Opening it", "leaves %s to a `.nokey` region inside a Resource", "leaves %s (shift %s) alone on a Markdown Resource"; `app/test/shortcut-sheet.test.ts` › "lists no Enter on the canvas, which opens no Resource"; `app/test/canvas-commands.test.tsx` › "removes the Resources selected together with the one it is aimed at", "leaves Space to a Resource’s own content and controls, and takes it from the Resource"; `app/test/edge-authoring-react.test.tsx` › "leaves the selected Resource standing when %s is aimed outside the canvas", "ignores an auto-repeated Backspace so one press removes one Resource", "removes the focused Resource rather than the selected one on %s"; `app/e2e/keyboard-shortcuts.spec.ts` › "the arrow keys follow the Active Graph, and Shift and an arrow move the Resource", "P and Present from Here present from the selected Resource"; `app/e2e/react-flow-integration.spec.ts` › "a focused Markdown Resource Opens from its rail and not on Enter, and Space reads it in Full View".
- **UI-102** A canvas key and the toolbar or menu item for the same action perform one Canvas command, named by a stable id. The command says what it is aimed at (the focused Resource, the selection, or the Map), which drawn Maps it serves, and whether it can run for a target: available; unavailable with a reason, which the item shows greyed with that sentence; or absent, which offers no item. Its key takes a press, and prevents the press's default, only while the command is available for the target the press resolves to; otherwise the key stays silent and the press is left to the browser or another control. The key and the item run through the same path, so a refusal is reported the same way from either. *Why:* two ways to reach one action must not disagree about when it runs or how it reports. **built**: `app/test/canvas-commands.test.tsx` › "is available on the Active Graph while presenting may start, and presents from it", "is unavailable off the Active Graph, saying so before any edit in progress", "is absent where nothing presents from the canvas", "runs the command at its target only while it is available"; `app/test/SpaceApp.test.tsx` › "offers the item and answers the key on the Active Graph", "greys the item with the reason off the Active Graph, and leaves the key alone", "greys the item with the reason while an edit is in progress, and leaves the key alone"; `app/test/key-dispatcher.test.tsx` › "prevents the default of a press only when an answer takes it".
- **UI-103** Each Space answers keys through one dispatcher, and no command listens for a key itself. A surface that covers the Space (presenting, Full View, a Space that is not on screen) decides which commands answer, so a command does not test for it. *Why:* every listener that repeats the guard and the context test is one that can forget them. **built**: `app/test/SpaceApp.test.tsx` › "adds no window key listener but the dispatcher’s, authoring and presenting", "is answered by the Space on screen and not by a hidden one"; `app/test/key-dispatcher.test.tsx` › "takes the most covering context, and returns to the canvas when the last cover lifts".
- **UI-104** `?` opens the keyboard shortcuts sheet from the canvas, from Full View and while presenting. The sheet lists the keys of the mode the reader is in, each with its `aria-keyshortcuts`, read from the binding declarations (UI-7), so it cannot list a key nothing answers; Escape closes the sheet alone. An actions-menu command with a key shows the key at the item's end, kept out of its name and announced with `aria-keyshortcuts`, and the Dock's Create for the default kind names `C` in its tooltip, except while that Create is unavailable. *Why:* a key nobody can discover is not a way to do anything. **built**: `app/test/SpaceApp.test.tsx` › "opens the shortcut sheet with ? from the canvas, from Full View and while presenting"; `app/test/shortcut-sheet.test.ts` › "lists every canvas and Full View key while authoring, and the sheet’s own", "lists every presenting key while presenting, and the sheet’s own", "announces the binding’s own aria-keyshortcuts"; `app/e2e/keyboard-shortcuts.spec.ts` › "? shows the sheet from inside Full View, and Escape closes only the sheet"; `app/test/dock-commands.test.tsx` › "teaches no C on a Create button it draws unavailable". The menu items' keys are untested (`app/src/resource-rail-actions.tsx`).

## Full View

- **UI-105** Space on a focused Resource of the canvas's own Map, or Read in Full View in its actions menu, reads that Resource in Full View: its plugin draws it read-only on the presenting Stage over the canvas, with the Command Dock still above it. Full View writes nothing, adds no history entry and leaves the camera alone. It ends when its Resource leaves the canvas or the canvas stops taking selection. A Map drawn inside a Space Resource offers no Full View. *Why:* an author can read one Resource at full size without presenting a Graph. **built**: `app/test/SpaceCanvas.test.tsx` › "shows the focused Resource on Space, without Opening it", "ends when the canvas surface is held"; `app/test/canvas-commands.test.tsx` › "reads in Full View on the canvas’s own Map, at its Resource", "offers no Full View where the canvas cannot be selected on or draws none"; `app/e2e/keyboard-shortcuts.spec.ts` › "Space reads a Resource in Full View, walks the Active Graph and leaves". That it writes nothing and adds no history entry is untested.
- **UI-106** In Full View the arrows go along the Active Graph with the canvas's Graph navigation (NV-13), reading each Resource reached; Space and Escape leave, back to the Resource last read; Enter does nothing; Tab stays the browser's. Full View is modal over its Map: a key pressed in it stops there, the covered canvas is inert, and `C`, `F2` and `P` do nothing. `?` still opens the sheet (UI-104). *Why:* focus must not reach a Map the reader cannot see, and no canvas command may run on it. **built**: `app/test/SpaceCanvas.test.tsx` › "leaves on %s, back to the Resource", "stays on Enter, Opening nothing", "keeps a canvas command from running on the Map it covers", "is modal: the covered canvas is inert, and its window keys leave it alone"; `app/e2e/keyboard-shortcuts.spec.ts` › "Space reads a Resource in Full View, walks the Active Graph and leaves".

## Selecting by click

- **UI-11** A single click on a Resource selects it, including the body of an Open Markdown Resource. No pointer gesture on a Resource's body Opens it: Open is a command. Double-click zoom is RD-66. *Why:* the Title control and a body gesture would want the same pixels. **built**: `app/e2e/editing.spec.ts` › "a click selects a Resource, and no pointer gesture on its body opens it"; `app/test/SpaceCanvas.test.tsx` › "does not happen on %s of the Resource body".

## Resource toolbar

- **UI-12** A Resource's commands are one `role="toolbar"` named for the Resource. It is one tab stop, and the arrows move between its commands. *Why:* a dozen Resources would otherwise cost dozens of tab stops. **built**: `ui/test/resource-rail-toolbar.test.tsx` › "names the Resource it commands, so its controls are heard as that Resource's", "costs one tab stop however many commands it carries", "moves between its commands on the arrow keys"; `app/ladle-e2e/resource-open.spec.ts` › "the rail is one toolbar: one tab stop, and its commands under the arrows".
- **UI-13** The toolbar is the host's and the commands in its kind group are the plugin's. The actions menu comes first; then, while the Resource embeds a Map it may choose for, that embedding's Map and Graph choices, which are the host's; then the plugin's own commands in one group named for its kind (`<Kind> commands`), with Open and Close among them and last. An empty group draws nothing, and the arrows cross groups. *Why:* whose command it is lives in the markup, not the look, and a plugin owns its own commands. **built**: `ui/test/resource-rail-toolbar.test.tsx` › "puts the plugin's own commands in its kind's group, Open and Close among them", "draws the Map embedding's commands outside the plugin's group, before it", "groups the commands without dividing the keyboard"; `ui/test/PluginResource.test.tsx` › "draws the plugin's rail commands on the Resource's rail, and runs them"; `app/e2e/resource-rail-hover.spec.ts` › "a Resource at rest draws no toolbar; selected, its commands end with Open, and its kind glyph stays at its top-right corner".
- **UI-14** A key pressed in a canvas toolbar never reaches the canvas, and a press on a command never starts a pan or drag. *Why:* the toolbar sits over the canvas. **built**: `ui/test/resource-rail-toolbar.test.tsx` › "keeps an arrow pressed on the rail off the canvas behind it"; `ui/test/CanvasCommandToolbar.test.tsx` › "keeps a press off React Flow's pan and drag".
- **UI-15** The toolbar floats above the Resource's top-right corner, outside the zoom, at the same size at every zoom. *Why:* a command's size must not depend on zoom, and inside the Resource it collides with the top anchor. **built**: `app/e2e/resource-rail-hover.spec.ts` › "the toolbar floats above its Resource’s top-right corner at a constant size".
- **UI-16** The toolbar is drawn for the one selected Resource (none while several are selected) and for a Resource whose plugin holds a Claim (a Markdown edit, a drawn Map's Edit, an image replacement), selected or not. It is hidden while the Resource is dragged or resized, and hovering reveals nothing. Open and Close keep the Resource selected and its toolbar drawn. *Why:* the exits of running work must stay reachable; a gesture owns the pointer while it lasts. **built**: `react-flow-adapter/test/ResourceNode.test.tsx` › "draws none on a Resource at rest", "draws none while several Resources are selected", "keeps the exits of a running edit, and returns focus to the Resource when it ends, although the Resource is no longer selected", "draws none while the Resource is dragged", "draws none while the Resource is resized"; `app/e2e/resource-rail-hover.spec.ts` › "hovering a Resource reveals its Edge handles and no commands; selecting it draws them in React Flow's NodeToolbar", "Open and Close keep the Resource selected and its toolbar drawn, by pointer or keyboard"; `app/ladle-e2e/resource-open.spec.ts` › "an Open Resource running an edit keeps its commands drawn, however it is left".
- **UI-109** While Claims nest, the deepest one holds the keys and shows its commands. Its Resource's toolbar is drawn (UI-16) and a canvas key acts in the drawing that Claim is inside: `C` while a drawn Map's Edit runs creates in that Map's Space and continues naming there, not on the canvas. A Resource holding an outer Claim keeps it but withdraws what would end it or change what it shows: Close is not offered, and the Map and Graph chooser of a Space Resource is drawn unavailable. A sibling offers no command that would take a Claim, and the Dock's Present is unavailable while the inner work runs. *Why:* one interaction at a time (editing.md ED-80), and the author must see and reach the exits of the one that runs. **built**: `app/test/space-resource-embedded-map.test.tsx` › "creates by keyboard in the selected drawing and continues naming there", "keeps an embedded draft safe from containing controls and sibling editors"; `app/test/plugin-host.test.ts` › "grants a first Claim to any drawing, and a later one only inside the deepest".
- **UI-17** Where a plugin draws the Resource's Title, the Title is not in the toolbar and keeps its own tab stop. A plugin that draws no Title (an Image Resource, whose Title is its picture's text alternative) offers Rename in its kind group instead, which opens the same Title field over its rect. *Why:* renaming must not be an arrow key away from Close, and a Title nobody can see still needs a way to change it. **built**: `plugin-image/test/image-plugin.test.tsx` › "renames from the rail where the Title commit is present"; `ui/test/PluginResource.test.tsx` › "draws the Title editor over a plugin that draws no Title while it is renamed". That a drawn Title is not in the toolbar is untested (`ui/src/PluginResource.tsx`).
- **UI-18** From a focused, selected Resource, the keyboard reaches that Resource's toolbar next. *Why:* every command must be reachable without a pointer. **not built**: the toolbar is portalled after every Resource, so Tab reaches the next Resource; the right-click menu is the only other reach. Tracked in `.scratch/resource-node-toolbar/issues/01-reach-a-selected-resources-toolbar-from-the-keyboard.md` (repo root). Which key enters it is an open question.
- **UI-19** An Open Reference Resource draws its Target through the host's embedding, under its own Title, and offers Close and its own Title editing; Edit, Save, Cancel, Replace, Shape and any Target, source, Map-choice or Graph-choice control of the Target are absent. A Reference to an Image Resource is renamed from its rail, through its own Title. No surface offers a control that picks or changes a Reference Resource's Target. *Why:* its Target is immutable and shown read-only. **built**: `ui/test/resource-embedding.test.tsx` › "draws its own Title once over a Markdown Target, offering no command of the Target", "draws its own Title once over an Ur Target, offering no Shape of it", "is a picture of an Image Target named by its own Title, renamed from the rail through its own commit"; `plugin-reference/test/reference-plugin.test.tsx` › "passes its own rename with its Title, so a rename inside the embedding renames the Reference"; `app/test/resource-authoring.test.tsx` › "opens each Reference Resource on resolved Target content without a source editor"; `app/test/space-resource-embedded-map.test.tsx` › "draws the Map a Reference to a Space Resource shows, offering no authoring of it". The absence of a Target picker on other surfaces is untested.

## Menus

- **UI-20** The actions menu holds, in groups: Create Reference; Connect to Resource; Read in Full View and Present from Here; for a Space Resource, Enter and Open in New Tab; the copy links; Remove from Map and Delete from Space. A Map drawn inside a Space Resource offers no Read in Full View (UI-105). The copy links are: on a Resource the Map places, Copy link to Resource in Map and Copy link to Resource; on a Resource it does not, Copy link to Resource; on a Space Resource also Copy link to Space; on a Reference Resource also Copy link to Target. - **UI-21** Create Reference is drawn unavailable on a Reference Resource, still leading its group. *Why:* the menu stays the same on every Resource, and the greyed row says that referencing stops here. **built**: `app/e2e/editing.spec.ts` › "Create Reference is drawn unavailable on a Reference Resource, still leading its menu".
- **UI-22** The Map menu holds the Map list, New Map, Rename with Copy link, then Delete. - **UI-25** An Open Space Resource offers the Map and Graph menus against its target Space, Shape… included, on its toolbar before its own commands (UI-13). Their choices list the target Space's Maps and Graphs as read from that Space, its working state where it is open. While the target is unread a plain note stands in for them, and a selection the target no longer holds is drawn unavailable. The target's Map and Graph authoring (New, Rename, Colour…, Shape…, Delete) is offered only while the Space Resource's Edit is running (UI-61); its copy links are offered without it. - **UI-26** An Ur Resource's Shape is a choice on its toolbar. ## Effects across controls

- **Escape** always closes the nearest surface without authoring: it restores a Title (UI-48), abandons a Markdown draft (UI-56), closes a menu or list with focus on its trigger (UI-41, UI-75), answers a Delete question with Cancel (UI-84), and on the canvas unselects (UI-10). Exceptions: it never cancels a completed Edit (see editing.md), never closes a Space (see navigation.md), and is withheld while a deletion runs (UI-84).
- **Unavailable stays reachable** (UI-29). Exception: a command the plugin does not offer is absent (UI-28).
- **Keys pressed in chrome never act on the canvas**: a Delete or arrow pressed in the Dock, a toolbar, a menu, a list or a Title field leaves the canvas selection alone (UI-10, UI-14). **built**: `app/test/edge-authoring-react.test.tsx` › "leaves the Edge standing when %s reaches a Create Resource control"; `app/e2e/mobile-dock.spec.ts` › "Delete on a Dock control leaves the selected Resource on the canvas".
- **Names**: a control, list row or piece of chrome names a Resource by its name, its first Title Line, alone. A sentence that quotes a Title uses the short Title (UI-99). **built**: `ui/test/resource-rail-toolbar.test.tsx` › "names the Resource it commands, so its controls are heard as that Resource's"; `app/test/resource-rail-actions.test.tsx` › "names its own Resource in each menu, drawn for the selected Resource alone".

- **UI-99** Wherever a sentence quotes a Title, it uses the short Title: the first Title Line, plus "…" when more lines follow. This covers questions, notices, and Edge labels and their accessible names. Controls, list rows and chrome use the first line alone (Effects "Names"). *Why:* a part of the Title must never read as the whole of it. **bug: code differs**: three notices quote the bare name: "X could not be entered", "… exited" and "… opened" (`app/src/resource-rail-actions.tsx` `subject: titleName(…)`, `app/src/command-outcomes.ts` `space-enter`, `space-exit`, `space-open`); the `resource-has-references` refusal (`graph/src/snapshot-edits.ts` `referenceTitles`, `app/src/authoring-refusal.ts`); and the drawn-Space failure notice "Title: message" (`app/src/use-embedded-open-space-resources.ts` `failedEmbeddings`).
