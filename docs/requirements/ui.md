**Terms** (definitions are in `CONTEXT.md`):
- **Toolbar**: a selected Resource's commands, floated beside it. Code calls it the rail.
- **Command Dock**: the Space's one command surface, floating over the canvas.
- **Surface**: the control conducting an interaction (a Title field, an Open Markdown body, a menu, a list). It decides commit and Escape.
- **Absent**: a command not drawn at all (UI-28).
- **Unavailable**: a command drawn in place, focusable and marked `aria-disabled`, which refuses to run (UI-29). It is not a refusal: nothing was attempted.
- **Editing**: a running Title, Markdown body or drawn-Map editing session. It ends in an Edit or in nothing.
- **Notice**: a standing report in the one notice area at the top end of the canvas (UI-94), worded by UI-89, dismissible, and cleared by the next press of the command it reports.
- **Continue at**: where the caret and selection land after an Edit completes.

**Status:** **built** means code and a named test match the rule. **built (untested)** means code matches and no test covers it. **not built** means the rule is decided and no code implements it. **bug: code differs** means the code does what the note says instead. **undecided (`conflicts/<doc>.md` Cn)** means the rule waits on that conflict (this doc's when no doc is named); the note says what the code does meanwhile. A test is named as `file` › "test name". Paths that start with `test/` are at the repo root; all others are under `packages/`.

## Foundation

- **UI-1** Where shadcn ships a component for a surface, the product builds on it and its headless primitive and keeps that primitive's keyboard, focus, dismissal and accessibility defaults. A hand-rolled component or stylesheet block is a deviation, recorded with its reason before it ships. *Why:* a local reason for a hand-roll always reads well and is rarely tested against the primitive. **built**: `test/unit/ui-catalog.test.ts` › "reports a production component no stable story renders", "requires a recorded reason for every block the stylesheet declares".
- **UI-2** Base UI is the one primitive layer (shadcn `base-nova`, `neutral` base, CSS-variable theming). No Radix wrapper is used. The palette and spatial look are Hyper's, not the registry's. *Why:* two primitive families mean two focus and dismissal models in one pane. **built (untested)**: `ui/components.json`; no `@radix-ui` import in any `packages/*/src` or manifest.
- **UI-3** Lucide is the default icon set. A custom icon is drawn only where no Lucide glyph says a Hyper-specific meaning, and that meaning is named. *Why:* one maintained vocabulary, not a component-by-component choice. **built**: `ui/test/icons.test.tsx` › "uses Lucide for every general-purpose interface glyph".
- **UI-4** The application and the React Flow adapter reach Base UI, cmdk, Lucide and the Markdown editor only through `@project/ui`'s root. *Why:* one package owns the UI foundation. **built**: `test/unit/ui-import-restrictions.test.ts` › "rejects %s from app composition", "rejects %s from the React Flow adapter".
- **UI-5** `@project/ui` names no React Flow type. The toolbar reaches React Flow through a seam the adapter fills. *Why:* reusable UI stays free of the canvas library. **built (untested)**: `eslint.config.js` `no-restricted-imports`; `ui/src/CanvasResource.tsx` `renderToolbar`.
- **UI-6** The Command Dock and every canvas toolbar wear one shared command surface, and the Dock and an Open Space Resource draw one shared Map and Graph choice. *Why:* one surface drawn twice cannot drift into two. **built**: `test/unit/command-surface-sharing.test.ts` › "is mounted by both the Command Dock and the canvas command toolbar", "is the same shared menu on the Dock and on a Space Resource".

## Keys

- **UI-7** Every application shortcut is declared once, with its keys, its `aria-keyshortcuts` and a description. *Why:* one table is the only place a binding can be checked against the others. **built**: `test/unit/key-bindings.test.ts` › "names every live binding once and no binding that has disappeared"; `app/test/key-bindings.test.tsx` › "announces a non-empty shortcut and description for every binding".
- **UI-8** No binding answers under Ctrl, Meta or Alt, and a plain binding takes no Shift. *Why:* modified keys belong to the browser and the system. **built**: `app/test/key-bindings.test.tsx` › "tells a Shift binding from the plain one on the same key"; `app/test/SpaceCanvas.test.tsx` › "ignores a modified press and a key repeat".
- **UI-9** A key belongs to the focused control in these cases:

  | Focused control | Keys it keeps |
  |---|---|
  | text entry, select, combobox, editable region, menu, listbox, dialog | every key |
  | any other focusable control | the Space and Enter that activate it |
  | range, slider, spin button | arrows, Home, End, PageUp, PageDown |

  Every other key goes to the shortcut table, wherever focus is, the Dock included. *Why:* a shortcut must still work after a click on chrome. **built**: `app/test/key-bindings.test.tsx` › "leaves a focused button its own Space and Enter and nothing else", "answers a key inside the Command Dock, which is marked for React Flow alone", "keeps every key in an editable region switched on, not one switched off"; `app/e2e/keyboard-shortcuts.spec.ts` › "C adds a Resource while a Dock control has focus".
- **UI-10** The canvas keys are:

  | Key | Does | Effect owned by |
  |---|---|---|
  | `C` | adds a Markdown Resource | space-and-resources.md |
  | Enter, Space | Opens the focused Resource | maps-and-graphs.md |
  | `F2` | renames the selected Resource (UI-46) | — |
  | arrows | Graph navigation | navigation.md (NV-13) |
  | Shift + arrow | moves the selected Resource | maps-and-graphs.md (Move) |
  | `P` | presents from the selected Resource | navigation.md |
  | Escape | unselects | navigation.md |
  | Delete, Backspace | removes the focused Resource from this Map (pressed on the pane, the selected one), or asks to delete the selected Edge | maps-and-graphs.md |

  Enter, Space, Delete and Backspace act only when aimed at the canvas or a Resource, one press per Edit; a region inside a Resource that keeps its keys keeps them. *Why:* removing from a Map cannot be taken back, so a key meant for chrome must not reach the canvas. **built**: `app/test/SpaceCanvas.test.tsx` › "opens with %s", "leaves %s to a `.nokey` region inside a Resource"; `app/test/edge-authoring-react.test.tsx` › "leaves the selected Resource standing when %s is aimed outside the canvas", "ignores an auto-repeated Backspace so one press removes one Resource", "removes the focused Resource rather than the selected one on %s"; `app/e2e/keyboard-shortcuts.spec.ts` › "the arrow keys follow the Active Graph, and Shift and an arrow move the Resource", "P and Present from Here present from the selected Resource".

## Selecting by click

- **UI-11** A single click on a Resource selects it, including the body of an Open Markdown Resource. No pointer gesture on a Resource's body Opens it: Open is a command. Double-click zoom is RD-66. *Why:* the Title control and a body gesture would want the same pixels. **built**: `app/e2e/editing.spec.ts` › "a click selects a Resource, and no pointer gesture on its body opens it"; `app/test/SpaceCanvas.test.tsx` › "does not happen on %s of the Resource body"; `ui/test/CanvasResource.test.tsx` › "offers no edit target on a Resource that is not selected".

## Resource toolbar

- **UI-12** A Resource's commands are one `role="toolbar"` named for the Resource. It is one tab stop, and the arrows move between its commands. *Why:* a dozen Resources would otherwise cost dozens of tab stops. **built**: `ui/test/CanvasResource-rail-toolbar.test.tsx` › "names the Resource it commands, so its controls are heard as that Resource's", "costs one tab stop however many commands it carries", "moves between its commands on the arrow keys".
- **UI-13** The commands sit in two named groups, the kind's own and the shared ones. An empty group draws nothing, and the arrows cross groups. The actions menu comes first, kind commands next, Open and Close last. *Why:* whose command it is lives in the markup, not the look. **built**: `ui/test/CanvasResource-rail-toolbar.test.tsx` › "puts a kind's own command in that kind's group", "puts Open and Close in the shared group, because every Resource has them", "groups the commands without dividing the keyboard", "draws Reference Resource Open in the shared Resource command group"; `app/e2e/resource-rail-hover.spec.ts` › "a Resource at rest draws no toolbar; selected, its commands end with Open, and its kind glyph stays at its top-right corner".
- **UI-14** A key pressed in a canvas toolbar never reaches the canvas, and a press on a command never starts a pan or drag. *Why:* the toolbar sits over the canvas. **built**: `ui/test/CanvasResource-rail-toolbar.test.tsx` › "keeps an arrow pressed on the rail off the canvas behind it"; `ui/test/CanvasCommandToolbar.test.tsx` › "keeps a press off React Flow's pan and drag".
- **UI-15** The toolbar floats above the Resource's top-right corner, outside the zoom, at the same size at every zoom. *Why:* a command's size must not depend on zoom, and inside the Resource it collides with the top anchor. **built**: `app/e2e/resource-rail-hover.spec.ts` › "the toolbar floats above its Resource’s top-right corner at a constant size".
- **UI-16** The toolbar is drawn for the one selected Resource (none while several are selected) and for a Resource whose editing is running, selected or not. It is hidden while the Resource is dragged or resized, and hovering reveals nothing. Open and Close keep the Resource selected and its toolbar drawn. *Why:* the exits of running editing must stay reachable; a gesture owns the pointer while it lasts. **built**: `react-flow-adapter/test/ResourceNode.test.tsx` › "draws none on a Resource at rest", "draws none while several Resources are selected", "keeps the exits of a running edit although the Resource is no longer selected", "draws none while the Resource is dragged", "draws none while the Resource is resized"; `app/e2e/resource-rail-hover.spec.ts` › "hovering a Resource reveals its Edge handles and no commands; selecting it draws them in React Flow's NodeToolbar", "Open and Close keep the Resource selected and its toolbar drawn, by pointer or keyboard".
- **UI-17** The Title is not in the toolbar. It keeps its own tab stop. *Why:* renaming must not be an arrow key away from Close. **built (untested)**: `ui/src/CanvasResource.tsx`.
- **UI-18** From a focused, selected Resource, the keyboard reaches that Resource's toolbar next. *Why:* every command must be reachable without a pointer. **not built**: the toolbar is portalled after every Resource, so Tab reaches the next Resource; the right-click menu is the only other reach. Tracked in `.scratch/resource-node-toolbar/issues/01-reach-a-selected-resources-toolbar-from-the-keyboard.md` (repo root). Which key enters it is an open question.
- **UI-19** An Open Reference Resource offers Close and Title editing; Edit, Save, Cancel, Replace and any Target, source, Map-choice or Graph-choice control are absent. No surface offers a control that picks or changes a Reference Resource's Target. *Why:* its Target is immutable and shown read-only. **built**: `ui/test/CanvasResource.test.tsx` › "draws an Open Reference Resource to an Image Resource as its Target’s image, with no Replace", "draws an Open Reference Resource to an Ur Resource the same, read-only"; `app/test/resource-authoring.test.tsx` › "opens each Reference Resource on resolved Target content without a source editor". The absence of Edit, Save, Cancel and the Map and Graph choices, the presence of Title editing, and the absence of a Target picker on other surfaces are untested.

## Menus

- **UI-20** The actions menu holds, in groups: Create Reference; Connect to Resource; Present from Here; for a Space Resource, Enter and Open in New Tab; the copy links; Remove from Map and Delete from Space. The copy links are: on a Resource the Map places, Copy link to Resource in Map and Copy link to Resource; on a Resource it does not, Copy link to Resource; on a Space Resource also Copy link to Space; on a Reference Resource also Copy link to Target. A Map, a Graph and a Space each offer one Copy link. A right click on a Resource opens the same ordered menu without selecting it. *Why:* one menu, two ways in. **built**: `app/e2e/editing.spec.ts` › "a Resource opens the same ordered menu from its actions control and a right click"; `app/test/enter-space-resource.test.tsx` › "groups Create Reference, Connect, Present from Here, Enter and Open in New Tab, the copy links, then Remove and Delete"; `app/test/entity-actions.test.ts` › "offers a placed Resource both link forms and no rename", "withholds the permanent link from a Resource this Map does not place", "offers a Space Resource the target Space’s own address and an independent open", "offers a Reference Resource a Copy link to Target alongside its own addresses". "Without selecting" is untested.
- **UI-21** Create Reference is drawn unavailable on a Reference Resource, still leading its group. *Why:* the menu stays the same on every Resource, and the greyed row says that referencing stops here. **built**: `app/e2e/editing.spec.ts` › "Create Reference is drawn unavailable on a Reference Resource, still leading its menu".
- **UI-22** The Map menu holds the Map list, New Map, Rename with Copy link, then Delete. The Graph menu holds the Graph list, New Graph, Colour… with Shape… directly under it, Rename with Copy link to Graph (the within-Map address only), then Delete. The Space menu holds Rename with Copy link to Space, then Exit Space. *Why:* one grouping grammar across menus. **built**: `app/ladle-e2e/command-dock.spec.ts` › "the Map menu groups New Map, Rename with Copy link, then Delete", "the Graph menu groups its commands and copies only its within-Map address", "the Space menu groups Rename with Copy link to Space, then Exit Space".
- **UI-23** Shape… is unavailable whenever Colour… is. *Why:* both change how the Graph's Edges are drawn. **built**: `ui/test/GraphMenuActions.test.tsx` › "draws Shape… unavailable when it has no press (%s)".
- **UI-24** The colour and head-shape grids are the menu's own radio group: the arrows move the highlight without choosing, Enter, Space or a click chooses and closes, ArrowLeft closes the submenu onto its trigger, and typing a name highlights it. *Why:* the menu primitive's keyboard, not a hand-rolled one. **built**: `ui/test/GraphMenuActions.test.tsx` › "moves the highlight with the arrows without choosing, and chooses on Enter", "highlights a choice by typing its name, without choosing", "closes Shape… onto its trigger on ArrowLeft, choosing nothing".
- **UI-25** An Open Space Resource offers the Map and Graph menus against its target Space, Shape… included. Their choices list the target Space's Maps and Graphs as read from that Space, its working state where it is open. While the target is unread a plain note stands in for them, and a selection the target no longer holds is drawn unavailable. What a choice writes is SR-46. *Why:* a drawn Map offers what the canvas Map offers, and a choice must name something the target holds. **built**: `ui/test/SpaceResourceSelectors.test.tsx` › "groups the Graph menu into New Graph, Colour… and Shape… with Rename and Copy link, then Delete", "draws a selection the target no longer holds as unavailable"; `ui/test/CanvasResource.test.tsx` › "stands a plain note in for the selectors while the Space is unread"; `app/test/space-resource-targets.test.tsx` › "drops a target whose read answers that it is gone". Reading the working state where the target is open is untested.
- **UI-26** An Ur Resource's Shape is a choice on its toolbar. Its face is the current Shape, its name is `Shape: <Shape>`, and its rows are the four Shapes, each drawn and named, the current one chosen. Each choice is one Edit. It is drawn at every size; on any other kind or a read-only Resource it is absent. *Why:* only an Ur Resource takes a Shape. **built**: `ui/test/CanvasResource.test.tsx` › "draws the current Shape on the rail, Open and Closed alike", "lists the four Shapes, each drawn and named, with the current one chosen and no caption", "offers no Shape where it cannot be changed, or is read-only"; `app/test/resource-rail-actions.test.tsx` › "offers a resized Ur Resource its Shape on the rail, the rectangle where its entry stores none"; `app/e2e/resource-shape.spec.ts` › "a Markdown Resource offers no Shape choice".
- **UI-27** A menu command that stays open to report (the copy links) replaces its label with a confirmation when it ran and announces a failure when it did not. A command that closes the menu on the press reports a refusal through its notice (UI-90). *Why:* a menu that has closed cannot carry the answer. **built**: `ui/test/EntityActionsMenu.test.tsx` › "confirms a command that answers at once", "announces the failure it reports"; `app/test/resource-rail-actions.test.tsx` › "shows a refused removal as \"Resource not removed\" and dismisses it".

## Absent or unavailable

- **UI-28** A command a Resource's kind lacks is absent: Edit, Open and Close on an Ur Resource; the Markdown body Edit on an Image Resource (it offers Replace, UI-53), a Reference Resource (UI-19) and a Space Resource (its Edit authors its drawn Map, UI-61). *Why:* a kind adds only what its content supports (see space-and-resources.md). **built**: `app/test/resource-rail-actions.test.tsx` › "offers an Ur Resource every Resource command and no Edit, Open or Close"; `ui/test/CanvasResource.test.tsx` › "offers Replace where a Markdown Resource offers Edit, opening a Closed one first", "offers Edit on the floating dock, and Done once the portal is being edited"; the UI-19 tests.

- **UI-32**: removed, see UI-31 and ED-37.

## Command Dock

- **UI-33** A Space has one command surface, the Command Dock, the one place its commands live. It floats over the canvas and takes no layout space: no Sidebar, Sheet, Drawer or gutter. At phone width it fits by scrolling along its own axis, with nothing to dismiss. *Why:* the canvas is the product, and a second place for commands leaves nowhere reliable to look. **built**: `app/ladle-e2e/command-dock.spec.ts` › "at phone width every cluster stays named and reachable with nothing to dismiss"; `app/e2e/mobile-dock.spec.ts` › "a side-edge Dock scrolls its clusters rather than overflowing the screen".
- **UI-34** The canvas takes one Map choice: one exclusive radio list over the authored Maps, with no second control and no empty value. Choosing is navigation (see navigation.md). *Why:* a second control needs a "none" value, which would let the canvas draw no Map (NV-5). **built**: `app/ladle-e2e/command-dock.spec.ts` › "the Map cluster is one exclusive list over the authored Maps".
- **UI-35** Activating a Graph is its own control, never merged with the Map choice. *Why:* two lists of coloured names are still two different acts. **built (untested)**: `app/src/components/CommandDockMapGraph.tsx`.
- **UI-36** Everything the Dock offers works from the keyboard alone, placing a Resource on a Map included. The Dock is one tab stop with a roving order inside it. *Why:* a drag may be a way, never the only way. **built**: `app/ladle-e2e/open-spaces-menu.spec.ts` › "the whole Dock is one tab stop with a roving order inside it"; `app/e2e/editing.spec.ts` › "a keyboard Add keeps the reader in the Resources list, on the filter".
- **UI-37** Every Dock control's accessible name contains its visible label. *Why:* speech input reaches what a reader sees (WCAG 2.5.3). **built**: `app/test/dock-commands.test.tsx` › "holds every named control in the bar to it".
- **UI-38** The Dock names the Space being worked in and reaches the Spaces open beside it, marking an unwell one (UI-98). *Why:* once Spaces nest, which one you are in cannot be read off the canvas. **built**: `app/ladle-e2e/command-dock.spec.ts` › "the bar names one Space back and discloses the rest of the open set"; `app/test/dock-commands.test.tsx` › "marks the Spaces trigger before anything is disclosed".
- **UI-39** The Dock's position is held only while it is mounted. Nothing stores it. *Why:* nobody opening a shared Space is owed the author's furniture. **built (untested)**: no browser storage in `app/src`.
- **UI-40** Create is one press per kind, as peer buttons: Markdown, Space, Image (whose press opens a file picker and completes on the files chosen) and Ur. There is no Reference button. *Why:* the kind is chosen at creation, so no kind is a default, and a Reference is made from its Target (UI-20). **built**: `app/e2e/dock-interactions.spec.ts` › "each Resource kind is created in one press from the Dock"; `app/ladle-e2e/command-dock.spec.ts` › "Create offers the four kinds as peers, each named for what it makes".
- **UI-41** The Resources list opens from the Dock and places what the selected Map does not, by drag or by press. It searches every Title Line and filters by kind and Spaces. It survives work on the canvas behind it, and Escape closes it with focus back on its trigger. Each Resource row offers Delete from Space with the toolbar's confirmation; a Space row offers none. *Why:* the list is the one surface naming a Resource the Map does not place. **built**: `app/test/ResourcesPopover.test.tsx` › "adds a Resource by name and finds it by any line of its Title", "filters by kind and search, then activates the matching Resource", "takes the Spaces away when their toggle is pressed off, and leaves the Resources", "closes on Escape and returns focus to the trigger", "deletes a Resource from its row without placing it", "offers no delete on a Space row, which is not a Resource of this Space"; `app/e2e/editing.spec.ts` › "the Resources list dismisses on Escape and survives working on the canvas behind it".
- **UI-42** A mounted session's Dock carries the mark "Edits lost on reload" beside the persistence report. It is a mark, not a command and not a status. *Why:* it is the only warning that a mounted Edit does not survive reload. **built**: `app/test/mounted-session.test.tsx` › "marks that edits are lost on reload, beside the persistence status"; `app/e2e/mount.spec.ts` › "marks that edits are lost on reload, takes an Edit, and loses it on reload".
- **UI-43** Once mounted Edits are kept in the browser, the mark reads "Edited in this browser" while the stored copy differs from the copy first mounted, and there is no mark when they match. *Why:* the mark says where the Edits are. **not built**: DECISIONS 4; tracked in `.scratch/mounting/issues/11-keep-mounted-edits-in-the-browser.md` (repo root).

## Title editing

- **UI-44** Wherever Title authoring is available, the displayed Title is a control named for the action and the Resource (`Edit Title <name>`), wrapping the heading. One activation (click, Enter or Space) replaces it with the field, focused, its whole value selected. *Why:* the value an author wants to change is the control that changes it. **built**: `ui/test/CanvasResource.test.tsx` › "wraps its heading in the Title’s one-activation control", "focuses and selects the draft on mount"; `ui/test/InlineTitleEditor.test.tsx` › "selects the whole Title on entry, later lines included".
- **UI-45** Activating the Title neither selects nor Opens the Resource, and its hit area is the Title's text. *Why:* the rest of the Resource stays the selection target. **built**: `ui/test/CanvasResource.test.tsx` › "does not let Title activation reach the Resource around it"; `app/test/SpaceCanvas.test.tsx` › "leaves the Title control free to rename without Opening the Resource"; `app/e2e/editing.spec.ts` › "a short Title control's hit-area hugs its text, not the whole Resource body".
- **UI-46** `F2` renames the selected Resource, except while focus is in a control. *Why:* the selection may belong to another Resource than the focused control. **built**: `app/test/SpaceCanvas.test.tsx` › "renames the selected Resource when the key is not typed into a control", "does not rename the selected Resource from one of its toolbar commands".
