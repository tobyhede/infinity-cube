# Conflicts: Storage and hosts

These are conflicts for `storage.md`, open and closed. Paths are relative to `packages/`.

## Open

### S2. Why the format still rolls forward now that a directory can be the author's only copy

- **Rules affected.** ST-36's *Why:*, which reads "undecided (S2)" until this is ruled. The rule itself (no versioned reader, no migration, no compatibility path) is accepted and built, and this conflict does not question it.
- **Disagreement.** 0054 and 0056 justify the rule by "the repository is the only source of state": every database and directory is derived and regenerated by a reset. Three later decisions break that premise without revisiting the rule. Under `hyper run` an Aggregate directory is the durable copy and may be an author's own talk outside this repo (0117). Image bytes outside the repo are excepted (0106, 0118). A mounted talk will keep edits in browser storage (0132, not built). So a format change can leave an author's directory, or a browser's stored copy, unreadable by the next build, with only git to recover it.
- **Options.**
  - (a) Restate the reason as "Hyper is unreleased and makes no compatibility promise: an author recovers an old directory from git, or reads it with the build that wrote it".
  - (b) Leave the reason as 0056 states it.
- **Recommendation.** (a). It matches the code and 0117's accepted cost ("git answers for history"). (b) states a premise that no longer holds. Adding an upgrade path for directories would change the rule, which is a new decision, not this conflict.
- **Evidence.** `docs/adr/0054`, `0056`, `0117`, `0118`, `0132`; AGENTS.md "State" already names the image exception. `test/unit/import-aggregate.test.ts` › "refuses a version 2 space directory rather than migrating it"; `test/unit/run.test.ts` › "serves the directory it was started on".

## Closed

### S1. Closed by ruling S1

Ruling S1 in `../DECISIONS.md` ("Checkpoint 2 rulings"): every working read goes through the one initializing loader, wherever it runs. Which reads count as working reads is MG-75.

For the record:
- **What the conflict was.** 0080 said one server-side boundary. The old contract R18 said one boundary per context. The code builds the loader in three places.
- **What the ruling settles.** The number of call sites is not a requirement. Each site must use the one loader.
- **Evidence.** `http/src/index.ts` (the single-Space route); `persistence/src/session-registry.ts` (`workingTargetSelection`); `app/src/open-spaces.ts` (`compose`); `persistence/src/working-space.ts` `createWorkingSpaceLoader`. Behind HTTP, the browser loaders read through the single-Space route, which has already initialized the Space.
