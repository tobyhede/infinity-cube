**Terms** (definitions are in `CONTEXT.md`):
- **Canvas**: the React Flow surface that draws one Map of a Space. **Drawn Map**: a Map drawn inside an Open Space Resource.
- **Anchor**: one of a Resource's four Edge attachment points, one per side. **Handle**: an anchor offered as a place to start or end the Edge-drawing gesture.
- **Lane**: the path one of several Edges joining the same two Resources takes beside the others.
- **Recede**: draw at reduced strength while staying fully interactive.
- **Rect**: a Resource's drawn box: its stored position and its size (the Closed Size, 260×146, when none is stored).
- **Title underline**: the line drawn under a Resource's Title while it is hovered or written.
- **Camera command**: one of React Flow's `setCenter`, `fitView`, `fitBounds` and `zoomTo`.

**Status:** **built** means code and a named test match the rule. **built (untested)** means code matches and no test covers it. **not built** means the rule is decided and no code implements it. **bug: code differs** means the code does what the note says instead. **undecided (Cn)** means the rule waits on conflict Cn; the note says what the code does meanwhile. A test is named as `file` › "test name". Paths that start with `test/` are at the repo root; all others are under `packages/`.

The canvas stores nothing. It draws from these fields, owned by other docs, and only an Edit changes them.

## Resources

- **RD-1** A Closed Resource draws its Title Lines, its border and, except on an Ur Resource, its kind glyph (RD-9), and no content. *Why:* a Closed Resource shows the shape of the Map; content is reached by Opening or presenting. **built**: `react-flow-adapter/test/projection.test.ts` › "maps resources to resource nodes carrying the title, not the content"; `app/ladle-e2e/resource.spec.ts` › "every Closed Resource draws its kind, its border and its Title Lines, and nothing beneath them".
- **RD-2** An Open Resource draws its content inside its own rect, where it sits, with its Title. It is the same Resource drawn with a content region, which its kind fills; there is no second drawing for Open. Nothing covers the canvas, several Resources may be Open at once, and an Open Resource takes its rect with no aspect-ratio constraint. *Why:* reading in place keeps the Map in view. **built**: `react-flow-adapter/test/ResourceNode.test.tsx` › "draws the Resource's rendered Markdown on the Resource, and says the Resource is Open"; `app/e2e/overview.spec.ts` › "a resource shows its title in the graph, and opens to show rendered Markdown"; `app/ladle-e2e/resource-open.spec.ts` › "Open and Close retain one Resource and Title treatment".
- **RD-3** Opening or Closing changes only what draws inside the rect. The rect and every other Resource stay where they are; the camera is RD-65. *Why:* Open shows content; only Resize changes a rect (MG-23). **built**: `app/e2e/editing.spec.ts` › "opened Markdown editing persists source while Opening and Closing move no Resource" (positions). Size is untested here; MG-27 holds it.
- **RD-4** An Open Image Resource's picture is contained: it shrinks to fit whole and is never enlarged. Other overflowing content is RD-5. *Why:* the Closed Size is the one floor (MG-22), so no kind asks for room. **built**: `app/e2e/image-resource.spec.ts` › "an Open Image Resource draws its picture contained where Markdown content is drawn, at the size it already had"; `app/ladle-e2e/resource-open.spec.ts` › "an Open Image Resource draws its picture at its own size where Markdown content is drawn".
- **RD-5** What Open content that does not fit its rect draws: Markdown longer than the rect, and a drawn Map larger than its window, including where an unframed drawn Map is placed. **undecided (C1)**: the code clips both. With no framing, a drawn Map puts the top-left of its Resources (their least `x` and least `y`, read once when it is drawn) at the window's inner top-left, at zoom 1, and clips the rest: `app/test/space-resource-framing.test.ts` › "fits from the Map origin when nothing has been framed yet"; `app/test/embedded-map.test.ts` › "draws a Resource beyond the containing bounds where it was authored, clipped rather than moved". Clipping Markdown is untested (`ui/src/markdown-resource-body.css`, `overflow: hidden`).
- **RD-6** Open Markdown at rest draws through the same renderer the presenting Stage uses, and that renderer sanitises the Markdown before it is put on the page. *Why:* one source must not be interpreted by two pipelines, and content may come from any import. **built**: `ui/test/MarkdownResourceBody.test.tsx` › "draws parsed Markdown at rest through the presentation renderer"; `ui/test/PresentedResource.test.tsx` › "strips event-handler attributes", "strips javascript: hrefs while keeping the link", "drops script and iframe elements entirely".
- **RD-7** An Open Image Resource draws a skeleton until its picture loads. A picture that does not load draws a failed state that names its URL and keeps the Title (that it is not a refusal is SR-27). *Why:* the author sees which picture is missing. **built**: `ui/test/ResourceImage.test.tsx` › "draws a skeleton in the picture’s place until the picture loads", "replaces the skeleton with the failed-image state when the picture does not load"; `ui/test/CanvasResource.test.tsx` › "names the URL when an Open Image Resource cannot load its image, keeping the Title".
- **RD-8** On Close, content fades out and the Resource keeps drawing the content it last drew until the fade ends. Reduced motion removes content transitions. *Why:* the content does not vanish mid-fade. **built**: `ui/test/CanvasResource.test.tsx` › "keeps the Markdown it last drew while the content fades out"; `app/ladle-e2e/resource.spec.ts` › "reduced motion removes Resource content transitions".
- **RD-9** A Closed Resource draws its kind glyph at its top-right corner, chosen by its stored kind, on every kind but the Ur Resource. An Open Resource draws no glyph. *Why:* the glyph tells a Reference Resource from its Target; an Ur Resource's Shape says what it is. **built**: `app/ladle-e2e/resource-open.spec.ts` › "at rest a Resource draws no toolbar; selected, its commands are drawn with Open last, and its kind glyph stays at its top-right corner"; `ui/test/CanvasResource.test.tsx` › "draws no kind glyph on an Ur Resource in a %s, Open or Closed", "presents a Reference Resource by its kind alone". The Open clause is untested (`CanvasResource.tsx` `kindMark`).
- **RD-10** A Reference Resource draws a dotted border at rest. *Why:* it tells the Reference apart from what it points at. **built**: `app/ladle-e2e/resource.spec.ts` › "a Reference Resource's dotted border and a long Markdown title's three-line clamp are the kind's own presentation".
- **RD-11** An Open Reference Resource draws its own Title over its Target's content, read-only, through the Target kind's own renderer. An unresolved Target draws a notice. *Why:* one renderer per kind, and the Reference shows what it points at. **built**: `react-flow-adapter/test/ResourceNode.test.tsx` › "draws an Open Reference Resource's resolved Markdown read-only under the Reference Resource Title"; `ui/test/CanvasResource.test.tsx` › "draws an unresolved Target as a notice, not an empty document".

## The Title ladder

- **RD-12** A Resource draws its Title as Title Lines: line 1 in the `title` role, line 2 `subtitle`, and line 3 and every later line `caption`. Each line is its own block, and an interior blank line is kept. The rungs step down in size and weight in the same ink. *Why:* the author's breaks carry meaning; the roles are domain knowledge (space-and-resources.md). **built**: `ui/test/CanvasResource.test.tsx` › "gives each authored line its role, and every line past the third the last one", "keeps an interior blank line as a line of its own"; `ui/test/canvas-resource-title-ladder.test.ts` › "step the weight 600 / 500 / 400", "keep the heading own colour and are not dimmed".
- **RD-13** The ladder draws the same Open and Closed, on every kind. *Why:* a Title that changes shape on Open teaches that Opening edits it. **built**: `ui/test/CanvasResource.test.tsx` › "draws the same ladder Open and Closed, on every Resource kind".
- **RD-14** A break the box chooses is not a rung. A line wraps within its own role, and clamping counts visual lines per role. *Why:* only authored breaks are load-bearing. **built**: `ui/test/canvas-resource-title-ladder.test.ts` › "clamp visual lines per role"; `app/ladle-e2e/resource.spec.ts` › "a wrapped single-line Title stays one rung while an authored three-line Title draws three".
- **RD-15** A Title too long for its room is clipped at a fixed ceiling chosen to fit a Closed Resource, the same Open and Closed. A Title never resizes a Resource. *Why:* placement is authored; resizing is how a long Title gets room. **built**: `ui/test/canvas-resource-title-ladder.test.ts` › "fits inside the body of a Closed Resource", "is a clip on the heading, not a size the Resource grows to", "still clamps to three visual lines at the title role". The ceiling per Shape is a code note (trace §5).

## Shapes

- **RD-16** A Shape is drawn at the Resource's rect, at every size. Ellipse and diamond fill the rect proportionally, a pill's ends stay half-circles, and every Shape touches the midpoint of each side, so an Edge meets the outline. *Why:* Edges attach at side midpoints, whatever the Shape (MG-29, MG-32). **built**: `ui/test/resource-shape-outline.test.ts` › "draws every Shape touching the midpoint of every side of its rect, at any size", "rounds a pill by half its smaller side, at any size, so its ends stay half-circles"; `app/e2e/resource-shape.spec.ts` › "an Edge drawn to a Closed diamond meets its outline".
- **RD-17** In a Shape other than the rectangle, the Title is centred in the rectangle inscribed in the Shape and draws the whole ladder, clipped as RD-15 says to the lines that rectangle holds. *Why:* the outline is not room for text. **built**: `ui/test/resource-shape-outline.test.ts` › "lays out the Title of every Shape in a rectangle inside the outline, at any size"; `ui/test/CanvasResource.test.tsx` › "draws the whole ladder in a %s, Open and Closed".
- **RD-18** The selection ring and drag shadow follow the outline. A selected Resource in a Shape other than the rectangle also draws a thin frame at its rect, which is where the resize control sits (ui.md); the frame is not drawn while the Resource is dragged. *Why:* the control needs a drawn corner. **built**: `app/e2e/resource-shape.spec.ts` › "a Shape's selection ring follows its outline at any size, and a Reference Resource made from it is the rectangle"; `react-flow-adapter/test/ResourceNode.test.tsx` › "frames a selected Shape at its rect with the resize control, and leaves the rectangle unframed".
- **RD-19** A drawn Map draws its Resources' Shapes as the canvas does. *Why:* one drawing serves every Map (RD-59). **built**: `app/e2e/space-resource.spec.ts` › "a Shape chosen inside an Open Space Resource is the target Map’s, drawn wherever it is".

## States, motion, colour and receding

- **RD-20** Rest, selected and dragging draw distinct treatments. The selection ring and shadow are ink on every Resource. *Why:* selection reads the same on every Graph. **built**: `app/ladle-e2e/resource.spec.ts` › "rest, selected and dragging draw visually distinct treatments, for both kinds".
- **RD-21** A dragged Resource leans by a fixed angle. An Open Space Resource's drawn Map leans with it as one rigid motion, and its Edges follow the moved positions. *Why:* the embedded Map stays aligned with its window. **built**: `app/test/embedded-map.test.ts` › "moves each embedded Resource rigidly about the dragged Resource rather than turning it in place", "leaves the Edges to React Flow, which draws them from the positions that moved".
- **RD-22** A Resource's position and size do not animate while it is dragged or resized, and a Resource never animates in from the canvas origin. *Why:* the drawing must stay under the pointer. **built**: `app/ladle-e2e/resource-open.spec.ts` › "an active Resource resize does not animate its dimensions behind the pointer"; `app/e2e/new-space.spec.ts` › "centres its first resource without animating it in from the canvas origin".
- **RD-23** A Resource's border is the Active Graph's colour when the Active Graph reaches it. Otherwise it is the colour of the first Graph, in the Map's order, that it is in, and ink when it is in none. "In a Graph" is MG-33. *Why:* a reader sees from a Resource which Graph it belongs to. **built**: `app/test/resource-graph-emphasis.test.ts` › "draws a Resource the Active Graph reaches in its colour, at full strength", "recedes any other Resource, drawn in the first Graph it is in", "draws a Resource in no Graph in ink, receding".
- **RD-24** A Resource the Active Graph does not reach recedes: its face stays solid, its border is mixed halfway towards the face, and its Title, kind glyph and content draw at half opacity. It stays fully interactive. *Why:* the Active Graph's line is the narrative; nothing behind a Resource may show through it. **built**: `app/e2e/overview.spec.ts` › "a Resource is drawn in its Graph colour, and recedes off the Active Graph (ADR 0135)".
- **RD-25** A receding Resource draws at full strength while hovered, focused, selected, edited or offered as the end of a connection. *Why:* the Resource being worked on is never dim. **built**: `app/e2e/overview.spec.ts` › "a Resource is drawn in its Graph colour, and recedes off the Active Graph (ADR 0135)" (hover). The other states are untested (`app/src/styles.css`).
- **RD-26** Nothing recedes while there is no Active Graph or the Active Graph has no Edges. *Why:* Add Graph activates an empty Graph, and the Map must not dim on that gesture. **built**: `app/test/resource-graph-emphasis.test.ts` › "recedes nothing while the Active Graph has no Edges", "recedes nothing with no Active Graph".
- **RD-27** Only the border and a Shape's outline take a Graph colour. The shadow, the selection ring, and the resize control's marks and frame (RD-18) stay ink. The Title underline draws in the Active Graph's colour on every Resource, receding ones included (handles: RD-51). *Why:* selection reads the same on every Graph. **built**: `app/ladle-e2e/resource.spec.ts` › "a Resource's commands stay neutral across the full palette while its handles carry the colour". The Title underline is untested.
- **RD-28** How fast a change of Active Graph fades a Resource's border and strength. **undecided (C2)**: the border, outline, Title and glyph fade over the hover timing; the content's opacity fades over its own timing (a fraction of the placement duration, placement easing), shared with the Close fade (`ui/src/canvas-resource.css`). Untested.
- **RD-79** A completed Resize moves the Resources it displaces, and changes its own rect, by a transition from one duration and easing token; Opening and Closing animate no rect. Reduced motion shortens the transition to nothing. *Why:* authored before-and-after positions, not entrance effects. **built**: `app/e2e/editing.spec.ts` › "a completed Resize animates the neighbours it displaces from the one duration token". Reduced motion for rects is untested (`app/src/styles.css`).
- **RD-80** Every text role a Resource draws on its own faces reads at WCAG AA at full strength. A receding Resource (RD-24) is below AA until it returns to full strength. *Why:* the Resource is light on a dark app, so a token that reads elsewhere can vanish here; receding is the point. **built**: `test/unit/canvas-resource-contrast.test.ts` › "reads at AA: $name".
- **RD-81** Every drawn Map applies RD-23–RD-27 by its own Active Graph. *Why:* each Map is read on its own terms. **built (untested)**: `app/src/canvas-projection.ts` (every drawing projects through it).

## Edges

- **RD-29** Every Graph the Map owns is drawn at all times. Activating a Graph is emphasis, never filtering: the other Graphs' Edges recede by opacity and a narrower stroke, and the Active Graph's Edges are painted last, on top. With no Active Graph every Graph draws at full strength. No Edge animates. *Why:* a reader sees every narrative and which one is current. **built**: `react-flow-adapter/test/projection.test.ts` › "recedes the other graphs while one is active, never hiding them", "draws every graph the same when nothing is emphasised", "draws the Active Graph last, over the lanes it converges with"; `app/e2e/overview.spec.ts` › "selecting a graph emphasises it without hiding the others".
- **RD-30** An Edge draws in its Graph's colour. Which colour a Graph without one draws in is MG-48. *Why:* appearance is the Graph's (MG-66). **built**: `app/e2e/overview.spec.ts` › "draws every Graph in the selected Map, each in its own color".
- **RD-31** An Edge's render id is `<graphId>::<from>::<to>`, never its index, and its Title is no part of it. In a drawn Map, node and Edge ids also name the occurrence, while the Edge's subject stays the domain Edge. *Why:* an index-keyed id passes to the next Edge when one is removed; a retitled Edge must redraw the same element. **built**: `graph/test/graph-rendering.test.ts` › "leaves a surviving edge’s id unchanged when an earlier edge is removed", "carries an Edge Title and its hiding, and leaves the id to the endpoints"; `app/test/embedded-map.test.ts` › "gives two embeddings of the same Space distinct node and Edge identities", "keeps the domain Edge subject when a drawing rekeys its endpoints".
- **RD-32** Nothing routes an Edge. Each is React Flow's bezier between its two anchors (offset when in a lane, RD-41), and no drawing assumes the Graphs agree on an order, so a backward Edge is drawn like any other. *Why:* a Map stores positions only, and Graphs may order the same Resources oppositely (MG-36). **built**: `react-flow-adapter/test/RoutedEdge.test.tsx` › "draws the curve between the two anchors it attaches to".
- **RD-33** A Resource has four anchors, one at the midpoint of each side, and they are the same four handles the gesture uses. An Edge names no handle. Every Resource declares all four of each role, read-only and drawn-Map Resources included, and they are always rendered. *Why:* React Flow draws no Edge at all for a Resource whose handles it cannot resolve. **built**: `react-flow-adapter/test/projection.property.test.ts` › "declares the four anchors of each role on every Resource an Edge reaches", "leaves an Edge naming no handle at all"; `react-flow-adapter/test/ResourceNode.test.tsx` › "keeps the four anchors of each role on a read-only Resource".
- **RD-34** An Edge attaches on the sides that face each other. On each axis, the gap is the empty distance between the two rects, negative by the overlap when they overlap. The axis with the larger gap is used; equal gaps take the horizontal axis. On that axis, a target whose centre is at or past the source's leaves the source's right (or bottom) side and enters the target's left (or top); otherwise the reverse. The other axis's centres are never read. *Example:* a target whose left side is 100 units right of the source's right side, and whose top is 20 units below the source's top, has a horizontal gap of 100 and a negative vertical gap, so the Edge leaves the source's right side and enters the target's left. *Why:* large beside small is the normal state of a Map, and a centre-vector rule attaches such pairs across a Resource. **built**: `react-flow-adapter/test/edge-attachment.test.ts` › "takes the horizontal axis when the two gaps are equal", "leaves the bottom when the two are level on the chosen axis", "faces the sides across the gap when a large Open Resource sits beside a collapsed one".
- **RD-35** The side is chosen from where the two Resources are now, so it is right during a drag, and it is never stored. An Edge's end lands on the outer rim of the anchor's handle. *Why:* a side chosen only at release crosses the Resource for the whole drag. **built**: `app/e2e/edge-attachment.spec.ts` › "the attachment follows the drag rather than waiting for the release"; `react-flow-adapter/test/RoutedEdge.test.tsx` › "attaches on the facing sides of where the two Resources are now"; `react-flow-adapter/test/edge-attachment.test.ts` › "sits on the outer rim of the handle declared on that side".
- **RD-36** A self-Edge draws a fixed loop from the right side to the top and never enters RD-34. *Why:* the facing rule draws a self-Edge's loop through its own Resource. **built**: `react-flow-adapter/test/edge-attachment.test.ts` › "loops between two adjacent sides of the one Resource"; `app/e2e/edge-attachment.spec.ts` › "a self-Edge draws a visible loop".

## Lanes

- **RD-37** Where several Edges join the same two Resources, from any Graphs and in either direction, each is drawn in its own lane, 8 units apart. Lanes are parallel, never fanned by curvature. *Why:* coincident lines read as one striped line; fanned ones read as different connections. **built**: `app/e2e/edge-attachment.spec.ts` › "several Graphs over one pair of Resources run as parallel lines below the active one"; `react-flow-adapter/test/edge-lanes.test.ts` › "keeps the centre for the first of a shared pair and stacks the rest outwards".
- **RD-38** The Active Graph's Edge is centred and runs anchor to anchor. Where the Active Graph holds both directions of a pair, they split the centre, half a spacing either side, the one whose source sorts first above or to the left. *Why:* the Active Graph is the one that connects. **built**: `react-flow-adapter/test/edge-lanes.test.ts` › "puts the Active Graph on the centre whatever order it arrives in", "splits the centre between both directions of a pair the Active Graph holds".
- **RD-39** Every other Graph's Edge takes a lane below the centre (to its right where the Resources are stacked), one spacing further out each in Graph order, starting past the Active Graph's outermost lane. The side is the screen's, so an Edge and its reverse stack on the same side. Activating another Graph moves the lanes, and a drag carries them. *Why:* lanes read the same everywhere on the canvas. **built**: `react-flow-adapter/test/projection.test.ts` › "puts the Active Graph on the centre, connecting, with the others below it", "moves the centre to whichever Graph becomes active"; `react-flow-adapter/test/edge-lanes.test.ts` › "bundles an Edge with its reverse".
- **RD-40** An Edge of a Graph that is not active stops short by a fifth of its length at each end, measured along the curve and cut in the geometry, even where it is alone in its pair. While no Graph is active nothing stops short, and the first Edge of a pair keeps the centre. *Why:* only the Active Graph connects; a dash pattern would slide. **built**: `react-flow-adapter/test/edge-lanes.test.ts` › "leaves a fifth of a level Edge undrawn at each end and keeps it level", "connects every Edge while no Graph is active", "keeps the centre for another Graph where the Active Graph has no Edge in the pair".
- **RD-41** Each lane follows the lone Edge's curve at its lane's distance, measured square to the curve, over the middle of the curve, and joins its anchors with a short forward curve at each end. Lanes of one pair never cross. Where the curve turns too tightly for that, the pair's lanes are the lone curve shifted sideways along the anchors' sides. How the middle stretch is found is a code note (trace §5). *Why:* a sideways shift alone closes the gap where the curve turns. **built**: `react-flow-adapter/test/edge-lanes.test.ts` › "runs every point of a lane inside its span at its offset from the centre curve", "never runs a lane nearer its neighbour than the same lanes moved whole", "moves a lane between anchors level on the facing axis whole, along the sides".
- **RD-42** A lane starts and ends beside its anchors, moved along the side each sits on, and a self-Edge's lanes move each anchor along its own side away from the corner. The label sits at the lane's midpoint. *Why:* ends and heads land where the lane is. **built**: `react-flow-adapter/test/edge-lanes.test.ts` › "starts and ends a lane beside its anchors, on the side each sits on", "keeps a self-Edge’s lane anchors on the sides they sit on, away from the corner".

## Head shapes, Edge Titles and the Graph key

The Edge controls (focus, the Edit/eye/Delete group, its reveal on hover or selection, and Edge Title editing) are UI-78–UI-82.

- **RD-43** Every drawn Edge ends in its Graph's head shape at its drawn `to` end, Edges that stop short included, filled in the Graph's colour and painted at the Edge's opacity. *Why:* the head shape tells Graphs apart where colour cannot, and the receding Graphs are the ones that need it. **built**: `react-flow-adapter/test/projection.test.ts` › "ends every Edge in its Graph's head shape, the ones that stop short included"; `app/e2e/edge-attachment.spec.ts` › "a receding Graph's head is painted at its Edge's opacity".
- **RD-44** Each Graph's head is one marker per canvas, drawn in one hidden `<defs>` under an id keyed by the Graph's id, sized in stroke widths, with its tip on the end of the line. Every canvas that draws Graph Edges mounts these markers. *Why:* one marker serves every Edge of a Graph, and the wider Active stroke draws a larger head. **built**: `react-flow-adapter/test/GraphHeadMarkers.test.tsx` › "draws one marker per Graph, in its head shape and colour, under the id its Edges name"; `ui/test/GraphHeadShape.test.tsx` › "draws the glyph as an SVG marker whose tip sits on the end of the line it ends".
- **RD-45** The four head shapes are drawn distinctly, from one glyph wherever a head shape shows. *Why:* they must stay distinct at small zoom. **built**: `ui/test/GraphHeadShape.test.tsx` › "draws each of the four head shapes differently".
- **RD-46** Only the Active Graph's Edges draw their Titles. At rest a Title is fitted to the room its Edge leaves: the drawn line's length less `EDGE_TITLE_CLEARANCE` (28), at most `EDGE_TITLE_CEILING` (224), and nothing where that room cannot hold `EDGE_TITLE_LEAST_TEXT` (`ui/src/edge-title-room.ts`, canvas units). The whole Title is in its tooltip. *Why:* a long Title on a short Edge must not cover the Map. **built**: `app/test/edge-authoring-react.test.tsx` › "draws only the Active Graph's Titles", "draws a Title at rest, fitted to its Edge, with the whole Title in its tooltip"; `ui/test/edge-title-room.test.ts` › "never runs past the Edge less its clearance, nor past the ceiling", "draws nothing exactly when the box could not hold three characters and the ellipsis".
- **RD-47** A hidden Title draws nothing at rest and draws dimmed while its Edge is revealed (UI-79). An Edge draws no endpoint handles. *Why:* hiding is the author's choice (MG-65); an Edge's end cannot be moved (MG-67). **built**: `app/test/edge-authoring-react.test.tsx` › "hides a Title at rest from the eye, and dims it while the Edge is revealed", "selects and focuses the Active Graph Edge alone, and reconnects none".
- **RD-48** The canvas draws a key: the Space and Map identity, and every Graph on the Map with its legend mark, the Graphs that are not active dimmed. The key takes no pointer it does not need. *Why:* it is the colour reference beside the Edges being read. **built**: `react-flow-adapter/test/GraphHud.test.tsx` › "resolves each stripe through the shared Graph colour seam and dims the rest", "lets the canvas take every pointer the key panel does not need"; `app/ladle-e2e/graph-hud.spec.ts` › "the Graph HUD keys every Graph and emphasises the active one".
- **RD-49** A Graph's legend mark is a short line in its colour ending in its head shape (`arrow` where none is stored). The same mark stands beside every Graph title in the key, the Dock's Graph choices and an Open Space Resource's Graph choices. *Why:* those lists are where a viewer matches a receding Edge's head to its Graph. **built**: `react-flow-adapter/test/GraphHud.test.tsx` › "ends each row’s mark in its Graph’s head shape, `arrow` where none is stored"; `app/e2e/overview.spec.ts` › "the Dock’s Graph rows draw the HUD key’s legend mark rather than a Graph glyph".

## Drawing an Edge, and the resize and move previews

The Edit a completed gesture makes is MG-62 and MG-63. The modifier key, Connect to Resource and what selects after a gesture are in ui.md.

- **RD-50** An Edge is drawn by dragging from one of a Resource's four handles and releasing on a Resource, the source included. The handles are the same for every Graph, and the side used is not stored. *Why:* drawing is spatial, and the Edge stores only its endpoints. **built**: `react-flow-adapter/test/ResourceNode.test.tsx` › "starts a drag from a source handle while no Edge is being drawn", "ends a drag on a target handle while an Edge is being drawn".
- **RD-51** The handles draw in the colour of the Graph the Edge will join, on every Resource, receding ones included: the Active Graph, or in a drawn Map the Graph it shows; with no Active Graph, the palette's first colour. *Why:* the result is visible before the drag begins. **built**: `react-flow-adapter/test/ResourceNode.test.tsx` › "shows four active-Graph-coloured spatial source handles on a selected Resource"; `app/test/canvas-projection.test.ts` › "colours the authoring handles as the Active Graph, and as the first slot without one".
- **RD-52** Source handles show on a hovered or selected Resource where Edges may be drawn, and not while it is dragged or resized. A Resource where they may not be drawn shows none. *Why:* a moving Resource has one gesture. **built**: `app/ladle-e2e/resource.spec.ts` › "hovering the real React Flow node reveals the adapter's Edge handles and none of CanvasResource's commands; selecting it draws them"; `app/e2e/editing.spec.ts` › "a Resource being moved draws neither its toolbar, its Edge handles nor its resize control, and offers them again on release"; `react-flow-adapter/test/ResourceNode.test.tsx` › "offers no affordance on a Resource the flow withholds connection from".
- **RD-53** During the drag, handles to end on show only on Resources within 80 canvas units of the pointer (distance to the Resource's bounds, zero over its body) that would accept the Edge. A Resource that would refuse it shows none and is not snapped to. The source is eligible when the pointer is near it. *Why:* showing a target the release would refuse misleads. **built**: `react-flow-adapter/test/connection-target-reveal.test.ts` › "requires seeking, proximity and eligibility together", "uses CONNECTION_TARGET_PROXIMITY as the default radius"; `react-flow-adapter/test/ResourceNode.test.tsx` › "withholds seeking ends when eligibility refuses the Resource", "withholds the seeking reveal when the pointer is not near the Resource".
- **RD-54** The connection preview draws in the colour and head shape of the Graph the Edge will join. *Why:* it previews the Edge as it will be drawn. **built**: `react-flow-adapter/test/GraphConnectionLine.test.tsx` › "ends the preview in the head shape it is given, in the stroke’s colour".
- **RD-55** Releasing on empty canvas cancels and changes nothing. With the modifier held (ui.md), a translucent preview of the next Markdown Resource is drawn centred at the pointer, and release creates it (MG-63); a release over a Resource's body or off the canvas creates nothing. A connection target within React Flow's connection radius outranks the element under the pointer. *Why:* a missed target must not become an Edit, and a release near a handle aims at it. **built**: `app/e2e/new-space.spec.ts` › "Alt toggles a transient Resource 2 preview during an empty connection drag", "an Alt-drop released off the canvas creates no Resource"; `app/test/edge-authoring.test.ts` › "never authors a Resource unless every fact agrees", "lets a connection target in range outrank %s underneath".
- **RD-56** The gesture is cancelled, writing nothing, when the selected Map or the Active Graph changes, the Space is replaced (editing.md), presenting withdraws authoring, the canvas selects another Resource, or its source Resource leaves the drawing. An unrelated completed Edit leaves it standing. *Why:* a drag must not land in a context the author did not start it in. **built**: `app/test/edge-authoring.test.ts` › "cancels the draft when the selected Map changes", "cancels the draft when the Active Graph changes", "cancels the draft when a replacement Space is opened over it", "cancels the draft when presenting withdraws Edge authoring", "cancels a pointer connection when the canvas selects another Resource", "leaves the draft standing through an unrelated completed Edit". The Active Graph, replacement and unrelated-Edit cases are tested on a Title draft through the same invalidation pass (`edge-authoring.ts`); the source-leaves case is untested (`subjectSurvives`).
- **RD-57** A Resize previews only the resizing Resource's rect. Its neighbours stay where they are stored until the Edit lands (MG-24). *Why:* displacement is written by the Edit, not derived while drawing. **built**: `app/test/render-adapter.test.ts` › "previews the resizing Resource and nobody else, and completes only its final size".
- **RD-58** A move is React Flow's own drag. The canvas reports a completed move only at the drop, and none for a drag that returns to where it began; what the Move writes is MG-21 and MG-83. *Why:* only a finished gesture is a fact for the domain. **built**: `app/e2e/editing.spec.ts` › "a dragged resource stays where it is dropped, and nothing else moves"; `app/test/render-adapter.test.ts` › "completes no Edit for a drag that returns to where it began".

## Drawn Maps

What a drawn Map may author, and its policy, are in space-and-resources.md.

- **RD-59** An Open Space Resource draws the Map and Graph it selects inside its own rect, through the same drawing as the canvas, projected into the containing React Flow instance. - **RD-60** With a framing, a drawn Map puts the framing's centre at the window's midpoint at the framing's zoom. Zoom scales positions, not Resources: each keeps its size. Where an unframed drawn Map is placed, and what lies past the window, are RD-5. *Why:* framing is a camera on the Map. **built**: `app/test/space-resource-framing.test.ts` › "places the stored centre at the window midpoint at the stored zoom"; `app/test/embedded-map.test.ts` › "does not change a Resource flow-pixel size when the portal zooms".
- **RD-61** While a drawn Map is being edited, the wheel over it pans and zooms it, and that is the Frame Edit (SR-48), but not while presenting. *Why:* framing is authored by looking. **built**: `app/test/space-resource-embedded-map.test.tsx` › "does not put nowheel on an Open Space Resource in portal Edit, and wheel still authors its framing", "does not author portal framing from wheel while presenting".

## Camera

- **RD-62** When a canvas first draws and has no stored framing to open on, it fits the Map in view with padding, never zooming past natural size, so a lone Resource is centred at natural size. *Why:* the origin is not a place anyone chose, and one Resource filling the screen reads as broken. **built**: `app/e2e/new-space.spec.ts` › "centres its first resource without animating it in from the canvas origin", "renders at natural size rather than filling the screen".
- **RD-63** A Space entered with a framing opens at that framing, sized from the canvas rather than the Space Resource, and is not fitted. *Why:* the author framed it. **built**: `app/test/cameras.test.tsx` › "places the entered canvas from stored framing and the canvas size, not fitView"; `app/test/space-resource-framing.test.ts` › "builds an entered viewport from the browser canvas size, not the source Resource".
- **RD-64** The author pans and zooms freely, up to 16× so one Resource can fill a large screen. A camera move is never an Edit and writes nothing. The minimap in the key pans and zooms the canvas; the zoom control is UI-96. *Why:* looking is not authoring. **built**: `react-flow-adapter/test/GraphHud.test.tsx` › "keeps the minimap panning and zooming the canvas". The ceiling is untested (`app/src/camera.ts` `MAX_ZOOM`).
- **RD-65** The camera moves on its own only for RD-62, RD-63, React Flow's own pan to a keyboard-focused Resource, and to fit a Resource reached by its product URL in view, with padding, once it is drawn. It never follows an Edit or an Open. *Why:* the author travels; a Resource reached by URL is somewhere the reader has never been. **built**: `app/test/canvas-continuation.test.tsx` › "focuses its Resource without waiting for the camera move to settle". The negative is untested.
- **RD-66** Double-click zoom is off on the whole canvas. *Why:* double click must mean one thing everywhere on the canvas. **built**: `app/e2e/editing.spec.ts` › "a click selects a Resource, and no pointer gesture on its body opens it" (a double click on a Resource leaves the viewport unchanged). Off the Resources (the empty pane) is untested.
- **RD-67** The wheel belongs to the canvas everywhere, Open content included: no Resource's content takes the wheel. *Why:* Open content must not become a hole in canvas panning. **built**: `app/test/space-resource-embedded-map.test.tsx` › "does not put nowheel on an Open Space Resource in portal Edit, and wheel still authors its framing". Open Markdown is untested (`ui/src/MarkdownResourceBody.tsx`).
- **RD-68** A camera command is issued and never awaited, chained on or caught. Work that must follow a move is scheduled by the effect that issued it and cancelled by its cleanup. *Why:* at the pinned release the Promise of a move interrupted by another never settles, and the only rejection is a real fault. **built**: `app/test/canvas-continuation.test.tsx` › "focuses its Resource without waiting for the camera move to settle"; `app/test/cameras.test.tsx` › "places the entered canvas from stored framing and the canvas size, not fitView".
- **RD-69** Each open Space has its own canvas and camera, and switching between open Spaces keeps each one's. *Why:* an entered Space is its own place. **built (untested)**: `app/src/open-spaces.ts` (one composition and canvas per Space).

## React Flow rules

- **RD-70** `@xyflow/react` is pinned to exactly 12.11.2 in both `app` and `react-flow-adapter`, and an upgrade moves both together. *Why:* RD-72 and RD-68 rest on behaviour verified against that release; the revalidation an upgrade needs is process (trace §3, PROC). **built (untested)**: `app/package.json`, `react-flow-adapter/package.json`.
- **RD-71** Only `react-flow-adapter` and `app` import React Flow. `core`, `graph`, `http`, `persistence`, `aggregate` and `ui` do not (for `ui`, see also UI-5). *Why:* the drawing stays out of the domain. **built (untested)**: enforced by `no-restricted-imports` in `eslint.config.js`.
- **RD-72** Handle geometry is declared from the rect the Map gives and never re-measured: nothing calls `useUpdateNodeInternals`. *Why:* a forced remeasure breaks handle resolution in the browser. **built**: `react-flow-adapter/test/ResourceNode.test.tsx` › "leaves the declared geometry alone when Opening the Resource moves its anchors"; `react-flow-adapter/test/projection.test.ts` › "declares four anchors of each role on the rim of the Resource's own box".
- **RD-73** A Resource's handles are distinguishable by side, with no two of one kind on one side. *Why:* React Flow's warning #008. **built**: `react-flow-adapter/test/projection.property.test.ts` › "gives a Resource no two handles of one kind on one side".
- **RD-74** A hidden handle uses `opacity: 0` or `visibility: hidden`, never `display: none`. *Why:* React Flow measures handles, and a `display: none` one reports 0×0. **built**: `app/e2e/overview.spec.ts` › "anchors stay measurable, so Edges attach where the Resource is".
- **RD-75** React Flow owns pointer attempts, transient node state and visual selection. Only a completed gesture reaches Space Authoring, and React Flow never applies a resize locally. *Why:* the domain sees authored facts, not frames. **built**: `app/test/SpaceCanvas.test.tsx` › "proposes no node change to React Flow while it resizes"; `app/test/render-adapter.test.ts` › "completes nothing for a connection Authoring refuses".
- **RD-76** React Flow's documented pointer, selection and focus behaviour is the default. A deviation needs a stated product requirement, recorded as a rule in this doc or ui.md. The keyboard deviations are in ui.md. *Why:* shaping the feature to the library is cheaper than reshaping the library. **built (untested)**: `app/src/components/SpaceCanvas.tsx`.
- **RD-77** Whether a Resource embeds a Map, and whether its content area draws above its Title, follow its resolved content, so a Reference Resource takes both from its Target. *Why:* the content decides its geometry, not the stored kind. **built**: `ui/test/CanvasResource.test.tsx` › "takes a Reference Resource’s content-area layout from its Target, including its Close fade"; `react-flow-adapter/test/ResourceNode.test.tsx` › "draws an Open Reference Resource to an Ur Resource as its Title alone, read-only".
- **RD-78** A drawn Resource draws no other Resource's or Space's name: neither a Reference Resource's Target nor a Space Resource's target Space is named on it. *Why:* the glyph and border tell them apart (RD-9, RD-10). **built (untested)**: `ui/src/CanvasResource.tsx`.

RD-77 and RD-78 belong with the Resources (RD-11); they are numbered here because ids are append-only.

## Cross-cutting effects

- **The drawing is the same everywhere a Map is drawn** (RD-19, RD-59, RD-81). Exceptions: one camera per canvas (RD-59); a framed drawn Map is placed by its framing (RD-60) and an unframed one by RD-5; only the canvas fits on opening (RD-62).
- **Graph colour reaches Resources, Edges, handles and the key together** (RD-23, RD-27, RD-30, RD-48, RD-51). Exceptions: the shadow, selection ring and resize marks stay ink (RD-27).
- **Emphasis follows the Active Graph** (RD-24, RD-29, RD-38–RD-40). Exceptions: nothing recedes while there is no Active Graph or it has no Edges (RD-26), and nothing stops short while no Graph is active (RD-40).
- **Nothing drawn is stored** (RD-34, RD-35, RD-50, RD-64). Exception: the wheel in a drawn Map being edited makes the Frame Edit (RD-61).
