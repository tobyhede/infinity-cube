**Terms** (definitions are in `CONTEXT.md`):
- **Canvas**: the React Flow surface that draws one Map of a Space. **Drawn Map**: a Map drawn inside an Open Space Resource.
- **Anchor**: one of a Resource's four Edge attachment points, one per side. **Handle**: an anchor offered as a place to start or end the Edge-drawing gesture.
- **Lane**: the path one of several Edges joining the same two Resources takes beside the others.
- **Recede**: draw at reduced strength while staying fully interactive.
- **Rect**: a Resource's drawn box: its stored position and its size (the Closed Size, 260×146, when none is stored).
- **Plugin**: the module that draws and authors one kind of Resource inside its rect (space-and-resources.md). **Host**: the application around it, which draws the rect, the border, the selection ring and the rail.
- **Outline**: the shape a plugin declares its Resource has inside its rect; the rectangle unless the plugin says otherwise.
- **Camera command**: one of React Flow's `setCenter`, `fitView`, `fitBounds` and `zoomTo`.

**Status:** **built** means code and a named test match the rule. **built (untested)** means code matches and no test covers it. **not built** means the rule is decided and no code implements it. **bug: code differs** means the code does what the note says instead. **undecided (Cn)** means the rule waits on conflict Cn; the note says what the code does meanwhile. A test is named as `file` › "test name". Paths that start with `test/` are at the repo root; all others are under `packages/`.

## Resources

- **RD-82** A Resource is drawn by its plugin, which owns everything inside its rect: its Title, its content and every way that content is authored. The host draws the rect, and on the plugin's outline draws the Resource's border and its selection ring, and applies receding (RD-24), for every plugin alike; no plugin draws its own border or ring. A plugin that declares it is drawn bare at rest draws no border while it is unselected and in no Graph. The host keeps no shared drawing of a Resource that a plugin fills a region of. *Why:* selection and Graph colour cannot be forgotten by a plugin, and no kind's differences accumulate in a frame every kind shares. **built**: `ui/test/PluginResource.test.tsx` › "draws the plugin's view, with the Title the host owns", "strokes the border and ring on a declared %s", "draws no outline for a rectangle, whose border is the rect", "draws a plugin bare at rest only while it is unselected and in no Graph".
- **RD-83** Each Resource is drawn inside its own failure boundary: a plugin that throws while drawing loses that Resource, and the canvas and every other Resource stay drawn. The throw is reported, and the plugin is drawn again once the Space is replaced or its Map content changes. On the Stage a plugin that throws draws a short note in its place. *Why:* one broken plugin must not cost the author the Map. **built**: `ui/test/PluginResource.test.tsx` › "loses only its own Resource when its plugin throws", "reports a throw to the reporter the surface was offered", "draws the plugin again once the Space is replaced or its Map content changes", "draws a short note in place of a plugin that throws".
- **RD-84** A Resource whose kind names no plugin in this build is drawn by the default plugin, on the Map, on the Stage and where a Reference Resource embeds it: its Title and a note that its kind is not available, offering no authoring of its content. *Why:* one Resource with a missing plugin must not make the Map unreadable. **built**: `ui/test/PluginResource.test.tsx` › "is drawn on the Map by the default plugin, given its stored kind", "is drawn on the Stage by the default plugin", "is drawn by the default plugin where a Reference embeds it as its Target"; `plugin-default/test/default-plugin.test.tsx` › "draws the Title and says the kind is not available, offering nothing".
- **RD-1** A Closed Resource draws its Title Lines, its border and, except on an Ur Resource, its kind glyph (RD-9), and no content. An Image Resource has no Closed face (RD-4). *Why:* a Closed Resource shows the shape of the Map; content is reached by Opening or presenting. **built**: `react-flow-adapter/test/projection.test.ts` › "maps resources to resource nodes carrying the title, not the content"; `app/ladle-e2e/resource.spec.ts` › "every Closed Resource draws its kind, its border and its Title Lines, and nothing beneath them"; `react-flow-adapter/test/ResourceNode.test.tsx` › "draws its title alone until the Map Opens it".
- **RD-2** An Open Resource draws its content inside its own rect, where it sits; an Open Markdown Resource draws it under its Title. The plugin draws Open and Closed in the one rect, with no second drawing for Open. Nothing covers the canvas, several Resources may be Open at once, and an Open Resource takes its rect with no aspect-ratio constraint. *Why:* reading in place keeps the Map in view. **built**: `react-flow-adapter/test/ResourceNode.test.tsx` › "draws the Resource's rendered Markdown on the Resource"; `app/e2e/overview.spec.ts` › "a resource shows its title in the graph, and opens to show rendered Markdown"; `app/ladle-e2e/resource-open.spec.ts` › "Open and Close retain one Resource and Title treatment".
- **RD-3** Opening or Closing changes what draws inside the rect and moves no Resource. The one exception is a size hint the canvas applies on an entry storing no size, which grows the rect and displaces as a Resize does (maps-and-graphs.md MG-88); Closing keeps that size. The camera is RD-65. *Why:* Open shows content; only a size change moves a rect (MG-26). **built**: `app/e2e/editing.spec.ts` › "Open and Close move nobody and keep the size, a Resize displaces once, and dragging never does", "Opening an unresized Markdown Resource grows it to its content, and Closing keeps that size".
- **RD-4** An Image Resource is its picture, Open or Closed alike: it has no Open, draws no Title (its Title names the picture for assistive technology), and draws the picture whole inside its rect at any size. *Why:* a Closed picture that still shows the picture is a distinction nobody can see. Other overflowing content is RD-5. **built**: `app/e2e/image-resource.spec.ts` › "an Image Resource draws its picture whole into its rect, bare at rest, at any size", "an Image Resource at the Closed Size draws its picture whole"; `app/ladle-e2e/resource-open.spec.ts` › "an Image Resource draws its picture whole into its rect, bare at rest and bordered when selected"; `plugin-image/test/image-plugin.test.tsx` › "is its picture, named by its Title, with no drawn Title and nothing offered when every capability is absent".
- **RD-5** Open content that does not fit its rect is clipped at the rect on the canvas. Markdown longer than its rect does not scroll. A drawn Map with no framing is placed at authored scale, zoom 1, with the top-left of its Resources (their least `x` and least `y`, read once when it is drawn) at the window's inner top-left; it is not shrunk to fit, and what lies past the window is clipped. To see more, the author resizes the Resource, or pans and zooms the drawn Map while its Space Resource is in Edit (RD-61). *Why:* the wheel belongs to the canvas (RD-67), so a scrolling body would be reachable only by its scrollbar, and the Closed Size is the one floor (MG-22), so no content asks for room beyond a size hint the canvas caps (MG-88). **built**: the drawn Map is placed by `embedCamera` (`app/src/space-resource-framing.ts`, used through `app/src/camera.ts` `spaceResourceEmbedCamera`): `app/test/space-resource-framing.test.ts` › "fits from the Map origin when nothing has been framed yet"; `app/test/embedded-map.test.ts` › "draws a Resource beyond the containing bounds where it was authored, clipped rather than moved". Clipping Markdown is untested (`ui/src/markdown-resource-body.css`, `overflow: hidden` on the rendered body).
- **RD-6** Open Markdown at rest draws through the same renderer the presenting Stage uses, which the host hands every plugin, and that renderer sanitises the Markdown before it is put on the page. *Why:* one source must not be interpreted by two pipelines, and content may come from any import. **built**: `ui/test/ResourceTextHost.test.tsx` › "draws a press target over rendered text only where the plugin offers an edit"; `ui/test/PresentedResource.test.tsx` › "strips event-handler attributes", "strips javascript: hrefs while keeping the link", "drops script and iframe elements entirely". That the canvas and the Stage share it holds by construction: both hand plugins `HostRenderedMarkdown` (`ui/src/ResourceTextHost.tsx`), which draws `ui/src/RenderedMarkdown.tsx`.
- **RD-7** An Image Resource draws a skeleton until its picture loads, and a picture the browser already holds draws at once. A picture that does not load draws a failed state that names its URL in its rect (that it is not a refusal is SR-27). *Why:* the author sees which picture is missing. **built**: `plugin-image/test/image-plugin.test.tsx` › "draws a skeleton until the picture loads, and names its URL when it does not", "draws a picture the browser already holds at once, with no skeleton"; `app/e2e/image-resource.spec.ts` › "an Image Resource whose picture does not load names its URL in its rect".
- **RD-8** removed (drafting rule 6).
- **RD-9** A Closed Resource draws its kind glyph, which its plugin draws, so the glyph follows the stored kind. An Ur Resource draws none in any Shape, and an Image Resource, always its picture, draws none. An Open Resource draws no glyph. *Why:* the glyph tells a Reference Resource from its Target; an Ur Resource's Shape says what it is. **built**: `plugin-markdown/test/markdown-plugin.test.tsx` › "draws its kind glyph, named for a screen reader, only while Closed"; `plugin-space/test/space-plugin.test.tsx` › "requests nothing while Closed, drawing its Title and glyph, and offers nothing with every capability absent"; `app/ladle-e2e/resource.spec.ts` › "every Closed Resource draws its kind, its border and its Title Lines, and nothing beneath them" (no glyph on the Ur Resource); `ui/test/PluginResource.test.tsx` › "draws a glyph that throws as nothing, and what it is drawn in survives".
- **RD-10** removed (drafting rule 6).
- **RD-11** An Open Reference Resource embeds its Target through the host's embedding, on a surface that offers no authoring of the Target, and passes its own Title and rename, so the Target's plugin draws the Reference's Title in place of the Target's and at most one Title draws. Closed, it draws its own Title and embeds nothing. A deleted Target draws a note, a Target that may not be one draws a note (references go one hop), and no Resource is ever drawn inside itself. *Why:* every kind is drawn by its own plugin, and the Reference shows what it points at. **built**: `ui/test/resource-embedding.test.tsx` › "draws its own Title once over a Markdown Target, offering no command of the Target", "draws its own Title alone when Closed, embedding nothing", "draws a note where its Target was deleted", "keeps referencing to one hop, drawing a note for a Target that may not be one", "never draws a Resource inside itself"; `react-flow-adapter/test/ResourceNode.test.tsx` › "draws an Open Reference Resource's Target Markdown read-only under the Reference Resource's Title, once".

## The Title ladder

- **RD-12** A Resource draws its Title as Title Lines: each line is its own block, and an interior blank line is kept. *Why:* the author's breaks carry meaning. **built**: `app/e2e/overview.spec.ts` › "a Resource whose author wrote more than one line draws its Title as Title Lines"; `app/ladle-e2e/resource.spec.ts` › "every Closed Resource draws its kind, its border and its Title Lines, and nothing beneath them". The interior blank line is tested only as data (`core/test/title.test.ts` › "keeps an interior blank line as a Title Line of its own"); drawn, it is untested.
- **RD-13** The ladder draws the same Open and Closed, on every kind. *Why:* a Title that changes shape on Open teaches that Opening edits it. **built**: `app/ladle-e2e/resource-open.spec.ts` › "Open and Close retain one Resource and Title treatment"; `react-flow-adapter/test/ResourceNode.test.tsx` › "keeps Opening and renaming independent, because one is authored and the other a gesture".
- **RD-14** A break the box chooses is not a rung. A line wraps within its own role, and clamping counts visual lines per role. *Why:* only authored breaks are load-bearing. **built**: `ui/test/canvas-resource-title-ladder.test.ts` › "clamp visual lines per role"; `app/ladle-e2e/resource.spec.ts` › "a wrapped single-line Title stays one rung while an authored three-line Title draws three".
- **RD-15** A Title too long for its room is clipped at a fixed ceiling chosen to fit a Closed Resource, the same Open and Closed. A Title never resizes a Resource. *Why:* placement is authored; resizing is how a long Title gets room. **built**: `ui/test/canvas-resource-title-room.test.tsx` › "fits inside the room a Closed $kind Resource leaves its Title"; `ui/test/canvas-resource-title-ladder.test.ts` › "is a clip on the heading, not a size the Resource grows to", "still clamps to three visual lines at the title role". The ceiling per Shape is a code note (trace §5).

## Shapes

- **RD-16** A Shape is drawn at the Resource's rect, at every size. Ellipse and diamond fill the rect proportionally, a pill's ends stay half-circles, and every Shape touches the midpoint of each side, so an Edge meets the outline. *Why:* Edges attach at side midpoints, whatever the Shape (MG-29, MG-32). **built**: `ui/test/resource-shape-outline.test.ts` › "draws every Shape touching the midpoint of every side of its rect, at any size", "rounds a pill by half its smaller side, at any size, so its ends stay half-circles"; `app/e2e/resource-shape.spec.ts` › "an Edge drawn to a Closed diamond meets its outline".
- **RD-17** In a Shape other than the rectangle, the Title is laid out in the rectangle inscribed in the Shape and draws the whole ladder, clipped as RD-15 says to the lines that rectangle holds. *Why:* the outline is not room for text. **built**: `ui/test/resource-shape-outline.test.ts` › "lays out the Title of every Shape in a rectangle inside the outline, at any size"; `app/ladle-e2e/resource.spec.ts` › "an Ur Resource draws each Shape at the Closed Size and resized, touching every side midpoint".
- **RD-18** A selected Resource in a Shape other than the rectangle draws a frame at its rect, which is where the resize control sits (ui.md); the frame is not drawn while the Resource is dragged. *Why:* the control needs a drawn corner. **built**: `react-flow-adapter/test/ResourceNode.test.tsx` › "frames a selected Shape at its rect with the resize control, and leaves the rectangle unframed".
- **RD-19** A drawn Map draws its Resources' Shapes as the canvas does. *Why:* one drawing serves every Map (RD-59). **built**: `app/e2e/space-resource.spec.ts` › "a Shape chosen inside an Open Space Resource is the target Map’s, drawn wherever it is".

## States, motion, colour and receding

- **RD-20** Rest, selected and dragging draw distinct treatments. *Why:* the author sees which Resource is selected and which is moving. **built**: `app/ladle-e2e/resource.spec.ts` › "rest, selected and dragging draw visually distinct treatments, for both kinds".
- **RD-21** While an Open Space Resource is dragged, its drawn Map moves with it as one rigid motion, and its Edges follow the moved positions. *Why:* the embedded Map stays aligned with its window. **built**: `app/test/embedded-map.test.ts` › "moves each embedded Resource rigidly about the dragged Resource rather than turning it in place", "leaves the Edges to React Flow, which draws them from the positions that moved".
- **RD-22** A Resource's position and size do not animate while it is dragged or resized. *Why:* the drawing must stay under the pointer. **built**: `app/ladle-e2e/resource-open.spec.ts` › "an active Resource resize does not animate its dimensions behind the pointer".
- **RD-23** A Resource's border is the Active Graph's colour when the Active Graph reaches it. Otherwise it is the colour of the first Graph, in the Map's order, that it is in, and ink when it is in none. "In a Graph" is MG-33. *Why:* a reader sees from a Resource which Graph it belongs to. **built**: `app/test/resource-graph-emphasis.test.ts` › "draws a Resource the Active Graph reaches in its colour, at full strength", "recedes any other Resource, drawn in the first Graph it is in", "draws a Resource in no Graph in ink, receding".
- **RD-24** A Resource the Active Graph does not reach recedes. Its face stays opaque, and it stays fully interactive. *Why:* the Active Graph's line is the narrative; nothing behind a Resource may show through it. **built**: `app/e2e/overview.spec.ts` › "a Resource is drawn in its Graph colour, and recedes off the Active Graph (ADR 0135)".
- **RD-25** A receding Resource draws at full strength while hovered, focused, selected, edited or offered as the end of a connection. *Why:* the Resource being worked on is never dim. **built**: `app/e2e/overview.spec.ts` › "a Resource is drawn in its Graph colour, and recedes off the Active Graph (ADR 0135)" (hover). The other states are untested (`app/src/styles.css`).
- **RD-26** Nothing recedes while there is no Active Graph or the Active Graph has no Edges. *Why:* Add Graph activates an empty Graph, and the Map must not dim on that gesture. **built**: `app/test/resource-graph-emphasis.test.ts` › "recedes nothing while the Active Graph has no Edges", "recedes nothing with no Active Graph".
- **RD-27** removed (drafting rule 6).
- **RD-28** removed (drafting rule 6).
- **RD-79** removed (drafting rule 6).
- **RD-80** Every text role a Resource draws on its own faces reads at WCAG AA at full strength. A receding Resource (RD-24) is below AA until it returns to full strength. *Why:* the Resource is light on a dark app, so a token that reads elsewhere can vanish here; receding is the point. **built**: `test/unit/canvas-resource-contrast.test.ts` › "reads at AA: $name".
- **RD-81** Every drawn Map applies RD-23–RD-26 by its own Active Graph. *Why:* each Map is read on its own terms. **built (untested)**: `app/src/canvas-projection.ts` (every drawing projects through it).

## Edges

- **RD-29** Every Graph the Map owns is drawn at all times. Activating a Graph is emphasis, never filtering: the other Graphs' Edges recede, and the Active Graph's Edges are painted last, on top. With no Active Graph every Graph draws at full strength. *Why:* a reader sees every narrative and which one is current. **built**: `react-flow-adapter/test/projection.test.ts` › "recedes the other graphs while one is active, never hiding them", "draws every graph the same when nothing is emphasised", "draws the Active Graph last, over the lanes it converges with"; `app/e2e/overview.spec.ts` › "selecting a graph emphasises it without hiding the others".
- **RD-30** An Edge draws in its Graph's colour. Which colour a Graph without one draws in is MG-48. *Why:* appearance is the Graph's (MG-66). **built**: `app/e2e/overview.spec.ts` › "draws every Graph in the selected Map, each in its own color".
- **RD-31** An Edge's render id is `<graphId>::<from>::<to>`, never its index, and its Title is no part of it. In a drawn Map, node and Edge ids also name the occurrence, while the Edge's subject stays the domain Edge. *Why:* an index-keyed id passes to the next Edge when one is removed; a retitled Edge must redraw the same element. **built**: `graph/test/graph-rendering.test.ts` › "leaves a surviving edge’s id unchanged when an earlier edge is removed", "carries an Edge Title and its hiding, and leaves the id to the endpoints"; `app/test/embedded-map.test.ts` › "gives two embeddings of the same Space distinct node and Edge identities", "keeps the domain Edge subject when a drawing rekeys its endpoints".
- **RD-32** Nothing routes an Edge. Each is React Flow's bezier between its two anchors (offset when in a lane, RD-41), and no drawing assumes the Graphs agree on an order, so a backward Edge is drawn like any other. *Why:* a Map stores positions only, and Graphs may order the same Resources oppositely (MG-36). **built**: `react-flow-adapter/test/RoutedEdge.test.tsx` › "draws the curve between the two anchors it attaches to".
- **RD-33** A Resource has four anchors, one at the midpoint of each side, and they are the same four handles the gesture uses. An Edge names no handle. Every Resource declares all four of each role, read-only and drawn-Map Resources included, and they are always rendered. *Why:* React Flow draws no Edge at all for a Resource whose handles it cannot resolve. **built**: `react-flow-adapter/test/projection.property.test.ts` › "declares the four anchors of each role on every Resource an Edge reaches", "leaves an Edge naming no handle at all"; `react-flow-adapter/test/ResourceNode.test.tsx` › "keeps the four anchors of each role on a read-only Resource".
- **RD-34** An Edge attaches on the sides that face each other. On each axis, the gap is the empty distance between the two rects, negative by the overlap when they overlap. The axis with the larger gap is used; equal gaps take the horizontal axis. On that axis, a target whose centre is past the source's leaves the source's right (or bottom) side and enters the target's left (or top), and one whose centre is short of it the reverse. Where the two centres are level on that axis, the other axis's centres decide in the same way, so an Edge and its reverse always face opposite ways; only centres that coincide take the right (or bottom). *Example:* a target whose left side is 100 units right of the source's right side, and whose top is 20 units below the source's top, has a horizontal gap of 100 and a negative vertical gap, so the Edge leaves the source's right side and enters the target's left. *Why:* large beside small is the normal state of a Map, and a centre-vector rule attaches such pairs across a Resource; a pair running both ways reads each direction's side from the side it leaves (RD-85). **built**: `react-flow-adapter/test/edge-attachment.test.ts` › "takes the horizontal axis when the two gaps are equal", "leaves the bottom when the two are level on the chosen axis", "faces the sides across the gap when a large Open Resource sits beside a collapsed one", "faces an Edge and its reverse opposite ways when the two are level on the chosen axis", "faces an Edge and its reverse opposite ways wherever their middles differ".
- **RD-35** The side is chosen from where the two Resources are now, so it is right during a drag, and it is never stored. An Edge's end lands on the outer rim of the anchor's handle. *Why:* a side chosen only at release crosses the Resource for the whole drag. **built**: `app/e2e/edge-attachment.spec.ts` › "the attachment follows the drag rather than waiting for the release"; `react-flow-adapter/test/RoutedEdge.test.tsx` › "attaches on the facing sides of where the two Resources are now"; `react-flow-adapter/test/edge-attachment.test.ts` › "sits on the outer rim of the handle declared on that side".
- **RD-36** A self-Edge draws a fixed loop from the right side to the top and never enters RD-34. *Why:* the facing rule draws a self-Edge's loop through its own Resource. **built**: `react-flow-adapter/test/edge-attachment.test.ts` › "loops between two adjacent sides of the one Resource"; `app/e2e/edge-attachment.spec.ts` › "a self-Edge draws a visible loop".

## Lanes

- **RD-37** Where several Edges join the same two Resources, from any Graphs and in either direction, each is drawn in its own lane. Lanes are parallel, never fanned by curvature, and no two Edges of one direction share a lane. *Why:* coincident lines read as one striped line; fanned ones read as different connections. **built**: `app/e2e/edge-attachment.spec.ts` › "several Graphs over one pair of Resources run as parallel lines, each ending in its own head"; `react-flow-adapter/test/edge-lanes.test.ts` › "never puts two Edges of one direction on the same lane", "lays out each pair on its own".
- **RD-38** Each direction of a pair is ranked on its own: the Active Graph's Edge first, then the other Graphs' Edges in the Map's Graph order, and with no Active Graph, Graph order alone. The first in each direction runs anchor to anchor, and each further one stops shorter at both ends than the one ranked before it, up to a fixed shortest length that every Edge past it shares. So exactly one Edge in each direction runs full length, and an Edge alone in its direction is full length whichever Graph is active. The shortening is cut in the geometry. How much each rank is shortened is a code note (trace §5). *Why:* the centre is where a connection is read, and length ranks a bundle without making a Resource the Active Graph does not reach look disconnected; a dash pattern would slide. **built**: `react-flow-adapter/test/edge-lanes.test.ts` › "runs exactly one Edge full length in each direction: the Active Graph’s, or the first in Graph order", "lays out %s"; `react-flow-adapter/test/projection.test.ts` › "carries the lane its Edge is given: the Active Graph centred, the rest beside it and shorter"; `react-flow-adapter/test/edge-lanes.test.ts` › "leaves a fifth of a level Edge undrawn at each end and keeps it level" (the cut in the geometry).
- **RD-39** In a pair running one way, the first Edge takes the centre line and the rest stack outwards on one side in rank order. The side is the screen's: below an Edge between left and right anchors, and right of one between top and bottom anchors, whichever way it travels. Activating another Graph moves the lanes, bringing its Edges to the centre, and a drag carries them. *Why:* a one-way pair already read correctly, so only its lengths follow the rank, and the Active Graph's Edge sits where a lone Edge would. **built**: `app/e2e/edge-attachment.spec.ts` › "a pair running one way puts the Active Graph on the centre, the rest stacked below and ranked shorter"; `react-flow-adapter/test/projection.test.ts` › "moves the centre to whichever Graph becomes active"; `react-flow-adapter/test/edge-lanes.test.ts` › "reads an offset as a side of the screen unless told otherwise".
- **RD-40** removed: superseded by RD-38, RD-85 and RD-86, which describe lanes laid out from the centre out. Only an Edge ranked after another in its direction stops short; an Edge outside the Active Graph alone in its direction runs full length.
- **RD-85** In a pair running both ways, each direction stacks on its own left of travel: its first Edge runs half a lane spacing from the centre, and each further one a spacing further out, so a rightward Edge sits above its reverse and a downward Edge to the screen's right of its reverse. Where the Active Graph runs the pair both ways, its two Edges share the centre line as one line with a head at each end, and each direction's other Edges stack outwards from it on that direction's left. Every other Edge of a direction stays clear of the Active Graph's head. The side is read from the side the Edge leaves as it is drawn, so it holds during a drag. *Why:* direction is read from the side, as on a road, and the Active Graph running both ways is one connection. **built**: `app/e2e/edge-attachment.spec.ts` › "a pair running both ways stacks each direction on its own left, the first in each direction full length"; `react-flow-adapter/test/edge-lanes.test.ts` › "lays out %s", "keeps every other Edge of a direction clear of the Active Graph’s head".
- **RD-86** Self-Edges on one Resource nest outwards from it: the Active Graph's innermost, then the rest in Graph order, their lengths ranked as any direction's are (RD-38). *Why:* loops are one direction of one pair. **built**: `app/e2e/edge-attachment.spec.ts` › "loops on one Resource nest outwards, the Active Graph’s innermost and full length"; `react-flow-adapter/test/edge-lanes.test.ts` › "lays out %s" (the three-loop cases).
- **RD-41** Each lane follows the lone Edge's curve at its lane's distance, measured square to the curve, over the middle of the curve, and joins its anchors with a short forward curve at each end. Lanes of one pair never cross. Where the curve turns too tightly for that, the pair's lanes are the lone curve shifted sideways along the anchors' sides. How the middle stretch is found is a code note (trace §5). *Why:* a sideways shift alone closes the gap where the curve turns. **built**: `react-flow-adapter/test/edge-lanes.test.ts` › "runs every point of a lane inside its span at its offset from the centre curve", "never runs a lane nearer its neighbour than the same lanes moved whole", "moves a lane between anchors level on the facing axis whole, along the sides".
- **RD-42** A lane starts and ends beside its anchors, moved along the side each sits on, and a self-Edge's lanes move each anchor along its own side away from the corner. The label sits at the lane's midpoint. *Why:* ends and heads land where the lane is. **built**: `react-flow-adapter/test/edge-lanes.test.ts` › "starts and ends a lane beside its anchors, on the side each sits on", "keeps a self-Edge’s lane anchors on the sides they sit on, away from the corner".

## Head shapes, Edge Titles and the Graph key

The Edge controls (focus, the Edit/eye/Delete group, its reveal on hover or selection, and Edge Title editing) are UI-78–UI-82.

- **RD-43** Every drawn Edge ends in its Graph's head shape at its drawn `to` end, Edges that stop short included, filled in the Graph's colour. *Why:* the head shape tells Graphs apart where colour cannot, and the receding Graphs are the ones that need it. **built**: `react-flow-adapter/test/projection.test.ts` › "ends every Edge in its Graph's head shape, the ones that stop short included".

Every canvas that draws Graph Edges mounts these markers. *Why:* one marker serves every Edge of a Graph at that size. **built**: `react-flow-adapter/test/GraphHeadMarkers.test.tsx` › "draws one marker per Graph, in its head shape and colour, under the id its Edges name", "draws a receding Graph's head small, under its own id, beside the Active Graph's full one"; `react-flow-adapter/test/projection.test.ts` › "names its Graph's one head marker as the Edge's end marker"; `ui/test/GraphHeadShape.test.tsx` › "draws the glyph as an SVG marker whose tip sits on the end of the line it ends".

- **RD-46** Only the Active Graph's Edges draw their Titles. At rest a Title is fitted to the room its Edge leaves, up to a ceiling, and draws nothing where that room cannot hold three characters and an ellipsis (`ui/src/edge-title-room.ts`). - **RD-47** A hidden Title draws nothing at rest and draws dimmed while its Edge is revealed (UI-79). - **RD-48** The canvas draws a key: the Space and Map identity, and every Graph on the Map with its legend mark, the Graphs that are not active dimmed. The same mark stands beside every Graph title in the key, the Dock's Graph choices and an Open Space Resource's Graph choices. *Why:* those lists are where a viewer matches a receding Edge's head to its Graph. **built**: `react-flow-adapter/test/GraphHud.test.tsx` › "ends each row’s mark in its Graph’s head shape, `arrow` where none is stored"; `app/e2e/overview.spec.ts` › "the Dock’s Graph rows draw the HUD key’s legend mark rather than a Graph glyph".

## Drawing an Edge, and the resize and move previews

The Edit a completed gesture makes is MG-62 and MG-63. The modifier key, Connect to Resource and what selects after a gesture are in ui.md.

- **RD-50** An Edge is drawn by dragging from one of a Resource's four handles and releasing on a Resource, the source included. The handles are the same for every Graph, and the side used is not stored. *Why:* drawing is spatial, and the Edge stores only its endpoints. **built**: `react-flow-adapter/test/ResourceNode.test.tsx` › "starts a drag from a source handle while no Edge is being drawn", "ends a drag on a target handle while an Edge is being drawn".
- **RD-51** The handles draw in the colour of the Graph the Edge will join, on every Resource, receding ones included: the Active Graph, or in a drawn Map the Graph it shows; with no Active Graph, the palette's first colour. *Why:* the result is visible before the drag begins. **built**: `react-flow-adapter/test/ResourceNode.test.tsx` › "shows four active-Graph-coloured spatial source handles on a selected Resource"; `app/test/canvas-projection.test.ts` › "colours the authoring handles as the Active Graph, and as the first slot without one".
- **RD-52** Source handles show on a hovered or selected Resource where Edges may be drawn, and not while it is dragged or resized. A Resource where they may not be drawn shows none. *Why:* a moving Resource has one gesture. **built**: `app/ladle-e2e/resource.spec.ts` › "hovering the real React Flow node reveals the adapter's Edge handles and none of the Resource's commands; selecting it draws them"; `app/e2e/editing.spec.ts` › "a Resource being moved draws neither its toolbar, its Edge handles nor its resize control, and offers them again on release"; `react-flow-adapter/test/ResourceNode.test.tsx` › "offers no affordance on a Resource the flow withholds connection from".
- **RD-53** During the drag, handles to end on show only on Resources within 80 canvas units of the pointer (distance to the Resource's bounds, zero over its body) that would accept the Edge. A Resource that would refuse it shows none and is not snapped to. The source is eligible when the pointer is near it. *Why:* showing a target the release would refuse misleads. **built**: `react-flow-adapter/test/connection-target-reveal.test.ts` › "requires seeking, proximity and eligibility together", "uses CONNECTION_TARGET_PROXIMITY as the default radius"; `react-flow-adapter/test/ResourceNode.test.tsx` › "withholds seeking ends when eligibility refuses the Resource", "withholds the seeking reveal when the pointer is not near the Resource".
- **RD-54** The connection preview draws in the colour and head shape of the Graph the Edge will join. *Why:* it previews the Edge as it will be drawn. **built**: `react-flow-adapter/test/GraphConnectionLine.test.tsx` › "ends the preview in the head shape it is given, in the stroke’s colour".
- **RD-55** Releasing on empty canvas cancels and changes nothing. With the modifier held (ui.md), a preview of the next Markdown Resource is drawn centred at the pointer, and release creates it (MG-63); a release over a Resource's body or off the canvas creates nothing. A connection target within React Flow's connection radius outranks the element under the pointer. *Why:* a missed target must not become an Edit, and a release near a handle aims at it. **built**: `app/e2e/new-space.spec.ts` › "Alt toggles a transient Resource 2 preview during an empty connection drag", "an Alt-drop released off the canvas creates no Resource"; `app/test/edge-authoring.test.ts` › "never authors a Resource unless every fact agrees", "lets a connection target in range outrank %s underneath".
- **RD-56** The gesture is cancelled, writing nothing, when the selected Map or the Active Graph changes, the Space is replaced (editing.md), presenting withdraws authoring, the canvas selects another Resource, or its source Resource leaves the drawing. An unrelated completed Edit leaves it standing. *Why:* a drag must not land in a context the author did not start it in. **built**: `app/test/edge-authoring.test.ts` › "cancels the draft when the selected Map changes", "cancels the draft when the Active Graph changes", "cancels the draft when a replacement Space is opened over it", "cancels the draft when presenting withdraws Edge authoring", "cancels a pointer connection when the canvas selects another Resource", "leaves the draft standing through an unrelated completed Edit". The Active Graph, replacement and unrelated-Edit cases are tested on a Title draft through the same invalidation pass (`edge-authoring.ts`); the source-leaves case is untested (`subjectSurvives`).
- **RD-57** A Resize previews only the resizing Resource's rect. Its neighbours stay where they are stored until the Edit lands (MG-24). *Why:* displacement is written by the Edit, not derived while drawing. **built**: `app/test/render-adapter.test.ts` › "previews the resizing Resource and nobody else, and completes only its final size".
- **RD-58** A move is React Flow's own drag. The canvas reports a completed move only at the drop, and none for a drag that returns to where it began; what the Move writes is MG-21 and MG-83. *Why:* only a finished gesture is a fact for the domain. **built**: `app/e2e/editing.spec.ts` › "a dragged resource stays where it is dropped, and nothing else moves"; `app/test/render-adapter.test.ts` › "completes no Edit for a drag that returns to where it began".

## Camera

- **RD-62** When a canvas first draws and has no stored framing to open on, it fits the Map in view with padding, never zooming past natural size, so a lone Resource is centred at natural size. *Why:* the origin is not a place anyone chose, and one Resource filling the screen reads as broken. **built**: `app/e2e/new-space.spec.ts` › "centres its first resource without animating it in from the canvas origin", "renders at natural size rather than filling the screen".
- **RD-63** A Space entered with a framing opens at that framing, sized from the canvas rather than the Space Resource, and is not fitted. *Why:* the author framed it. **built**: `app/test/cameras.test.tsx` › "places the entered canvas from stored framing and the canvas size, not fitView"; `app/test/space-resource-framing.test.ts` › "builds an entered viewport from the browser canvas size, not the source Resource".
- **RD-64** The author pans and zooms freely, up to 16× so one Resource can fill a large screen. A camera move is never an Edit and writes nothing. The minimap in the key pans and zooms the canvas; the zoom control is UI-96. *Why:* looking is not authoring. **built**: `react-flow-adapter/test/GraphHud.test.tsx` › "keeps the minimap panning and zooming the canvas". The ceiling is untested (`app/src/camera.ts` `MAX_ZOOM`).
- **RD-65** The camera moves on its own only for RD-62, RD-63, React Flow's own pan to a keyboard-focused Resource, and to fit a Resource reached by its product URL in view, with padding, once it is drawn. It never follows an Edit or an Open. *Why:* the author travels; a Resource reached by URL is somewhere the reader has never been. **built**: `app/test/canvas-continuation.test.tsx` › "focuses its Resource without waiting for the camera move to settle". - **RD-66** Double-click zoom is off on the whole canvas. *Why:* double click must mean one thing everywhere on the canvas. **built**: `app/e2e/editing.spec.ts` › "a click selects a Resource, and no pointer gesture on its body opens it" (a double click on a Resource leaves the viewport unchanged). - **RD-67** The wheel belongs to the canvas everywhere, Open content included: no Resource's content takes the wheel. - **RD-68** A camera command is issued and never awaited, chained on or caught. - **RD-69** Each open Space has its own canvas and camera, and switching between open Spaces keeps each one's. *Why:* an entered Space is its own place. **built (untested)**: `app/src/open-spaces.ts` (one composition and canvas per Space).

## React Flow rules

- **RD-70** `@xyflow/react` is pinned to exactly 12.11.2 in both `app` and `react-flow-adapter`, and an upgrade moves both together. *Why:* RD-72 and RD-68 rest on behaviour verified against that release; the revalidation an upgrade needs is process (trace §3, PROC). **built (untested)**: `app/package.json`, `react-flow-adapter/package.json`.
- **RD-71** Only `react-flow-adapter` and `app` import React Flow. `core`, `graph`, `http`, `persistence`, `aggregate`, `ui`, `resource-api` and every `plugin-*` package do not (for `ui`, see also UI-5). *Why:* the drawing stays out of the domain. **built (untested)**: enforced by `no-restricted-imports` in `eslint.config.js`.
- **RD-72** Handle geometry is declared from the rect the Map gives and never re-measured: nothing calls `useUpdateNodeInternals`. *Why:* a forced remeasure breaks handle resolution in the browser. **built**: `react-flow-adapter/test/ResourceNode.test.tsx` › "leaves the declared geometry alone when Opening the Resource moves its anchors"; `react-flow-adapter/test/projection.test.ts` › "declares four anchors of each role on the rim of the Resource's own box".
- **RD-73** A Resource's handles are distinguishable by side, with no two of one kind on one side. *Why:* React Flow's warning #008. **built**: `react-flow-adapter/test/projection.property.test.ts` › "gives a Resource no two handles of one kind on one side".
- **RD-74** A hidden handle uses `opacity: 0` or `visibility: hidden`, never `display: none`. *Why:* React Flow measures handles, and a `display: none` one reports 0×0. **built**: `app/e2e/overview.spec.ts` › "anchors stay measurable, so Edges attach where the Resource is".
- **RD-75** React Flow owns pointer attempts, transient node state and visual selection. Only a completed gesture reaches Space Authoring, and React Flow never applies a resize locally. *Why:* the domain sees authored facts, not frames. **built**: `app/test/SpaceCanvas.test.tsx` › "proposes no node change to React Flow while it resizes"; `app/test/render-adapter.test.ts` › "completes nothing for a connection Authoring refuses".
- **RD-76** React Flow's documented pointer, selection and focus behaviour is the default. A deviation needs a stated product requirement, recorded as a rule in this doc or ui.md. The keyboard deviations are in ui.md. *Why:* shaping the feature to the library is cheaper than reshaping the library. **built (untested)**: `app/src/components/SpaceCanvas.tsx`.
- **RD-77** An Open Reference Resource is drawn as its Target is drawn, by its Target's plugin, with no authoring of the Target: a Reference to an Image Resource is that picture, named by the Reference and offering no Replace; a Reference to an Ur Resource is its Title alone; a Reference to a Space Resource draws the Map that Space Resource shows. *Why:* the content decides what is drawn, not the stored kind. **built**: `react-flow-adapter/test/ResourceNode.test.tsx` › "draws an Open Reference Resource to an Image Resource as its Target's picture, named by the Reference, with no Replace", "draws an Open Reference Resource to an Ur Resource as its Title alone, read-only"; `app/test/space-resource-embedded-map.test.tsx` › "draws the Map a Reference to a Space Resource shows, offering no authoring of it".
- **RD-78** A drawn Resource draws no other Resource's or Space's name: neither a Reference Resource's Target nor a Space Resource's target Space is named on it. *Why:* the glyph tells them apart (RD-9). **built**: `ui/test/resource-embedding.test.tsx` › "draws its own Title once over a Markdown Target, offering no command of the Target" (the Target's Title is not drawn). That a Space Resource does not name its target Space is untested (`plugin-space/src/view.tsx`).

RD-77 and RD-78 belong with the Resources (RD-11); they are numbered here because ids are append-only.

## Cross-cutting effects

- **The drawing is the same everywhere a Map is drawn** (RD-19, RD-59, RD-81). Exceptions: one camera per canvas (RD-59); a framed drawn Map is placed by its framing (RD-60) and an unframed one by RD-5; only the canvas fits on opening (RD-62).
- **Graph colour reaches Resources, Edges, handles and the key together** (RD-23, RD-30, RD-48, RD-51).
- **Emphasis follows the Active Graph** (RD-24, RD-29, RD-38, RD-39, RD-85, RD-86). Exceptions: nothing recedes while there is no Active Graph or it has no Edges (RD-26), and with no Active Graph, Graph order alone ranks each direction of a pair (RD-38).
- **The host draws around every Resource the same way** (RD-82): border, ring and receding on the plugin's outline. Exceptions: a plugin drawn bare at rest draws no border while unselected and in no Graph (RD-82), and a Resource whose plugin throws is not drawn (RD-83).
- **Nothing drawn is stored** (RD-34, RD-35, RD-50, RD-64). Exception: panning or zooming a drawn Map in Edit makes the Frame Edit (RD-61).
