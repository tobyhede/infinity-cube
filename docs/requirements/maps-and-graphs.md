# Maps and Graphs

**Purpose:** what Maps, Map entries, Graphs and Edges hold, and what each Edit does to them.

**Terms** (definitions are in `CONTEXT.md`):
- **Working Space**: a Space opened for authoring. A **working read** loads one.
- **Intake**: the validation every stored or imported Space passes before it loads.
- **Unchanged** and **refused**: an attempt that produces no Edit. An unchanged attempt is silent. A refused attempt carries a refusal code.
- **Canvas Map**: the Map a Space's own canvas draws. For example, renaming the selected Map from the Dock is an Edit through the canvas Map.
- **Drawn Map**: a Map drawn inside an Open Space Resource and edited in its own (target) Space. For example, moving a Resource inside the Map an Open Space Resource shows is an Edit through a drawn Map.
- **Space Resource**: a Resource that shows another Space's Map and Graph (its selection), optionally with a **framing** (a saved camera).
- **Saved Active Graph**: the Map's stored `activeGraph`.
- **Starting Map**: a Map with no entries that owns one empty Graph, which is its Active Graph. At a first working read the Map is titled `Map 1` and its Graph `Graph 1`. From Add Map the Map is titled `Map N` (MG-10) and its Graph `Graph 1` (MG-42).
- **Closed Size**: 260×146.
- **Map content**: what a Resource's plugin keeps for it on one Map, stored in the Map entry beside the canvas's position and size. Markdown, Reference and Space Resources keep whether they are Open; an Ur Resource keeps its Shape; an Image Resource keeps nothing. Which plugin draws a kind is in space-and-resources.md.
- **Size hint**: a size a plugin asks for with a Map content Edit made on an author's gesture. The canvas decides whether and how far it applies (MG-88).

**Status:** **built** means code and a named test match the rule. **built (untested)** means code matches and no test covers it. **not built** means the rule is decided and no code implements it. **bug: code differs** means the code does what the note says instead. **undecided (Cn)** means the rule waits on conflict Cn (none is open in this doc). A test is named as `file` › "test name". Paths that start with `test/` are at the repo root; all others are under `packages/`.

## Operations index

Every completion first asks the exclusive gate (editing.md ED-82), then runs the guards in editing.md (ED-19 to ED-21): for example, `map-not-found` when the Map it writes has gone, and `graph-not-owned` for a drawing whose Graph has gone. "Checks, in order" then lists the Edit's own checks. The first failure is the answer, and "⇒ unchanged" marks where an unchanged result is decided. Delete Map and Delete Graph are coordinated Edits and run no guards (ED-23).

| Edit | Effect | Checks, in order | Rules |
|---|---|---|---|
| Add Map | appends a starting Map, makes it `defaultMap` and selects it (from an Open Space Resource: MG-11) | none | MG-9–MG-11 |
| Delete Map | removes the Map and its Graphs, and repoints Space Resources | last Map ⇒ unchanged | MG-12–MG-15 |
| Rename Map | writes the title | `map-not-found` (the completion names another Map than the one resolved: an action check, not the guard) → `map-title-required` → same trimmed title ⇒ unchanged | MG-8 |
| Rename Graph | writes the title | `graph-not-owned` → `graph-title-required` → same trimmed title ⇒ unchanged | MG-8 |
| Add to Map | writes a position | `resource-not-found` → `resource-already-in-map` | MG-16–MG-18 |
| Remove from Map | removes the entry and incident Edges | `resource-not-in-map` | MG-19 |
| Delete from Space | Remove from Map in every Map | see space-and-resources.md | MG-20 |
| Move | writes drop points | no position changes ⇒ unchanged (bug: MG-83) | MG-21, MG-83 |
| Resize | writes size and displaces | `resource-not-in-map` → same drawn size ⇒ unchanged | MG-23–MG-26, MG-82 |
| Change Map content (a plugin's commit: Open, Close, Choose Shape) | writes the entry's Map content; with a size hint on an entry storing no size, also a size and displacement | `resource-not-in-map` → `resource-not-found` → `map-content-invalid` → the value the plugin is already given there ⇒ unchanged | MG-27–MG-31, MG-86–MG-88 |
| Add Graph | appends an empty Graph and activates it | none | MG-41–MG-42, MG-85 |
| Switch Graph | writes `activeGraph` (bug: MG-45) | already the saved Active Graph ⇒ unchanged (MG-84) | MG-45–MG-47, MG-84 |
| Recolour | writes `color` | `graph-not-owned` → same drawn colour ⇒ unchanged (bug: MG-49) | MG-49 |
| Choose head shape | writes `headShape` | `graph-not-owned` → same drawn head shape ⇒ unchanged | MG-51 |
| Delete Graph | removes the Graph, and repoints Space Resources | last Graph ⇒ unchanged | MG-52–MG-56 |

| Title Edge | writes or clears `title` | `graph-not-owned` → `edge-not-found` → `edge-title-one-line` (on the raw draft) → trimmed draft equals the stored Title, or is empty on an untitled Edge ⇒ unchanged | MG-64 |

| Auto-arrange | rewrites a Map's positions | — | MG-71 (not built) |

## Maps and membership

- **MG-1** A Space owns its Maps. Each Map has an id, a title, one entry per member Resource, and its Graphs. *Why:* a Map is an authored diagram and part of what the Space is. **built**: `graph/test/space-intake.test.ts` › "accepts two maps owning distinct graphs over the same resources".
- **MG-2** A Map id is unique within its Space. Intake refuses a repeat (`duplicate-map-id`). *Why:* lookup would otherwise collapse two Maps into one. **built**: `graph/test/space-intake.test.ts` › "refuses duplicate map ids, which the lookup would silently collapse".
- **MG-3** A Map's members are exactly its entry keys. A Resource with no entry is not in the Map and is not drawn there, and a missing entry never means the origin. *Why:* membership and position are one fact. **built**: `graph/test/space-intake.test.ts` › "accepts a map that omits resources — a resource it leaves out is not in it"; `graph/test/positioned.test.ts` › "omits resources the authored placement omits".
- **MG-4** An entry may not name a Resource the Space lacks (`map-member-missing-resource`). *Why:* a position must belong to something. **built**: `graph/test/space-intake.test.ts` › "says only that a position names a missing resource, not that edges into it dangle".
- **MG-5** A Resource has at most one entry per Map and no placement stored on itself. It may be absent from one Map and have a different position, size and Map content (so Open state and Shape) in each Map that contains it. *Why:* placement is the diagram's notation. Content shown twice is a Reference Resource (see space-and-resources.md). **built**: `graph/test/snapshot-edits.property.test.ts` › "removes a Resource from the one Map only, with every Edge incident to it there".
- **MG-6** The canvas draws one Map and only the Graphs that Map owns. *Why:* nothing is drawn that no Map authored. **built**: `app/test/canvas-projection.test.ts` › "draws every Graph a selected Map owns", "draws no Edge of a Graph a sibling Map owns".
- **MG-7** A working Space always has a `defaultMap` naming one of its Maps. Intake refuses one that names no Map (`unresolved-default-map`). *Why:* a Space must always have a durable place to open. **built**: `graph/test/space-intake.test.ts` › "refuses a defaultMap naming no declared Map".
- **MG-8** A Map title and a Graph title are each one non-empty, trimmed line. A blank rename is refused (`map-title-required`, `graph-title-required`). Renaming to the same trimmed title is unchanged. *Why:* these titles are single-line names. **bug: code differs**: authoring trims and refuses a blank title, but neither authoring nor intake refuses a line break, and intake accepts an untrimmed title or one made only of spaces (`z.string().min(1)`): `app/test/space-authoring-operations.test.ts` › "refuses a blank title and treats the stored title with padding as unchanged".

## Add Map

- **MG-9** Add Map is one Edit on a Space's own canvas. It appends a starting Map, makes it that Space's `defaultMap` and selects it there. From an Open Space Resource it is MG-11. The canvas continues on the new Map (navigation.md NV-7). *Why:* an empty Map is the way into manual authoring, and creating a Map decides where the canvas continues. **built**: `app/test/space-authoring-operations.test.ts` › "creates and selects an empty Map with one empty Active Graph".
- **MG-10** A new Map is titled `Map N`, where N is one above the highest `Map N` in the Space. *Why:* a neutral name the author can change. **built**: `app/test/titles.test.ts` › "numbers Maps and Graphs on their own titles", "takes one past the highest number already in use".
- **MG-11** Add Map invoked from an Open Space Resource is a drawn Edit of the target Space. It asks guard 1 against nothing, because it writes no existing Map (editing.md ED-20). It appends a starting Map in the target and leaves the target's `defaultMap` and canvas alone, and the Space Resource is then repointed at the new Map and its Graph (see space-and-resources.md). *Why:* only a canvas Edit records where the author is working. **bug: code differs**: the code completes it as a canvas Edit in the target Space, so it sets the target's `defaultMap`, and the drawn Edit target cannot carry it at all (`app/test/edit-target.test.ts` › "takes a Map lifecycle Edit from the canvas alone"): `app/test/map-authoring-commands.test.ts` › "points the embedding Space Resource at the created Map once both Spaces have saved".

## Delete Map

- **MG-12** Delete Map removes the Map and every Graph it owns. The Resources it placed stay in the Space. *Why:* Resources belong to the Space, not to a Map. **built**: `app/test/map-authoring-commands.test.ts` › "deletes the Map, repoints every Space Resource that selected it and continues on the survivor".
- **MG-13** The last Map cannot be deleted: a deletion of it answers unchanged, with no refusal code. Whether the command is offered is in ui.md. *Why:* MG-7. **built**: `persistence/test/space-resource-lifecycle.test.ts` › "update: deleting the only Map is unchanged before any read or commit".
- **MG-14** Delete Map leaves `defaultMap` where it is if that Map survives. Otherwise the first surviving Map in list order becomes `defaultMap`. The canvas continues on `defaultMap` (navigation.md NV-7). *Why:* the opening Map changes only when it has to, and the same way in every context. **bug: code differs**: on the Space's own canvas the code complies, because the deleted Map is the one shown. From an Open Space Resource, when the deleted Map is `defaultMap`, the code moves `defaultMap` to the Map the target Space's canvas shows, if that survives, instead of the first survivor: `app/test/map-authoring-commands.test.ts` › "continues on the Space’s opening Map, where the Resources that selected the deleted Map go too"; `app/src/map-authoring-commands.ts` `preferredSurvivor`.
- **MG-15** Every Space Resource, in any Space, that selects the deleted Map moves in the same Edit to the surviving Map (MG-14) and that Map's Active Graph, and loses its framing. Selection itself is in space-and-resources.md. *Why:* no selection may dangle. **built**: `persistence/test/space-resource-planning.test.ts` › "moves every Space Resource selecting a deleted Map to the successor, and the default with it"; `core/test/space-selection.test.ts` › "drops the framing when the Map changes, since it was the old Map's".

## Add to Map, Remove, Delete, Move

- **MG-16** Add to Map gives a Resource the Space holds an entry in one Map, holding a position only: no size, no Map content (so its plugin's default: Closed, and the rectangle) and no Edges. Re-adding a removed Resource restores none of its old size, Map content or Edges. A Resource already in the Map is refused (`resource-already-in-map`). *Why:* a fresh entry is the simplest thing to explain. **built**: `graph/test/placement.test.ts` › "writes an entry as given, storing no state, size or Map content it was not given"; `app/test/space-authoring-operations.test.ts` › "forgets the Shape with the rest of the entry, so Add to Map stores none again"; `graph/test/snapshot-edits.property.test.ts` › "refuses a Map, a Resource or a membership it cannot add, changing nothing".
- **MG-17** A position aimed at a dropped point is kept exactly, even when another Resource occupies it. *Why:* the author chose the point. **built**: `graph/test/snapshot-edits.property.test.ts` › "keeps an exact point as aimed, even one another Resource occupies".
- **MG-18** A position from a menu, which has no aimed point, steps off any point another Resource occupies. *Why:* Resources created from a menu would otherwise stack exactly. **built**: `graph/test/snapshot-edits.property.test.ts` › "never lands avoidingOverlap on a point another Resource already occupies".
- **MG-19** Remove from Map is one Edit. It removes the Resource's whole entry in that Map (position, size and Map content) and every Edge touching the Resource in every Graph of that Map, with those Edges' Titles. Displacement an earlier Resize caused is not undone. Graphs left empty remain, and the Resource stays in the Space and in every other Map; removed from its last Map, it stays in the Space, placed nowhere. Whether the author is asked first is UI-85. *Why:* an Edge joins members only (MG-58). **built**: `graph/test/snapshot-edits.property.test.ts` › "removes a Resource from the one Map only, with every Edge incident to it there", "moves no other Resource when it removes or deletes a resized one".
- **MG-20** Deleting a Resource from the Space applies Remove from Map in every Map. When a deletion is refused is in space-and-resources.md. *Why:* a deleted Resource can be no Map's member. **built**: `graph/test/snapshot-edits.property.test.ts` › "names exactly the Maps and Graphs Delete from Space changes".
- **MG-21** Move writes each drop point exactly as the Resource's position and keeps its size and Map content. Between Edits, the drawn position is the stored one. *Why:* positions are authored, and a conversion at render misplaces drops. **built**: `graph/test/placement.test.ts` › "preserves a Resource size and Map content when the renderer reports only its moved position", "authors a drop on top of a resized Resource exactly where it was released".

## Size and displacement

- **MG-22** An entry's size is optional, and with none stored the Resource is the Closed Size. No size is below the Closed Size on either axis for any kind, Open or Closed, and intake refuses one that is. No kind has a size of its own, and no Edit writes a size on a Resource's behalf except a plugin's size hint, which the canvas floors, caps and applies or ignores (MG-88). *Why:* one floor for every kind, and the canvas keeps the veto over every rect. What Open content draws when it does not fit is rendering.md RD-5. **built**: `graph/test/space-intake.test.ts` › "loads an entry with no size stored"; `core/test/schema.test.ts` › "reads an entry with none as the Closed Size", "refuses a size below the Closed Size on either axis".
- **MG-23** Resize writes a new size on a Resource of any kind, Open or Closed, and keeps its Map content. Resizing to the size it already draws at is unchanged, so resizing an entry that stores no size to the Closed Size is unchanged. A Resize back to the Closed Size leaves an Open Resource Open. *Why:* a bigger Resource is one gesture, and Closing is never a side effect of a size. **built**: `graph/test/snapshot-edits.property.test.ts` › "resizes, writing the size and keeping Map content and every Edge", "answers unchanged for a Resize to the Closed Size of an entry storing none"; `app/test/space-authoring-operations.test.ts` › "stays Open when resized back to the Closed Size".
- **MG-24** Let the subject sit at (sx, sy) with size (w, h) before the Resize, and change by (Δw, Δh). For every other Resource at (x, y):
  - if `x ≥ sx + w`, it moves by Δw on `x` only;
  - otherwise, if `y ≥ sy + h`, it moves by Δh on `y` only;
  - otherwise it does not move.

  The test on one axis ignores the other, so a Resource left of or above the subject never moves, and the subject itself never moves. This happens in the same Edit.

  *Example:* the subject at (0, 0), 260×146, grows to 400×200 (Δw = 140, Δh = 54). A at (300, 0) moves to (440, 0). B at (0, 200) moves to (0, 254). C at (300, 300) moves to (440, 300) (`x` wins). D at (100, 100) and E at (−300, 0) stay put.

  *Why:* one axis is enough to stay clear, and testing `x` first keeps a Resource beside the subject from moving vertically. **built**: `graph/test/placement.test.ts` › "moves each Resource on one axis, x first", "moves a Resource exactly on the bottom edge, and leaves one unit short of it", "never moves the subject, whatever the change".
- **MG-25** A Resize reads the Map as it is now and records nothing about what it pushed. A grow followed by the shrink back restores every position; a shrink followed by a grow need not. *Why:* per-Resize history goes stale, and two identical Maps would behave differently. **built**: `graph/test/placement.test.ts` › "restores every position on the shrink back", "is not an involution when the shrink comes first".
- **MG-26** Only a size change moves another Resource: a Resize, or a Map content Edit whose size hint is applied (MG-88). Only those two change a size, and one of them may move many. *Why:* displacement written by the Edit that causes it keeps every position authored. **built**: `graph/test/snapshot-edits.property.test.ts` › "moves no other Resource when it removes or deletes a resized one", "applies a Map content Edit’s size hint as a Resize does, floored at the Closed Size".
- **MG-82** A Resize below the Closed Size never reaches the domain; the control's floor is ui.md UI-68. An Edit that asked for less would fail intake inside authoring and throw as a defect, not refuse. *Why:* MG-22 is a floor, not a request to check. **built**: `app/test/canvas-resource-decoration.test.ts` › "offers resize on every kind, Open or Closed, where the Map may be authored" (the control's minimum is the Closed Size). The throw is untested (`app/src/space-authoring.ts` `assertValidAuthoredSnapshot`).

## Map content, Open and Close

- **MG-86** A Map entry may hold its plugin's Map content, and holds nothing else beside the canvas's `x`, `y` and `size`. With none stored the plugin is given the default it declares, and on a surface with no Map it is given its own declared value, so an absent value never tells a plugin where it is. Intake refuses Map content the Resource's plugin's schema rejects (`map-content-invalid`), and refuses an entry storing `open` or `shape`, which are no longer entry keys. The Map content of a Resource whose kind names no plugin in this build is kept as it is, unread (space-and-resources.md). *Why:* the canvas owns the rect, and the plugin owns what it keeps per Map. **built**: `core/test/schema.test.ts` › "keeps any JSON value as Map content, at any size, leaving its meaning to the plugin", "refuses a value JSON cannot carry, and the retired shape and open keys"; `graph/test/space-intake.test.ts` › "loads a %s Resource with no Map content stored", "refuses Ur Map content its plugin refuses, naming the entry".
- **MG-87** Change Map content is one Edit. It is how a plugin commits its own Map content, on its own Resource, through Space Authoring, and it writes only that entry's `content` and, under MG-88, its size and the displacement that size causes. A plugin never writes a position, a size or an Edge. Content the plugin's schema rejects is refused (`map-content-invalid`), and the value the plugin is already given there, its default included, is unchanged. *Why:* a plugin owns what it keeps, and the canvas owns every rect. **built**: `graph/test/snapshot-edits.property.test.ts` › "changes one Resource's Map content and nothing else, and the content it has is unchanged", "keeps the Map content its plugin accepts and refuses what it refuses, whichever plugin it is"; `app/test/space-authoring-operations.test.ts` › "refuses Map content the plugin refuses, changing nothing", "is unchanged for the plugin's default on an entry that stores none".
- **MG-88** A Map content Edit made on an author's gesture may carry a size hint, and a plugin asks once per gesture. The canvas caps the hint at the visible canvas at the current zoom, less a margin; a hint the cap narrows grows taller to keep its area, up to the cap's height. A hint the canvas cannot cap is dropped. The Edit then floors the hint at the Closed Size and applies it as a Resize, moving the Resources its growth passes (MG-24), in that one Edit. On an entry that already stores a size, or when the Map content is unchanged, the hint is ignored. *Why:* opening a long document at the Closed Size draws two cramped lines, and the canvas keeps the veto over every rect. **built**: `graph/test/snapshot-edits.property.test.ts` › "applies a Map content Edit’s size hint as a Resize does, floored at the Closed Size", "ignores a size hint on an entry that already stores a size, and on content that is unchanged"; `app/test/app-derivations.test.ts` › "grows a hint the cap narrows taller, so text reflowed at the narrower width still fits", "never grows a hint past the cap’s height"; `app/test/plugin-host.test.ts` › "carries a size hint capped at what the canvas shows, and drops one it cannot cap"; `app/e2e/editing.spec.ts` › "Opening an unresized Markdown Resource grows it to its content, and Closing keeps that size".
- **MG-27** Open and Closed belong to the plugins that keep them, as Map content `{ open }`: Markdown, Reference and Space. Each is Closed where a Map stores nothing and Open where there is no Map. Opening and Closing are those plugins' Change Map content Edits: a Markdown Resource Opens with a size hint (MG-88), and a Reference or Space Resource Opens with none. Opening an Open Resource, or Closing a Closed one, is unchanged. The application has no Open or Close Edit of its own and opens no Resource itself. Which Resources are Open survives reload and export. *Why:* which Resources are Open is part of the diagram, and only the plugin knows what Open means for its content. **built**: `plugin-markdown/test/markdown-plugin.test.tsx` › "is Closed where a Map stores nothing, Open where there is no Map, and starts as the empty asset", "Opens with one Map content commit carrying a size hint at least the reading width"; `plugin-reference/test/reference-plugin.test.tsx` › "Opens and Closes through its Map content, with no size hint"; `plugin-space/test/space-plugin.test.tsx` › "Opens and Closes through its Map content"; `app/test/space-authoring-operations.test.ts` › "Opens and Closes a Space Resource changing nothing but its Map content".
- **MG-28** An Image Resource and an Ur Resource have no Open. An Image Resource keeps no Map content, and an Ur Resource keeps only its Shape (MG-29). A Map content Edit that asks either to be Open is refused (`map-content-invalid`), and intake refuses an entry storing one Open with the same code. *Why:* an Image Resource is always its picture, and an Ur Resource has no content to show. **built**: `app/test/space-authoring-operations.test.ts` › "refuses Open as an Ur Resource’s Map content, which its plugin does not take", "refuses Map content an Image Resource’s plugin does not keep"; `graph/test/space-intake.test.ts` › "refuses Ur Map content its plugin refuses, naming the entry".

## Shape

- **MG-29** A Shape is one of rectangle, pill, ellipse or diamond. It is the Ur plugin's Map content, stored in the entry and never on the Resource. It is optional, and an entry with none is the rectangle, which is also the Shape where there is no Map. Every Shape touches the midpoint of each side of its rect. *Why:* Shape is diagram notation, and Edges attach at the side midpoints. **built**: `plugin-ur/test/ur-plugin.test.tsx` › "keeps a Shape per Map, rectangular where a Map stores none and where there is no Map"; `graph/test/placement.test.ts` › "keeps the Map content of a whole entry it is given".
- **MG-30** Only an Ur Resource takes a Shape. The principle: **an Edit on the canvas records where the author is working, and nothing else does.** Each cell gives `defaultMap` / `activeGraph`. ✓ means the field is written with the canvas Map (or, for `activeGraph`, the Graph the canvas shows). ✗ means the field is left alone. — means there is nothing to write, because the Map is gone. A rule id means that rule gives the value. Every cell is decided; the code's departures are listed under Bugs.

| Edit | Canvas Edit writes | Drawn Edit writes |
|---|---|---|
| Any Edit with a change of its own (Move, Resize, Change Map content (Open, Close, Shape), Add to Map, Remove, Delete from Space, Resource renames and content commits, Map and Graph renames, Recolour, head shape, Edges) | ✓ / ✓ | ✗ / ✗ |
| An Edit whose own change is nothing (MG-83) | ✗ / ✗ | ✗ / ✗ |

| Switch Graph | ✓ / ✓ (MG-45, MG-46); to the saved Active Graph ✗ / ✗ (MG-84) | ✗ / ✗ (it writes the Space Resource's selection: MG-47) |
| Delete Map | ✓ (the survivor, MG-14) / — | MG-14 / — |
| Delete Graph | ✓ (MG-81) / MG-54 | ✗ / MG-54 |
| Rename Space | ✗ / ✗ | ✗ / ✗ |
