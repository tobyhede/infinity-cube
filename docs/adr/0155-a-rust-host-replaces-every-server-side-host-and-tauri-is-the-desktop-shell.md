# The desktop application ships on a Node host in a Tauri shell, and a Rust host then replaces every server-side host

Status: accepted
Date: 2026-11-18
Refines: 0030, 0034, 0095, 0117, 0119, 0124
Refined by: 0165, 0167, 0172
Related: 0071, 0078, 0109, 0130, 0141, 0156, 0157

InfinityCube is to be installed and run by presenters who are not its developers: a desktop application they download, open an Aggregate directory in, and edit. Today every server-side host is TypeScript on Node 26.8.1 (ADR 0071), and Running serves through Vite's development server, so it needs a clone of the repository, Node and pnpm. ADR 0034 already makes the HTTP application Fetch-native and calls the Node and Vite wiring "prototype composition, not architectural constraints". The maintainer decided on 16 November 2026 to move the server side to Rust and to ship the desktop application with Tauri, and on 17 November 2026 that the desktop application ships first on the existing Node host rather than waiting for Rust: working code before the port. The research behind this is `.scratch/desktop-app/research.md`; the plan is `.scratch/rust-host/spec.md`.

## The decision

- **The desktop application ships first on the Node host, as a Tauri sidecar.** A production Node host (no Vite) serves the Fetch application, the product addresses and the built static files; it is compiled to a single Node 26 binary per platform and started by the Tauri shell, one sidecar per window. It listens on `127.0.0.1` only, on a random port, refuses any request whose `Host` is not that address, and requires a secret minted at each launch that the shell passes to its window. The shell stops it by closing its standard input, on which it Exports and exits, and kills it after five seconds. macOS on Apple Silicon is the first platform. When the Rust host passes the conformance suite (ADR 0156) it replaces the sidecar inside the same shell, served through a custom URI scheme with no port, and the browser application does not change.
- **One Rust host serves the HTTP contract the TypeScript host serves, unchanged on the wire.** Every route under `/api` and `/assets`, the product addresses (`/` and `/spaces/…`) answered before the shell, the single-page fallback, the transport policy and the Problem Details catalogue are the same requests answered with the same statuses, bodies and headers. The browser, its typed client and the Mount build do not change.
- **It replaces every server-side host, in stages.** Running and `check` first; then SQLite; then PostgreSQL; then the remaining CLI verbs (`init`, `import`, `export`) and the MCP server. When the last stage lands the TypeScript server is retired. TypeScript remains the language of the browser application and of Mounting, which runs its host inside the page (ADR 0130). No TypeScript server-side host is added beyond the production Node host of the first stage, which other TypeScript hosts (the standalone HTTP host) may adopt. Whether an agent authors a running aggregate over the network (proposed ADR 0141) is not decided here.
- **The host is a library behind a storage trait.** A Rust `host` crate owns the HTTP application, product resolution, the commit rules, assets, and Import and Export of an Aggregate directory. It reaches storage only through one repository trait that mirrors the TypeScript seam (`StoredSpaceRepository` plus the aggregate lifecycle of `SpaceRepository`, and the asset store). The memory store is the first implementation; SQLite and PostgreSQL follow behind the same trait through one SQL repository over `sqlx`. The commit decision is pure code every store calls, so only transactions and locking differ between stores.
- **Both hosts share one database schema until PostgreSQL moves.** The migrations are plain SQL files that Prisma (PostgreSQL), the SQLite migrator and `sqlx` all apply, held to one schema by a test. Migration ownership moves to Rust when PostgreSQL does. Either host can then serve the same database during the switch, with no data migration.
- **Two thin shells wrap the Rust library.** A command-line binary (`run`, `check`) serves to the person's browser on loopback. Once the swap lands, the Tauri application serves to its own window through a custom URI scheme, with no port. The Tauri application opens one Aggregate directory per window, each window owning its own run, and Exports before the window or the application closes.
- **Nondeterminism is still injected at composition (ADR 0109).** The host's builder requires its directory, its id source and its clock; the two shells pass the real ones, and tests pass deterministic ones.

## Why

- **Working code before the port.** The Node host and the browser application already work. A Tauri shell around them puts an installable application in presenters' hands now, and the shell is the one the end state keeps, so only the sidecar is thrown away.
- **The desktop application's end state is a host that is not Node.** Electron would run the existing host in its main process, but embeds Node 24 against ADR 0071's Node 26 pin (Electron 45 ships Node 24.22: `.scratch/desktop-app/research.md`, "Answer" and option A) and ships Chromium in every download. Tauri with a Node sidecar keeps the TypeScript host but ships a Node binary anyway, needs a stop protocol Tauri does not document, and listens on a port. A Rust host runs inside Tauri's own process, with no second runtime and no port.
- **One host rather than two.** A Rust host for the desktop alone would leave two server implementations to keep in step forever. Making Rust the end state for every server-side host bounds that to a transition.
- **The wire contract is the seam that already exists.** Keeping it unchanged means the browser, the Mount build and the HTTP-level tests stay as they are, and the same tests can be run against both hosts (ADR 0156).

## Rejected

- **Electron, with the run in its main process.** The smallest step from today's code, rejected for the Node 24 runtime under a Node 26 pin (research, option A), the bundled Chromium, and because it keeps the server in TypeScript, which the maintainer wants to move.
- **Tauri with a Node sidecar as the end state.** It keeps the TypeScript host, but a whole Node binary rides along, so Tauri's size advantage mostly goes, and it needs a single-file Node build per platform, a stop protocol of its own, and a loopback listener that must be locked down. Accepted as the first stage only, because it ships working code in the shell the end state keeps.
- **Waiting for the Rust host before shipping a desktop application.** Rejected on 17 November 2026: the port is weeks of work with nothing usable until its end.
- **Electron for the first stage.** Faster to a first build, with no port and no WebKit, but on Node 24 against the Node 26 pin (research, option A) and in a shell the end state throws away.
- **Tauri IPC commands in place of HTTP.** A second client in the browser application beside the typed HTTP client, and nothing the existing HTTP-level tests could run against.
- **Porting only the Running host.** Smaller at first, but it leaves a TypeScript server for the databases indefinitely and invites designing the Rust host around a memory store alone.

## Consequences

- ADR 0034's "runtime hosts adapt the application" now includes a second implementation of the application itself, not only a second adapter.
- This ADR refines 0030 and 0095 (the SQL repository moves to `sqlx` over plain-SQL migrations), 0034, 0117 (the desktop sidecar serves a run without Vite and stops on standard input), 0119 (Export in place is reimplemented in Rust, with the same rules), and 0124 for as long as two CLIs exist: the Rust binary takes verbs from `pnpm cube` stage by stage, and `pnpm cube` keeps the rest until it is retired.
- ADR 0071's Node pin governs the TypeScript host until it is retired. The desktop application's browser floor is ADR 0157.
- Running's semantics (ADR 0117 and its refinements) are unchanged: the directory is the durable copy, Export is the only write, and file watching and locking stay rejected. ST-65 (opening a Space never writes the directory) is fixed in the first stage, before the Node sidecar meets real talks.
- The shell's five-second kill is a deliberate exception to Storage ST-63's "stopping never loses an edit", for the desktop sidecar only: a window must close even when its sidecar hangs. Its cost is that an Export still running after five seconds is cut short, and git answers for that partial write as ADR 0119 has it answer for any other.
- The first installable release is unsigned, with Tauri's own updater keys; signing and notarization are a release blocker before a public launch.
- Rust code follows the `rust-sdk-dx` conventions for its safety rules (`thiserror` errors, no `unwrap`, `expect` or `panic!` in library code, newtype identifiers, `#[must_use]`, tokio), relaxed to crate-root types for `#[non_exhaustive]` and doctests, since both consumers are ours. `intake` reads JSON with a parser of its own rather than `serde`, so that its answers follow `JSON.parse`'s (ADR 0156); `serde_json` is a dev-dependency of `intake`, reading the conformance corpus.
- The Node sidecar's loopback port is the one surface this application exposes beyond its window, which is why it is locked to its Host and a per-launch secret; that surface goes when the Rust host replaces the sidecar.
- The first stage's code (the ST-65 fix, the production Node host and the Tauri shell) was written before this ADR was accepted, by the maintainer's choice. The rest of the work is `.scratch/rust-host/issues/`.
