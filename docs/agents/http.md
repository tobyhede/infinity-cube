# HTTP & Hono

Read this for the Fetch application in `packages/http` and its Hono adapters. The Vite host and Node sidecar use `@hono/node-server`. Read [Storage and hosts](../requirements/storage.md#http) for the shared wire contract and the [HTTP conformance guide](../../conformance/http/README.md) when changing either the Node or Rust host.

## Hono reference

Consult Hono's [RPC guide](https://hono.dev/docs/guides/rpc) for inferred client types and [best practices](https://hono.dev/docs/guides/best-practices) for route composition. Use the [full docs](https://hono.dev/llms-full.txt) when those pages omit the relevant API.

## Route handling and media validation

- **Hono hands the host a rejected promise unless the app terminates every path.** Two rules, both load-bearing, both proven by regressions in `space-http-app.test.ts`. **Never call `context.notFound()` inside the handler `app.notFound()` installed** — Hono seeds the Context's not-found handler from the app's, so it re-enters itself until the stack blows, on every path off the declared contract including the trailing slash an address bar produces; return an explicit response instead, which is also what the RPC docs say when a client infers types. **Never rethrow from `onError`** — Hono does not convert that into a 500, it re-invokes the handler and lets the throw escape, so `app.fetch()` rejects and a host without a `.catch` gets an unhandled rejection, which Node 26 answers by killing the process. A non-`Error` throw never reaches `onError` at all. An `onError` that returns a Response is entered once; one that rethrows is entered once per compose frame.
- **One media policy, or Hono's json validator silently hands you `{}`.** Its `jsonRegex` is narrower than RFC 9110 — it rejects space before `;`, spaces around `=`, `_` in a parameter name, and quoted strings containing `;` — and on disagreement it does not parse the body and reports nothing, which surfaced as a 400 about the fields of a body never read. `requireSupportedRequestMedia` therefore rewrites the header it has just validated to canonical `application/json`; don't remove that and don't add a second policy beside it. Relatedly, `content-type@2` validates **nothing** — `parse` has no throw path and answers `parse('garbage')` with `{ type: 'garbage' }` — so the hand-rolled scanner is the whole of this module's media validation, not a duplicate of the dependency.
- **A Node host must keep `@hono/node-server`'s global `Request`/`Response`, and Hono answers HEAD from the GET handler.** Both Node hosts take the default: the Vite host through `getRequestListener`, the desktop sidecar through `serve`. Two host-level facts the portable route module quietly depends on. **`getRequestListener` replaces `globalThis.Request`/`Response`** with its own lightweight classes unless `overrideGlobalObjects: false` is passed, and defines them non-writable and non-configurable — a permanent, process-wide swap. Leave it on: `requireSupportedRequestMedia` and `requireBoundedCommitBody` both rebuild the request through the *global* `Request` constructor, so with the override off the constructor is handed an instance it does not recognise and **every commit answers 500** while all the rejection paths stay green. This is `@project/http`'s one host requirement — portable does not mean indifferent to the host. Separately, **Hono routes a HEAD request to the GET handler and strips the body**, so a resource that does not explicitly intercept HEAD answers 200 carrying nothing; `unservedContractPath` is that interception, and it is shared with `app.notFound()` so the two cannot disagree about whether a non-UUID segment is a 400 or a 405. Both are pinned in `vite-hono-host.test.ts` and `space-http-app.test.ts`.

## Commit input and body limits

- **Keep wire input separate from decoded output.** A JSON validator otherwise infers its input from its return type and can expose a decoded `bigint` instead of the wire revision. Use the named `decodeCommitBody` function so both `InputType` and `VF` are explicit. Supplying only `InputType` defaults the other type parameters and can erase the route from the inferred schema. Keep middleware status types in the inferred contract. Run root `pnpm typecheck` to exercise the assertions in `space-http-app-types.test.ts`.
- **Count the bytes that arrive and bound the drain.** `requireBoundedCommitBody` strips `Content-Length` and counts the body. Hono's `bodyLimit` trusts the declared length and can leave an overflowing reader locked. Drain up to `MAX_DRAINED_BODY_BYTES` to preserve keep-alive for a bounded overshoot. `space-http-app.test.ts` checks the read boundary and `vite-hono-host.test.ts` checks socket reuse and termination.
- **A wire codec throws prose, not Zod.** Use [Storage's Problem Details contract](../requirements/storage.md#http) for response shape. Keep `decodeSnapshot`'s concise `safeParse` summary at the wire boundary.

## Asset and build routing

Use [Storage's HTTP rules](../requirements/storage.md#http) for asset admission, encoding refusals, response headers and request policy. A size refusal is `asset-too-large` (413), and unsupported content encoding is a separate 415 refusal.

Vite forwards `/assets` and `/assets/<hash>` to the Fetch app when the final segment is a valid asset hash. Other paths under `/assets/` can be built scripts or styles and stay with Vite. Keep the routing proof in `test/unit/vite-hono-host.test.ts` when changing that boundary.
