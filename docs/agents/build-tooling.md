# Build & Tooling

The TypeScript 7 compiler and its TypeScript 6 bridge, Vite config gotchas, Prettier scope, and the spike-harness rule. Read before touching a root `*.config.ts`, `packages/app/vite*.ts`, the TypeScript entries in `package.json`, or leaving a throwaway harness behind.

- **TypeScript 7 is the compiler and TypeScript 6 is a bridge (ADR 0061).** `@typescript/typescript7` owns the `tsc` binary, and `tsc` is the only type-checking truth here. The package name `typescript` deliberately resolves to `@typescript/typescript6`, which owns `tsc6` and the `createProgram` API `typescript-eslint` and `prisma-next` consume. So `package.json`'s TypeScript entries look wrong and are not: a TypeScript 6 diagnostic is not a defect to fix, `tsc6` is a migration aid rather than a gate, and no TypeScript 6 typecheck is added. Keep the two names apart: pointing `typescript` at 7 breaks typed linting. `pnpm typecheck:toolchain` asserts the arrangement and runs first in `verify`, because a typecheck against the wrong compiler still passes. The ADR states when the bridge is removed: a stable release exposing the replacement compiler API, `typescript-eslint` and the other programmatic consumers supporting it, and `verify` green with `typescript` pointing at 7. The one known casualty is the `pnpm` patch on `@ladle/react` (`patches/`): its bundled `.tsx` carries a `//@ts-ignore` that TypeScript 7's relocated diagnostic no longer sits under.
- **Markdown is excluded from Prettier** (`.prettierignore`) — don't rely on `format` to touch `*.md`.
- **Don't import a workspace package by name into a module bundled into a Vite config** (`vite.config.ts`, `http-server-build.config.ts`). Vite loads the config in Node and externalizes bare specifiers, so `@project/core` hands *Node* the TypeScript source, whose extensionless relative imports (`export * from './schema'`) Node's ESM resolver rejects — the config then fails to load at all and the dev server will not start. Import by relative path (`../core/src/index`) so esbuild bundles it. This is the one place the repo's extensionless-import convention does not hold.
- **Vite hosts a fixed server runtime, not browser-selected capabilities.** The thin config-time plugin imports no application package. Development loads the chosen runtime with Vite's SSR module runner; preview loads the dedicated bundled Node artifact. The server configuration fixes PostgreSQL versus isolated E2E memory and fixture versus empty catalog before any browser request. Opt-in SQLite (`vite.sqlite.config.ts`, port 5177) is a development host; `pnpm preview` still loads the PostgreSQL bundled artifact.
- **Changing the Vite config needs a dev server restart** — plugins load at config time and HMR won't pick them up. That server is the human's; say it needs restarting rather than restarting it.
- **`stryker.conf.mjs` is a kept tool, not a spike harness left behind.** The rule below is about throwaway harnesses; this one is a deliberate diagnostic with two `pnpm mutate:*` commands in `package.json` and its rationale in `.scratch/mutation-testing/engine.md`. Three details about it are not obvious. `verify` does **not** typecheck it — the root program's `include` is `"*.config.ts"` and this is `.mjs`, so the `@stryker-mutator/api` annotation buys editor completion and nothing more. Its sandbox is a plain `fs.copyFile` copy of the repository, which is why `ignorePatterns` names `.claude/**` (tracked directory symlinks fail with `ENOTSUP` on macOS) and `.worktrees/**` (a worktree is a full checkout and would be copied whole). And that sandbox is a complete repo copy carrying its own `tsconfig.json`, so a leftover one makes `eslint` see several candidate TSConfig roots and report a parse error for every file in the repository — the same failure the `.worktrees/` entry in `eslint.config.js` exists to prevent. `cleanTempDir: 'always'` plus `.stryker-tmp/**` in both `eslint.config.js` and `.oxlintrc.json` is what stops a crashed campaign breaking the next `pnpm verify`.
- **Delete a spike harness when you write it up; ignoring it is not enough.** `packages/app/spike.html` sat gitignored, went stale against the `elkLayout` → `elkStrategy` rename, and broke `pnpm dev` — Vite's dependency scanner treats every root `.html` as an entry and does not read `.gitignore`, while tsc and eslint both skip `.scratch/`, so `pnpm verify` stayed green and only the dev server saw it.

## Database contracts

Generated Prisma Next `contract.d.ts` files import adapter types directly. Under pnpm's strict layout, each package named by those generated imports must be an exact-version root devDependency matching the Prisma Next pin. Authored code imports capabilities through the database facade (`@prisma-next/postgres` or `@prisma-next/sqlite`). Remove an extra direct dependency when generated types resolve through the facade; do not hoist dependencies or patch generated declarations to hide the packaging issue.

A relational schema change updates `migrations/app/` and the Prisma contract together. Document-format roll-forward does not remove relational migrations. Keep the PostgreSQL integration job exercising the same repository contract as SQLite and memory. A new `SqlStore` member needs a concrete database operation that the shared repository cannot express through its existing surface; type shared tables structurally rather than casting one database's tables to another's.

## UI dependency changes

Before changing React Flow, read its full documentation at `https://reactflow.dev/llms-full.txt` and the specific mechanism's page; the combined document can omit pages. Update both consuming manifests together. Revalidate handle resolution, consecutive connections, warning #008 and the camera-Promise contract in [Rendering](../requirements/rendering.md#camera) in a real browser, and run the complete Playwright suite in CI. Re-read the pinned implementation of `setTransform`, `scaleTo`, `scaleBy`, `resolveFitView` and `getD3Transition` when upgrading. Keep the exact pin until that evidence passes.

Pin UI primitives and revalidate keyboard, focus, dismissal and accessibility when upgrading them. Preserve recorded extensions in existing registry components, including `Kbd`'s `keyName="modifier"`, and the component comments that name them. A new runtime is supported only after its adapter passes the shared contract tests.

## Styling and structural checks

Tailwind's scan roots include `app`, `ui/src` and `react-flow-adapter/src`; a new production root using utilities must be scanned. React Flow placement and portal layers live in `packages/app/src/styles.css`; product appearance belongs beside the component that draws it. Everything inside a Resource's rect is its plugin's, and the host keys no style on a kind: a Resource whose plugin declares a content Target is drawn dotted by `packages/ui/src/target-canvas.css`, which selects `[data-shows-target]`. App-owned colour tokens remain in `tailwind.css`. The app reaches Markdown editing through `@project/ui` and does not style CodeMirror's `.cm-*` classes.

Use the chrome and Resource's respective named scales for radius, border width, weight and shadow. Register a new class-generating chrome utility with `extendTailwindMerge` beside `cn()` in the same change, so it replaces the conflicting built-in utility. Keep shadows theme-derived, including the theme's definitions of Tailwind's named shadow steps. The structural scans enforce these conventions across production TypeScript and CSS; TSX style objects and CodeMirror themes are outside their CSS-declaration scan. Keep an exemption only while its reason and matching declaration remain, and use computed-style browser assertions for cases the source scan cannot see.

`handRolledStyles` in `packages/app/stories/design-system-inventory.ts` records every block of `styles.css` with its reason. Colocated stylesheets need no inventory entry, but the dead-rule check still covers them. Catalogue-support styles declare only `inv-*` classes and do not reconstruct production surfaces. The inventory is a ratchet, not a backlog: remove entries when the exception ends, and retain justified permanent exceptions.
