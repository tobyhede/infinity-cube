# Builds and updates

**Missing UI in a bundle.** Check both paths in [tauri.conf.json](../../../../packages/desktop/src-tauri/tauri.conf.json). Tauri resolves them from the directory containing that file. `frontendDist` supplies the shell’s home and question pages from `packages/desktop/ui`. Bundle resources supply the shared browser build from `packages/app/dist` to the Rust host. Run `pnpm build` before building the shell directly.

**Apple silicon macOS preview.** Use `pnpm release:build --desktop` from a clean checkout for the release proof. The [build script](../../../../release/build.sh) checks the Cargo workspace version against the bundle, installs the app from the DMG and opens a Space. The DMG carries an ad-hoc signature. The updater separately verifies a signed update archive using the public key in the Tauri configuration. ST-130 records the current distribution policy and the limits of the installed-update evidence.

**Update offered on launch.** Trace the generated update bundle, signature and manifest through the [release workflow](../../../../.github/workflows/release.yml), then the manifest copy on publication in [desktop-updates.yml](../../../../.github/workflows/desktop-updates.yml). Inspect [update.rs](../../../../packages/desktop/src-tauri/src/update.rs) for the user’s choice and installation. The replacement takes effect at the next launch so an open Aggregate can complete its last write. [Tauri updater reference](https://v2.tauri.app/plugin/updater/)

**Linux shell.** Use the Linux dependencies and shell checks in [CI](../../../../.github/workflows/ci.yml). To exercise packaging after building the browser application, run `pnpm --filter @project/desktop tauri build --bundles deb` on Linux. For WebKitGTK runtime observations, consult ST-121 and ST-122 in [Storage and hosts](../../../../docs/requirements/storage.md). Record what a build, a scheme test or a live window demonstrated separately. Windows installer work would need its own port and release evidence.
